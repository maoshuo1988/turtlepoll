### 特性状态规则提示词

当你填写或更新 03-特性清单总览 时，严格遵守以下规则：

1. 状态只允许：`设计中`、`未实现`、`已实现`。
2. 如果某特性的设计文档已经完成，则该特性状态不能写为 `设计中`，只能是 `未实现` 或 `已实现`。
3. 只有“尚未完成设计”的特性，才允许写为 `设计中`。
4. `已实现` 表示已落地代码并可验证；仅完成文档不算 `已实现`。
5. 若当前阶段仅完成设计、尚未开发，状态应统一标记为 `未实现`。
6. 状态判定必须与文档正文一致，不允许表格与正文冲突。

状态口径示例：

- 设计完成 + 未开发：`未实现`
- 设计完成 + 已开发：`已实现`
- 设计未完成：`设计中`

### 特性详情锚点规则提示词

当你填写或更新 `03-特性清单总览-0` 的“详情”列时，严格遵守以下规则：

1. “详情”列必须使用可点击链接，不允许纯文本描述。
2. 优先锚点到 `04-特性详情介绍-0.md` 对应章节。
3. 若该特性已拆分到 04 补充文件，可直接锚点到对应补充文件章节。
4. 同一特性只保留一个主锚点，避免在“详情”列放多个链接。
5. 锚点标题必须与目标文档实际标题一致，不允许编造锚点。
6. “详情”列只做导航，不写实现细节；实现细节写在 04 文档正文。
7. 若 04 章节尚未完成，先补齐 04 再回填 03 的“详情”链接。

推荐格式：

```markdown
[查看](./04-特性详情介绍-0.md#章节标题)
```

拆分场景格式：

```markdown
[查看](./04-特性详情介绍-主动对话链路.md#章节标题)
```

口径要求：

- `03` 负责“特性清单导航”。
- `04` 负责“技术实现细节”。
- `03.详情` 必须能一跳进入对应 `04` 设计章节。
### 锚点精准度规则提示词

当你填写或校验 `03-特性清单总览` 的"详情"锚点时，严格遵守以下精准度要求：

1. **精确到子章节**：锚点必须指向最细粒度的匹配标题，禁止用父章节（如 `#2-体力系统`）代替子章节（如 `#21-规则`）。
2. **与实际标题逐字对应**：锚点由标题文字转换而来，规则如下：
   - 空格 → `-`
   - 删除所有标点（`.`、`/`、`（`、`）`、`、`等）
   - 全部小写（英文部分）
   - 示例：`### 2.2b 自然恢复实现` → `#22b-自然恢复实现`
   - 示例：`## 1. 完整处理流程` → `#1-完整处理流程`
3. **修改 04 标题后必须回写 03**：每次新增或重命名 04 章节标题，必须同步检查并更新所有引用该锚点的 03 表格行。
4. **校验方法**：在 04 文档中 `grep -n "^### \|^## "` 列出全部标题，逐一与 03 中对应锚点比对，不允许存在任何不匹配。
5. **多特性共用锚点**：若多个特性对应同一 04 章节，允许共用锚点，但该章节内容必须覆盖所有相关特性，不得遗漏。

## 外部特性依赖

### 外部特性文档规则提示词

当你编写 08-外部特性依赖 与 09-外部特性依赖详情 时，严格遵守以下规则：

1. 08 只做“特性清单总览”，不写建议性分析。
2. 08 必须列清楚：特性编号、特性名称、是否必须、调用方、被调用方、详情锚点。
3. 09 必须按特性编号逐项展开，且每项都要有接口定义。
4. 09 每个特性最少包含：接口名、调用方向、输入参数、输出参数、错误码、固定策略。
5. 09 的描述必须是确定性规则，禁止使用“建议、可选、尽量、后续优化”等不确定措辞。
6. 涉及超时、重试、熔断、阈值、窗口期的规则必须给出具体数值。
7. 08 的“详情”列必须使用可点击锚点，跳转到 09 对应章节。
8. 外部特性只描述外部依赖能力，不混入站内业务接口的非外部逻辑。

外部特性章节模板（用于 09）：

- 特性编号与名称
- 接口定义（接口名、调用方向、调用方式）
- 输入参数（字段、类型、必填、说明）
- 输出参数（字段、类型、说明）
- 错误码（错误码、触发条件）
- 固定策略（超时、重试、熔断、并发、限速）
- 验收标准（可量化）

## 接口

### Iris MVC 路由防错提示词

当项目使用 Iris MVC controller 方法名自动映射路由时，设计和实现接口前复制以下提示词：

请检查接口 URL 与 Iris MVC 实际路由是否一致，并严格遵守以下规则：

1. 文档 URL 是最终契约，代码必须服务文档 URL。
2. 不要假设方法名里的下划线 `_` 会自动映射成短横线 `-`。
3. 当 URL 包含短横线，例如 `/ability-options`、`/kill-switch`，必须使用 `BeforeActivation` 显式绑定。
4. 当 URL 包含多级路径，例如 `/market/settle`、`/comment_reward/logs`，必须使用 `BeforeActivation` 显式绑定。
5. 显式绑定格式示例：

```go
func (c *PetController) BeforeActivation(b mvc.BeforeActivation) {
	b.Handle("GET", "/ability-options", "GetAbility_options")
}
```

6. controller 文件需要导入：

```go
import "github.com/kataras/iris/v12/mvc"
```

7. 新增接口后必须用文档 URL 做本地 curl 验证，不能只跑单测。
8. curl 返回 HTML 首页通常表示路由未命中并被 SPA fallback 接住；返回 JSON 的“请先登录/无权限”才表示已经命中后端。
9. 对 `/api/admin/**` 接口，验证时同时检查认证方式：cookie 名通常是 `bbsgo_token`，也可用 `Authorization: Bearer <token>`。
10. 如果已有接口使用自动映射且 URL 含下划线，可以保留；但新增文档 URL 使用短横线时必须显式绑定，避免线上 404 或 HTML fallback。
