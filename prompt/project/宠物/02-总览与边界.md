# 宠物系统总览与边界

## 目标

宠物系统为用户提供龟种收集、装备、成长、开蛋、装扮、体力和金币能力加成。系统需要支持运营长期配置、审计、回滚和止血，同时保证所有金币相关能力可幂等结算。

## 术语

- **龟币**：系统金币账户余额，不新增独立币种。
- **龟种 / PetDefinition**：运营维护的宠物资产定义，包含稀有度、展示资源、能力配置。
- **用户龟种 / UserPet**：用户已拥有的某个龟种资产，包含等级、经验和获得时间。
- **当前装备龟种**：用户当前生效的龟种能力来源。
- **特性 / Ability / Feature**：挂载到龟种上的业务能力，如每日登录加成、开蛋折扣、生息、欠账等。
- **开蛋池**：按稀有度概率和稀有度内候选龟种进行随机抽取的配置集合。
- **版本快照**：运营配置发布后生成的不可变配置，用于解释历史开蛋和结算结果。

## 模块边界

### 用户侧

- 展示当前装备龟种、拥有龟种列表、能力说明、等级和装扮状态。
- 支持切换龟种，但每日只能切换一次。
- 支持注册初始化、每日登录结算、开蛋、体力恢复、AI 体力减免、小游戏奖励、赛季奖励等规则。
- 所有金币变动必须写金币流水，并保证同一业务事件幂等。

### 运营侧

- 维护龟种资产库、特征库、开蛋池、外观资源、止血开关。
- 对概率、价格、返还、能力参数做强校验。
- 发布后形成可追溯配置快照，支持审计和回滚。

### 不在本领域内

- 用户账号注册、登录认证本身。
- 金币账户底层账务模型，只消费 `UserCoin / UserCoinLog` 能力。
- 预测市场、好友对赌、AI 对话、小游戏的完整业务状态机。
- 成就系统完整设计；本文只描述装扮解锁所需追踪字段。

## P0 主链路

### 新用户注册初始化

- 用户注册成功后，初始化用户宠物资产。
- 授予并默认装备 `basic` 小龟。
- 注册流程本身不再直接发放 500 龟币；500 龟币作为小龟的「注册时赠送 500 龟币」特性，由小龟能力执行并写入金币流水。
- 同一用户只允许执行一次小龟注册赠送，重复初始化不得重复发币。

### 每日登录结算

- 触发：登录成功后，北京时间当日首次登录。
- 幂等：同一天只结算一次。
- 结算内容：签到基础 100 + 火花加成 + 欠款补贴或存款生息 + 龟种每日登录加成。
- 登录不能被宠物结算失败阻断；失败时记录错误并返回可观测信息。

### 切换龟种

- 每位用户每天北京时间仅可切换一次龟种。
- 欠款未还清时禁止切换龟种，错误码 `DEBT_UNPAID`。
- 切换当日不再结算旧龟补贴或生息，新龟从次日 0 点生效。

### 开蛋

- 用户消耗龟币开蛋。
- 折扣影响本次实际花费。
- 抽中重复龟种时，按本次实际花费的 30% 向下取整返还。
- 本次订单必须记录使用的配置版本，确保历史可解释。

## 优先级

- P0：注册初始化、每日登录结算、切龟限制、欠账/补贴/生息、火花倍率、运营强校验和止血。
- P1：开蛋折扣与重复返还、AI 体力减免、幸运骰、首次下注奖励、手续费减免、爆冷、对赌奖励、窃取。
- P2：小游戏护盾/缩小/收益加成、赛季排名提升、贡献值加成。

## 待确认

- 好友系统与私人对赌的完整状态机。
- 下注增强能力的胜率口径、手续费口径和结算落点。
- 装扮成就的实际解锁服务归属。
- 配置版本快照是否对外暴露，当前建议接口层不暴露，内部留存。
