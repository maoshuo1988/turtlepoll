# 初始化数据说明

> 本页说明宠物系统上线时的初始化数据、种子数据和运营配置。  
> 初始化数据分为三类：数据库迁移脚本写入、服务启动时幂等补种、运行时链路写入。不得把运行时写入误写成纯迁移，也不得把幂等补种误写成手工后台操作。

## 初始化阶段

### 阶段 1：基础龟种资产库初始化

**时间点**：系统上线前的迁移脚本运行 + 服务启动时幂等补种  
**负责人**：运营、技术  
**验收**：龟种能够在管理端查询，用户注册时能正常获得，启动后重复执行不会重复插入

#### 初始化方式拆分

| 数据类型 | 写入方式 | 责任模块 |
| --- | --- | --- |
| 基础龟种资产库 | 迁移脚本 + 启动时幂等补种 | `migrations/*` + `PetDefinitionService.EnsureDefaultSeeds()` |
| FeatureCatalog 种子 | 启动时幂等补种 | `FeatureCatalogService.EnsureDefaultSeeds()` |
| 管理员默认宠物 | 可选程序补发 | `PetDefinitionService.GrantDefaultPetsToAdmins()`（当前默认注释，不作为主初始化链路） |

#### basic 小龟

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `pet_id` | `basic` | 业务唯一标识 |
| `name_json` | `{"zh_CN": "小龟", "en_US": "Turtle"}` | 多语言名称 |
| `description_json` | `{"zh_CN": "系统赠送的初始龟种，每日登录+100龟币", ...}` | 多语言描述 |
| `rarity` | `C` | 稀有度：C/B/A/S/SS/SSS |
| `display_json` | 见下表 | 展示资源 |
| `obtainable_by_egg` | `false` | 开蛋池不提供 |
| `abilities_json` | 见下表 | 能力配置 |
| `enabled` | `true` | 启用状态 |
| `status` | `1` | 活跃状态 |

##### display_json 结构

```json
{
  "icon": "/images/pet/basic/icon.png",
  "cover": "/images/pet/basic/cover.png",
  "thumbnail": "/images/pet/basic/thumb.png",
  "animation_url": "/animations/pet/basic/idle.gif",
  "rarity_color": "#999999"
}
```

##### abilities_json 结构

```json
{
  "signup_bonus": {
    "enabled": true,
    "amount": 500
  },
  "signin_bonus": {
    "enabled": true,
    "base": 0
  }
}
```

### 阶段 3：开蛋池初始化

**时间点**：龟种资产库完成后  
**负责人**：运营、技术  
**验收**：用户能够成功开蛋，抽取到配置的龟种

#### 初期开蛋池配置

```yaml
gacha_pool_v1:
  enabled: true
  base_cost: 500
  repeat_return_ratio: 0.3
  
  rarity_probabilities:
    C: 0.50
    B: 0.30
    A: 0.12
    S: 0.05
    SS: 0.02
    SSS: 0.01
  
  rarity_candidates:
    C: ["basic", ...]  # 50% 概率抽到
    B: ["忍者龟", ...]
    A: ["幽灵龟", ...]
    S: ["财神龟", "钻石龟", ...]
    SS: ["赛博龟", ...]
    SSS: ["传奇龟", ...]
```

**必须校验**：
- 每项概率 >= 0
- 概率总和 == 1
- 若某稀有度概率 > 0，则必须至少有一只可抽龟种

## 数据迁移脚本

### 迁移脚本命名规范

```
000001_migration_script_pet_init_basic.go
000002_migration_script_pet_gacha_pool_init.go
000003_migration_script_pet_feature_catalog_seed.go
```

### 程序补种说明

以下数据不是一次性写死在迁移脚本里，而是由服务启动时幂等补种逻辑写入数据库：

- `FeatureCatalog` 内置特性模板，启动时由 `FeatureCatalogService.EnsureDefaultSeeds()` 补种
- 默认龟种定义，启动时由 `PetDefinitionService.EnsureDefaultSeeds()` 补种
- 管理员默认宠物，可选由 `PetDefinitionService.GrantDefaultPetsToAdmins()` 程序补发，但当前代码中处于注释状态，不作为必选初始化步骤

这些补种逻辑的特点：

1. 幂等，重复启动不会重复插入。
2. 与迁移脚本职责分离，迁移负责建表与基础骨架，补种负责业务默认值。
3. 当新环境启动时，先完成迁移，再执行补种，最后进入注册/登录运行时流程。

### 迁移脚本模板（Go）

```go
// 文件：migrations/000XXX_migration_script_pet_basic_init.go

package migrations

import (
	"fmt"
	"github.com/kataras/iris/v12/middleware/recover"
)

func init() {
	// 注册迁移脚本
	// Migrate 函数中执行初始化逻辑
}

func MigratePetBasicInit(db interface{}) error {
	// 1. 插入 basic 龟种
	// 2. 验证插入结果
	// 3. 返回错误或 nil
	
	// 伪代码
	pet := &PetDefinition{
		PetId:          "basic",
		Name:           `{"zh_CN": "小龟", "en_US": "Turtle"}`,
		Rarity:         "C",
		ObtainableByEgg: false,
		Enabled:        true,
		DisplayJSON:    `{...}`,
		AbilitiesJSON:  `{...}`,
	}
	
	if err := db.Create(pet).Error; err != nil {
		return fmt.Errorf("failed to insert basic turtle: %w", err)
	}
	
	return nil
}
```

## 每日定时初始化

### PetDailySettleService 初始化检查

- **触发**：用户登录成功
- **幂等**：按 userId + dayName 检查 `pet_daily_settle_log`，若不存在则创建
- **操作**：读取当前装备龟种配置，计算签到、火花、补贴/生息，写流水

> 这里属于运行时链路，不属于离线初始化脚本。它的作用是补齐用户每日结算状态，避免把登录后写入误认为“初始化种子数据”。

### UserPet 初始化（注册新用户）

- **触发**：用户注册事务
- **操作**：
  1. 创建 `UserPet` 记录（basic 龟种）
  2. 创建 `UserPetState` 记录（当前装备）
  3. 记录 `pet_daily_settle_log` 以避免重复发放
  4. 调用 `UserCoinService.Reward()` 发放 500 龟币

> 这里同样属于运行时写入，发生在用户注册事务中，不应归类到“上线前迁移脚本”。

## 版本快照机制

### 快照生成

运营每次发布配置时生成不可变快照：

```sql
INSERT INTO pet_config_snapshot (
  snapshot_version,
  published_at,
  published_by,
  pet_definitions_json,
  gacha_pool_json,
  features_json,
  rollout_json,
  checksum
) VALUES (
  'v1.20260611.1',
  NOW(),
  'admin_user_id',
  '...',
  '...',
  '...',
  '...',
  SHA256(...)
);
```

### 快照应用

- 用户开蛋时应查询并记录 `snapshotVersion`
- 每日结算时应查询并记录 `snapshotVersion`
- 支持灰度：特定用户只能使用特定快照

### 快照验收标准

- 快照 checksum 与数据完整性匹配
- 过期快照支持查询（只读）
- 支持回滚至历史快照（通过管理端）

## 回滚方案

### 快照回滚

如需回滚到历史配置：

1. 管理员在管理端选择历史快照版本
2. 系统验证快照完整性（checksum）
3. 标记为"活跃配置版本"
4. 新开蛋、结算均读取活跃快照
5. 旧快照保留，不删除

### 龟种回滚

如需禁用某龟种：

1. 设置 `enabled = false`
2. 已有的 `UserPet` 记录不删除
3. 用户仍可装备，但开蛋不提供
4. 若需紧急止血，在止血开关中配置

## 监控与告警

### 初始化验证指标

- 龟种总数、特性注册数、开蛋池稀有度分布
- 用户注册后 basic 龟种获得率 (应为 100%)
- 用户首次登录结算成功率 (应 > 99.9%)
- 开蛋成功率、返还触发率

### 告警规则

- 若龟种初始化失败，系统启动告警
- 若用户注册后未自动获得 basic，告警
- 若结算失败率 > 0.1%，告警
- 若快照生成失败，告警
