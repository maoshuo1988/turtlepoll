# 初始化数据说明

> 本页说明宠物系统上线时的初始化数据、种子数据和运营配置。  
> 所有数据均通过数据库迁移脚本或管理端界面完成初始化，不依赖代码硬编码。

## 初始化流程总览

```mermaid
flowchart TD
  A[数据库迁移脚本启动] --> B[初始化基础龟种资产库]
  B --> C[注册 FeatureCatalog 种子]
  C --> D[初始化开蛋池]
  D --> E[写入运营配置与快照]
  E --> F[用户注册触发 UserPet 初始化]
  F --> G[首次登录触发每日结算]
  G --> H[按日幂等写入结算日志]
```

### 流程说明

1. **数据库迁移脚本先行**：先落地龟种定义、特性目录、开蛋池和基础配置，保证后续业务链路可读到完整种子数据。
2. **运营配置后置发布**：基础资产就绪后，再由管理端发布可变配置，并生成版本快照。
3. **注册链路触发用户初始化**：用户注册时只初始化 `UserPet`、`UserPetState` 和注册赠送日志，不在这里重复定义全局种子。
4. **登录链路触发每日结算**：首次登录时按北京时间日切执行签到、火花、欠款补贴/生息，结算日志用于幂等控制。
5. **后续业务依赖初始化结果**：开蛋、AI 体力减免、投票奖励、赛季奖励等能力都依赖前述种子和快照存在后才能正常工作。

## 初始化阶段

### 阶段 1：基础龟种资产库初始化

**时间点**：系统上线前的迁移脚本运行  
**负责人**：运营、技术  
**验收**：龟种能够在管理端查询，用户注册时能正常获得

#### basic 小龟

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `pet_id` | `basic` | 业务唯一标识 |
| `name_json` | `{"zh_CN": "小龟", "en_US": "Turtle"}` | 多语言名称 |

### 阶段 3：开蛋池初始化

**时间点**：龟种资产库完成后  
**负责人**：运营、技术  
**验收**：用户能够成功开蛋，抽取到配置的龟种

#### 初期开蛋池配置

```yaml
gacha_pool_v1:
  enabled: true
  base_cost: 500
  repeat_return_ratio: 0.3
  
  rarity_probabilities:
    C: 0.50
    B: 0.30
    A: 0.12
    S: 0.05
    SS: 0.02
    SSS: 0.01
  
  rarity_candidates:
    C: ["basic", ...]  # 50% 概率抽到
    B: ["忍者龟", ...]
    A: ["幽灵龟", ...]
    S: ["财神龟", "钻石龟", ...]
    SS: ["赛博龟", ...]
    SSS: ["传奇龟", ...]
```

**必须校验**：
- 每项概率 >= 0
- 概率总和 == 1
- 若某稀有度概率 > 0，则必须至少有一只可抽龟种

## 每日定时初始化

### PetDailySettleService 初始化检查

- **触发**：用户登录成功
- **幂等**：按 userId + dayName 检查 `pet_daily_settle_log`，若不存在则创建
- **操作**：读取当前装备龟种配置，计算签到、火花、补贴/生息，写流水

### UserPet 初始化（注册新用户）

- **触发**：用户注册事务
- **操作**：
  1. 创建 `UserPet` 记录（basic 龟种）
  2. 创建 `UserPetState` 记录（当前装备）
  3. 记录 `pet_daily_settle_log` 以避免重复发放
  4. 调用 `UserCoinService.Reward()` 发放 500 龟币

## 版本快照机制

### 快照生成

运营每次发布配置时生成不可变快照：

```sql
INSERT INTO pet_config_snapshot (
  snapshot_version,
  published_at,
  published_by,
  pet_definitions_json,
  gacha_pool_json,
  features_json,
  rollout_json,
  checksum
) VALUES (
  'v1.20260611.1',
  NOW(),
  'admin_user_id',
  '...',
  '...',
  '...',
  '...',
  SHA256(...)
);
```

### 快照应用

- 用户开蛋时应查询并记录 `snapshotVersion`
- 每日结算时应查询并记录 `snapshotVersion`
- 支持灰度：特定用户只能使用特定快照

### 快照验收标准

- 快照 checksum 与数据完整性匹配
- 过期快照支持查询（只读）
- 支持回滚至历史快照（通过管理端）

## 回滚方案

### 快照回滚

如需回滚到历史配置：

1. 管理员在管理端选择历史快照版本
2. 系统验证快照完整性（checksum）
3. 标记为"活跃配置版本"
4. 新开蛋、结算均读取活跃快照
5. 旧快照保留，不删除

### 龟种回滚

如需禁用某龟种：

1. 设置 `enabled = false`
2. 已有的 `UserPet` 记录不删除
3. 用户仍可装备，但开蛋不提供
4. 若需紧急止血，在止血开关中配置

## 监控与告警

### 初始化验证指标

- 龟种总数、特性注册数、开蛋池稀有度分布
- 用户注册后 basic 龟种获得率 (应为 100%)
- 用户首次登录结算成功率 (应 > 99.9%)
- 开蛋成功率、返还触发率

### 告警规则

- 若龟种初始化失败，系统启动告警
- 若用户注册后未自动获得 basic，告警
- 若结算失败率 > 0.1%，告警
- 若快照生成失败，告警
