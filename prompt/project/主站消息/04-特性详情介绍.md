# 主站消息特性详情介绍

## 1. 消息模板表

`t_message_notify_template` 保存可复用消息模板。模板由 `business_code + template_code` 唯一定位，业务模块只传模板编码和参数，不直接拼接文案。

模板必须包含：

- `business_code`：业务分类，如 `dark_market`、`reward`。
- `template_code`：具体场景，如 `daily_login_reward`。
- `subject_template`：消息标题模板。
- `body_template`：消息正文模板。
- `template_params`：JSON 数组，声明必填参数。
- `detail_url_template`：跳转链接模板。
- `status`：模板启用状态。

## 2. 用户消息记录表

`t_user_message_notify_record` 保存每个用户收到的消息。记录是最终渲染后的结果，不依赖模板后续变更。

记录必须包含：

- `business_code`：便于列表筛选。
- `template_code`：便于追溯来源模板。
- `user_id`：接收人。
- `subject`：最终标题。
- `body`：最终正文。
- `status`：0 未读，1 已读。
- `detail_url`：点击跳转地址。
- `template_params`：本次渲染参数快照。
- `biz_id` 和 `idempotency_key`：业务幂等和追溯。

## 3. 业务类型与模板编码

业务类型固定使用英文编码，前端展示中文名称。

| business_code | 中文名 | 说明 |
|---------------|--------|------|
| dark_market | 暗盘 | 预测、盘口、结算 |
| tear_square | 开撕台 | 评论、回复、引用、观点互动 |
| intel | 线报 | 关注线报、来源补充 |
| system | 系统 | 公告、规则、审核、仲裁 |
| reward | 奖励 | 登录、任务、宠物、评论奖励 |
| underground_bank | 地下钱庄 | 订单、交易、黑市、宠物购买 |

## 4. 模板参数校验

`template_params` 使用 JSON 数组声明必填参数：

```json
["amount", "marketTitle", "detailUrl"]
```

推送时必须检查参数：

- 模板声明参数全部存在。
- 参数值不能是空字符串。
- 未声明的额外参数允许保留到记录快照。
- 参数缺失返回 `TEMPLATE_PARAM_MISSING`。

## 5. 模板渲染

模板占位符格式固定为 `{param}`。

示例：

```text
subject_template = "今日登录奖励已到账"
body_template = "领取 {amount} 龟币，连续登录 {loginStreak} 天。"
```

渲染规则：

- 只替换 `{param}` 格式。
- 渲染后仍存在 `{` 或 `}` 时返回 `TEMPLATE_RENDER_FAILED`。
- 渲染结果写入用户消息记录。
- 模板变更不影响历史消息。

## 6. 公共推送方法

公共方法命名建议：

```go
MessageNotifyService.PushByTemplate(ctx, input)
```

输入包含：

- `BusinessCode`
- `TemplateCode`
- `UserId`
- `Params`
- `BizId`
- `IdempotencyKey`

输出包含：

- `RecordId`
- `Created`
- `Record`

业务模块只调用该方法，不直接写表。

## 7. 幂等写入

同一用户同一业务事件不能重复生成消息。

幂等口径：

- `idempotency_key` 为空时不做幂等。
- `idempotency_key` 非空时，按 `user_id + idempotency_key` 唯一。
- 幂等命中时返回已有记录，`Created=false`。

建议 key：

- 每日登录奖励：`daily_login_reward:{userId}:{dayName}`
- 预测结算：`predict_settle:{betId}:{settleResult}`
- 地下钱庄订单：`underground_order:{orderNo}:completed`

## 8. 消息列表

消息列表按当前登录用户查询。

支持筛选：

- `businessCode`
- `status`
- `cursor`
- `limit`

默认排序：

- `create_time desc`
- `id desc`

返回内容包含：

- 消息列表。
- 下一页游标。
- 是否还有更多。
- 当前用户未读总数。

## 9. 未读数量

未读数量用于顶部红点和消息模块 tab。

MVP 返回：

- `totalUnread`
- `businessUnread`

`businessUnread` 按 `business_code` 聚合。

## 10. 标记已读

单条已读接口只允许更新当前用户自己的消息。

规则：

- 未读变已读：更新 `status=1`、`update_time=now`。
- 已读重复提交：返回成功，不重复更新业务含义。
- 消息不存在或不属于当前用户：返回 `MESSAGE_NOT_FOUND`。

批量已读为 P1：

- 按 ids 批量。
- 按 businessCode 批量。
- 全部标记已读。

## 11. 详情跳转

`detail_url_template` 由模板提供，推送时使用参数渲染成 `detail_url`。

示例：

- `/predict/markets/{marketId}`
- `/pet/warehouse`
- `/battle/{battleId}`
- `/messages/{recordId}`

前端点击消息先调用已读接口，再跳转 `detailUrl`。

## 12. 模板初始化

模板初始化通过 migration SQL 完成。

要求：

- 使用 `business_code + template_code` 幂等插入。
- 重复执行不产生重复模板。
- 初始化模板 status 默认启用。

## 13. 每日登录奖励场景

触发点：登录成功后的每日结算。

推送条件：

- 当日首次结算。
- `dailySettle.items` 中存在正向奖励金额。

模板：

- `business_code=reward`
- `template_code=daily_login_reward`

参数：

- `amount`
- `loginStreak`
- `detailUrl`

## 14. 预测暗盘结算场景

触发点：用户结算预测下注。

推送条件：

- 下注单从 OPEN 变为 SETTLED。
- 胜负或退款结果明确。

模板：

- `predict_settle_win`
- `predict_settle_lose`
- `predict_settle_refund`

参数：

- `marketTitle`
- `amount`
- `payout`
- `result`
- `marketId`

## 15. 开撕台互动场景

触发点：

- 评论被回复。
- 评论被引用。
- 观点被多人引用。

MVP 不实现，P1 接入。

接入时复用通用评论事件，但需要支持 `predict_market`、`pk`、`battle` 等业务详情跳转。

## 16. 系统公告场景

触发点：

- 平台规则更新。
- 维护公告。
- 争议仲裁提醒。

MVP 只初始化模板，不做群发。

## 17. 地下钱庄订单场景

触发点：

- 黑市订单完成。
- 宠物购买交付。
- 龟币交易完成。

原型详情页需要订单编号、消耗龟币、交付对象和处理记录。MVP 只做模板占位。

## 18. 模板后台查询

P1 提供后台模板列表接口，方便运营确认模板是否启用。

后台写接口不进入 MVP。

## 19. 数据埋点验证

验证目标：

- 模板命中率。
- 推送成功率。
- 用户读取率。

MVP 使用数据库聚合：

- 当日新增消息数。
- 当日已读消息数。
- 按 `business_code` 的未读数。

后续可接入专门埋点系统。
