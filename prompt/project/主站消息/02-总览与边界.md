# 主站消息总览与边界

## 1. 模块定位

主站消息是龟投 PC 主站面向用户的统一业务消息中心。它负责把不同业务场景的结果、提醒、奖励和公告转成可阅读、可筛选、可跳转、可标记已读的消息记录。

## 2. 用户与角色

| 角色 | 诉求 |
|------|------|
| 普通用户 | 查看暗盘、开撕台、系统、奖励、线报等消息，处理未读状态 |
| 业务模块 | 使用统一公共方法推送消息，不关心文案拼接和记录表细节 |
| 运营 | 维护模板、初始化系统公告和奖励类文案 |
| 后端 | 保证模板渲染、幂等、状态更新和接口契约稳定 |
| 前端 | 按分类 tab、未读角标、详情跳转展示消息 |

## 3. 范围内

- 消息模板表 `t_message_notify_template`。
- 用户消息记录表 `t_user_message_notify_record`。
- 模板渲染与参数校验。
- 业务场景公共推送方法。
- 用户消息列表、未读数、详情、标记已读接口。
- 模板初始化 SQL。
- MVP 数据埋点验证场景。

## 4. 范围外

- 不替换旧论坛站内信 `t_message`。
- 不在 MVP 实现移动端推送、短信、邮件、WebSocket。
- 不设计复杂运营模板编辑后台，只预留模板表和后台查询能力。
- 不把 AI 主动推送强制迁入本模块；MVP 可以并行存在。
- 不实现全量线报业务，只保留 `intel` 业务分类和模板占位。

## 5. 与旧消息系统的边界

旧 `t_message` 当前服务论坛类互动：

- 话题评论、文章评论、评论回复。
- 话题点赞、收藏、推荐、删除。
- 等级提升、获得勋章。

新主站消息服务业务化模板消息：

- 暗盘/预测结算。
- 开撕台观点互动。
- 地下钱庄或交易订单。
- 每日登录奖励、宠物奖励。
- 系统公告、规则更新、仲裁提醒。
- 线报更新。

## 6. 业务类型口径

| business_code | 名称 | 原型 tab | 说明 |
|---------------|------|----------|------|
| dark_market | 暗盘 | 暗盘 | 预测、盘口、结算、开盘提醒 |
| tear_square | 开撕台 | 开撕台 | 评论、引用、回复、观点互动 |
| intel | 线报 | 线报 | 关注线报、来源补充、热点更新 |
| system | 系统 | 系统 | 规则、维护、审核、仲裁、风控 |
| reward | 奖励 | 奖励 | 登录奖励、任务奖励、宠物奖励、评论奖励 |
| underground_bank | 地下钱庄 | 可归入暗盘或交易 | 黑市订单、龟币交易、宠物购买 |

## 7. MVP 优先级

MVP 必须先落下列能力：

- 模板表与用户记录表。
- 模板初始化 SQL。
- `PushByTemplate` 公共方法。
- 用户消息列表与标记已读接口。
- 每日登录奖励到账消息。
- 预测/暗盘结算结果消息。

## 8. 数据生命周期

- 模板长期保留，不做物理删除。
- 用户消息记录 MVP 不做自动清理。
- 已读状态只影响展示，不影响历史查询。
- 后续若需要归档，保留至少 180 天用户消息。
