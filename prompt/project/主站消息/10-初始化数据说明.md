# 主站消息初始化数据说明

## 1. 初始化原则

- 初始化 SQL 必须幂等。
- `business_code + template_code` 唯一。
- 已存在模板时更新标题、正文、参数和跳转模板。
- 默认 `status=1`。

## 3. MVP 验证模板

MVP 必须验证：

- `reward.daily_login_reward`
- `dark_market.predict_settle_win`
- `dark_market.predict_settle_lose`

## 4. 每日登录奖励验证数据

输入：

```json
{
  "businessCode": "reward",
  "templateCode": "daily_login_reward",
  "userId": 10001,
  "params": {
    "amount": "80",
    "loginStreak": "3"
  },
  "idempotencyKey": "daily_login_reward:10001:20260711"
}
```

期望：

- 生成一条未读消息。
- 标题为 `今日登录奖励已到账`。
- 正文包含 `80 龟币` 和 `连续登录 3 天`。
- 重复提交不生成第二条。

## 5. 预测结算验证数据

输入：

```json
{
  "businessCode": "dark_market",
  "templateCode": "predict_settle_win",
  "userId": 10001,
  "params": {
    "marketTitle": "BTC 周末方向",
    "payout": "180",
    "marketId": "20001"
  },
  "idempotencyKey": "predict_settle:90001:win"
}
```

期望：

- 生成一条暗盘未读消息。
- 点击消息后变成已读。
- `detailUrl=/predict/markets/20001`。

## 6. 上线验收

- 初始化 SQL 可重复执行。
- 所有模板能被公共推送方法读取。
- 用户只能看到自己的消息。
- 未读数与列表未读状态一致。
- 已读接口重复调用幂等成功。
- MVP 两个业务场景均能产生真实记录。
