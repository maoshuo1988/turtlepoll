# 特性详情介绍

## 1. 采集去重

### 1.1 目标

- 避免同一条资讯重复入库。
- 允许同一条资讯被多次采集但只保留一条主记录。

### 1.2 去重策略

- 优先使用外部唯一键：虎扑帖子 id（如 `bbs.hupu.com/{id}.html`）、原始 URL 或其稳定哈希。
- 当外部唯一键缺失时，使用 `source + title + publishedAt` 的组合指纹兜底。
- 去重命中后仅更新可变字段：摘要、正文、封面、标签、热度、更新时间。

### 1.3 风险

- 标题相近但内容不同的资讯，不能只靠标题去重。
- 不同分区转载同一资讯时，需要明确是否合并为一条或保留多来源副本。

## 2. 资讯聚合

### 2.1 目标

- 把虎扑资讯数据标准化成站内统一资讯模型。
- 让列表、详情、搜索、分类都基于同一套主数据。

### 2.2 归一项

- 标题、摘要、正文、封面图、作者/来源、发布时间。
- 分类、标签、专题、来源频道。
- 原文链接与抓取时间。

### 2.3 规则

- 标题为空的资讯不入库。
- 发布时间无法解析时，允许用抓取时间兜底，但要标记来源不完整。
- 正文过长时可在列表接口中返回截断摘要，详情接口返回完整内容。

## 3. 热度排序

### 3.1 目标

- 提供热门资讯列表，作为首页或频道页的补充排序。

### 3.2 口径定义

- 热度可由发布时间衰减、浏览次数、人工置顶、标签权重综合计算。
- 默认公式：`hotScore = baseScore + interactionScore + topScore - decayScore`。
- 初版 `baseScore` 固定为 50，`interactionScore` 由亮/回复线性映射，`topScore` 默认为 0。
- `decayScore` 按发布时间每小时衰减 1 分，最小衰减为 0。

## 4. 搜索与筛选

### 4.1 目标

- 支持按关键词、分类、来源、时间范围检索资讯。

### 4.2 规则定义

- `q` 优先匹配标题，其次摘要，再其次正文。
- 分类和标签筛选应使用站内归一后的字段。
- 列表接口必须支持分页，避免一次返回过多资讯。
- 分页默认 `page=1`、`pageSize=20`，`pageSize` 上限 200。

## 5. 错误与重试

### 5.1 目标

- 采集失败时可重试，不影响已入库资讯的查询。

### 5.2 规则定义

- 对临时网络错误、超时、429、5xx 做重试。
- 对结构变化、内容解析失败做记录并跳过该条。
- 单请求最多重试 3 次，退避序列为 30 秒、60 秒、120 秒。
- 连续 3 个批次失败时暂停采集 15 分钟并告警。
