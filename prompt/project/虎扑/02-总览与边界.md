# 总览与边界

## 1. 目标

- 从虎扑采集可公开访问的资讯数据，形成站内统一资讯库。
- 为前端提供稳定的资讯查看接口：列表、详情、分类、搜索。
- 为后台提供采集触发、重跑、失败排查入口。
- 支持按时间、分类、来源、热度等维度展示资讯。

## 2. 数据来源

- 虎扑公开可访问页面或接口（重点为 `https://www.hupu.com/` 首页资讯区与 `https://bbs.hupu.com/*` 资讯帖）。
- 采集时应以外部唯一标识、原始 URL、发布时间等信息辅助去重。
- 资讯内容应保留来源站点、来源频道、原文链接、抓取时间。

## 3. 非目标

- 不做资讯原创写作。
- 不做评论、点赞、收藏、转发等社交能力。
- 不做用户自定义频道推荐系统的完整闭环。
- 不做跨平台聚合资讯的统一采集，本期仅面向虎扑。
- 不做侵入式爬取或规避访问限制的设计。

## 4. 边界约束

- 必须遵守目标站点的访问策略与 robots/合规要求。
- 采集频率不能过高，避免给外部站点造成明显压力。
- 采集失败必须可回退，不允许影响资讯查询接口可用性。
- 所有资讯都应能追溯到外部来源与采集时间。
- 资讯列表接口必须只依赖站内数据库，不直接依赖外部站点实时查询。

## 5. 合规与访问控制细则

- 默认 `User-Agent` 固定为服务标识，不伪造浏览器指纹。
- 单 worker 抓取速率上限：1 请求/秒。
- 单域名并发上限：2。
- 抓取超时：5 秒；单请求最大重试次数：3。
- 出现 `429` 时至少退避 120 秒后再尝试。
- 连续 3 个批次失败后暂停该来源 15 分钟。
- 明确禁止登录态抓取和反爬绕过逻辑。
