# 撕裂带初始化数据说明

说明: 热度计算领域不管理话题与话题种子，话题创建由对立PK领域负责。本章仅定义热度计算系统级配置初始化。

## 1. 初始化目标

- 初始化撕裂带默认配置。
- 初始化赛季与回合基线数据模板。

## 2. 初始化顺序

1. 写入基础配置 `tear.*`。
2. 生成当前赛季 `season_no=1` 基线记录。

## 3. 默认配置种子

| key | value | 说明 |
|------|------|------|
| tear.enabled | true | 是否启用撕裂带热度计算功能；false时所有热度计算请求返回0 |
| tear.dark.mint_ratio | 0.1 | 暗盘热度转化铸币比例，每单位热度贡献 0.1 铸币额度 |
| tear.dark.mint_floor | 10 | 暗盘热度铸币最低阈值，低于此值不进行铸币分配 |
| tear.round.duration_seconds | 259200 | 回合计分窗口默认时长（秒），对应3天（259200秒=3*24*3600） |
| tear.round.cooldown_seconds | 600 | 对立PK业务冷却期（秒），用于结算后下一局创建前的等待窗口，不作为热度冻结触发条件 |
| tear.heat.comment_cap | 20 | 单条评论最大热度贡献上限，防止高频评论刷屏热度 |
| tear.heat.coin_factor | 0.02 | 投币热度线性系数，H_coin = BetAmount × 0.02 |
| tear.settle.retry_max | 3 | 热度结算下游消费失败的最大重试次数 |

## 4. 初始化校验

- 配置所有 `tear.*` 键的初始值必须与 03 表定义一致。
- 赛季基线 `season_no=1` 必须成功创建，用于后续回合初始化。

## 5. 回滚策略

- 初始化失败时按批次回滚事务。
- 若已生成部分事件，按 `init_batch_id` 全量删除重建。
