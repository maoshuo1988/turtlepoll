# 撕裂带接口

说明: 撕裂带热度计算领域采用被动接收模式，不直接提供用户侧或运营侧 HTTP 入口，也不主动向上游发起任何业务操作。本章只定义上游入口映射与本域内部调用契约。本域任何行为都不会对暗盘或对立PK的业务流程产生影响；上游系统可独立修改业务规则、时序、实现，只需保持入口与输出契约一致。

## 1. 上游入口映射（由其他系统提供）

### 1.1 下注入口（当前按对立PK口径）

- Method: `POST`
- URL: `/api/pk/bet`
- 归属系统: 对立PK领域
- 本域职责: 接收下注结果与阵营归属变化，更新 `BetAmount` 输入与热度快照。

请求示例（由上游定义）:

```json
{
  "topicId": 123,
  "roundId": 456,
  "side": "A",
  "requestId": "pk-bet-uuid"
}
```

### 1.2 评论入口

- Method: `POST`
- URL: `/api/pk/comment/create`
- 归属系统: 对立PK领域
- 本域职责: 接收评论写入结果，按评论作者阵营累计评论热度输入。

### 1.3 点赞入口

- Method: `POST`
- URL: `/api/pk/like`
- 归属系统: 对立PK领域
- 本域职责: 接收有效点赞结果，累计点赞热度输入。

### 1.4 回复入口

- Method: `POST`
- URL: `/api/pk/comment/reply`
- 归属系统: 对立PK领域
- 本域职责: 接收回复写入结果，按回复者阵营累计评论热度输入。

### 1.5 暗盘入口说明

- 暗盘仍通过其所属领域入口接入本域（不在本章扩展 URL 设计）。
- 本次调整仅修改对立PK相关入口口径。

### 1.6 事件热度榜单查询入口

- Method: `GET`
- URL: `/api/pk/heat/rank`
- 归属系统: 对立PK领域
- 本域职责: 返回事件全榜或本方榜单（用户名、头像、总热度）。

查询参数（由上游定义）:

- `topicId`/`roundId`
- `scope` (`ALL`/`MY_SIDE`)
- `page`/`pageSize`

### 1.7 我的事件数据查询入口

- Method: `GET`
- URL: `/api/pk/heat/me`
- 归属系统: 对立PK领域
- 本域职责: 返回我的互动与热度聚合数据。

### 1.8 当前下注赔率查询入口

- Method: `GET`
- URL: `/api/pk/odds/current`
- 归属系统: 对立PK领域
- 本域职责: 返回不同 option 的当前赔率。

### 1.9 评论回复查询返回option入口

- Method: `GET`
- URL: `/api/pk/comments`
- 归属系统: 对立PK领域
- 本域职责: 返回评论与回复时附带 `option`（即 `option_at_action`）。

返回契约:

- `list[]` 每项至少包含：`commentId/userId/content/createTime/option`。
- `option` 必须返回，取值来源固定为 `option_at_action`。
- 若历史数据缺失 `option_at_action`，允许一次性回填后返回，回填值为该记录创建时 `current_option`；回填后禁止再次改写。

## 2. 本域内部调用契约（非用户/非运营接口）

当前实现位置：`internal/services/tear_heat_service.go`

### 2.1 计算或刷新热度快照

- 方法名: `ComputeHeatSnapshot`
- 调用方向: PKService -> TearHeatService
- 输入结构: `TearHeatSnapshotComputeRequest`
  - `EventType` (string, 必填，当前仅支持 `pk`)
  - `EventId` (int64, 必填)
  - `TopicId` (int64, 必填)
  - `RoundId` (int64, 必填)
  - `SnapshotType` (string, 选填, `CHECKPOINT`/`SETTLE`)
  - `FreezeSource` (string, 选填, `ON_DEMAND` 等)
- 输出:
  - `options[]`（option/hLike/hComment/hCoin/hTotal/snapshotType/snapshotTime）
  - `snapshotTime` (int64)

实现说明:

- 当 `SnapshotType=SETTLE` 且已有 SETTLE 快照时，直接返回已有快照（幂等）。
- 当前只实现了 PK 事件类型，DARK 等类型尚未接入。

### 2.2 查询热度快照

- 方法名: `GetHeatSnapshot`
- 调用方向: PKService -> TearHeatService
- 输入结构: `TearHeatSnapshotQuery`
  - `EventType` (string, 必填)
  - `EventId` (int64, 必填)
  - `RoundId` (int64, 必填)
  - `SnapshotType` (string, 选填)
- 输出:
  - `options[]`（option/hLike/hComment/hCoin/hTotal/snapshotType/snapshotTime）

兼容规则:

- 未传 `SnapshotType` 时，默认使用 `CHECKPOINT`。
- 结算链路可显式传 `SnapshotType=SETTLE` 读取冻结快照。

### 2.3 其他能力说明

- 事件热度榜、我的热度数据、赔率查询、评论归属记录等能力当前由 `PKService` 直接读写相关表实现，未在 `TearHeatService` 内独立封装。
- 文档中不再声明 `RecordHeatInput`、`GetEventHeatRank`、`GetMyEventHeatProfile` 等未落地的方法名。

## 3. 错误码

错误处理原则：写入类热度错误为非致命性错误，不会阻塞或影响上游业务流程的继续推进。结算读取链路是例外：当对立PK在结算阶段请求 `SETTLE` 冻结快照时，若冻结或读取失败，应将失败返回上游，由上游阻塞本次结算并允许重试。

| 错误码 | 场景 | 上游处理 |
|------|------|------|
| unsupported event type | EventType 不是当前支持的类型 | 返回上游，阻塞本次请求 |
| db is required | 调用方未传 db/tx | 返回上游，阻塞本次请求 |
| eventId/topicId/roundId are required | 关键参数缺失 | 返回上游，阻塞本次请求 |

## 4. 边界约束

- 本域不设计用户侧 HTTP 入口，不干扰用户交互流程。
- 本域不设计运营侧 HTTP 入口，不干扰运营管理流程。
- 写入类调用不阻塞上游业务操作；结算阶段的冻结与读快照调用允许返回错误给上游。
- 下注、评论、点赞、回复入口 URL 以各上游系统文档为准，本章仅做映射。
