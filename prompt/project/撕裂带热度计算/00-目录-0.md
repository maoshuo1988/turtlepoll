## 3. 设计范围

- 热度计算能力: 统一热度公式、统一站队规则、统一风控与幂等策略。
- 调用边界: 热度计算由对立PK或预测市场触发（暗盘为预测市场别名），本目录不定义触发流程本身。
- 下游消费: 热度结果可被预测市场结算或对立PK胜负判定消费。

## 4. 核心设计原则

- **支撑性**：热度计算不反向依赖或约束上游业务。
- **被动**：纯被动接收模式，不主动向上游发起操作。
- **独立**：不耦合暗盘或对立PK的实现细节。
- **可扩展**：支持任意第三方业务域接入。
