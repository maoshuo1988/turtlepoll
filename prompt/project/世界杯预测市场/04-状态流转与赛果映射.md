## 5. 状态流转

### 5.1 赛程状态到市场状态

当前 MVP 只按“球队是否确定”控制开盘：

```text
homeTeam 和 awayTeam 都非空 -> OPEN
任一为空 -> CLOSED/CLOSE
```

建议演进为完整状态映射：

| football-data status | 站内 PredictMarket.status | 说明 |
|------|------|------|
| `SCHEDULED/TIMED` 且球队确定 | `OPEN` | 可下注 |
| `SCHEDULED/TIMED` 但球队未确定 | `CLOSED` | 只展示，不可下注 |
| `IN_PLAY/PAUSED` | `CLOSED` | 比赛已开始，禁止下注 |
| `FINISHED` | `SETTLED` 或 `CLOSED` | 小组赛可映射 `A/B/DRAW`；淘汰赛只映射 `A/B`，平局记错误日志并交运营 |
| `POSTPONED/CANCELLED/SUSPENDED` | `CLOSED` | 后续可走退款/作废 |

当前代码注意点：

- `FootballSyncService.SyncWorldCupSchedules` 没有读取 football-data 的 `score` 字段。
- `MatchSchedule` 模型没有比分字段。
- `PredictMarket.result` 不会由轮询任务自动写入。
- `PredictMarket.status` 当前只在同步中按队名是否齐全写为 `OPEN` 或 `CLOSE`，没有按 `FINISHED` 自动变为 `SETTLED`。
- 管理员结算接口要求市场状态为 `CLOSED`，但轮询服务当前写的是 `CLOSE`，这两个状态值需要统一，否则自动生成的关闭市场可能无法直接走 admin settle。

### 5.1.1 比分到预测市场结果

目标规则：

```text
A = 主队胜
B = 客队胜
```

当 football-data 返回 `FINISHED` 且比分可用时：

```text
homeScore > awayScore -> PredictMarket.result = A
homeScore < awayScore -> PredictMarket.result = B
homeScore = awayScore 且小组赛 -> PredictMarket.result = DRAW
homeScore = awayScore 且淘汰赛 -> 记录错误日志，交运营人员结算
```

建议落库：

```text
MatchSchedule.homeScore
MatchSchedule.awayScore
MatchSchedule.winner = A/B/DRAW/UNKNOWN
PredictMarket.result = A/B/DRAW
PredictMarket.status = SETTLED / CLOSED
```

平局处理口径已经明确：

- 小组赛支持平局：平局是下注选项之一，用户可以下注 `DRAW`。
- 淘汰赛不支持平局：如果同步发现淘汰赛比分平局，视为外部数据异常或加时/点球口径未取到，记录错误日志，闭环流程交由运营人员结算。

小组赛平局结算规则：

```text
football-data FINISHED + stage/group 判断为小组赛
  -> homeScore == awayScore
    -> MatchSchedule.winner = DRAW
    -> PredictMarket.result = DRAW
    -> PredictMarket.status = SETTLED 或进入运营确认
    -> 遍历该 market 未结算 PredictBet
      -> bet.status = SETTLED
      -> bet.option == DRAW 的用户 WIN，按锁定赔率派奖
      -> bet.option != DRAW 的用户 LOSE，payout = 0
      -> UserCoinLog bizType = SETTLE
```

结算必须幂等：

- 只处理 `PredictBet.status=OPEN` 的下注单。
- 已 `SETTLED` 的下注单不重复结算。
- 金币流水 `bizType=SETTLE`，`bizId=PredictBet.Id`。
- 推荐在事务内锁定 `PredictMarket` 和相关 `PredictBet`。

淘汰赛平局异常规则：

```text
football-data FINISHED + stage 判断为淘汰赛
  -> homeScore == awayScore
    -> slog.Error("knockout match ended draw, manual settlement required", ...)
    -> MatchSchedule.winner = UNKNOWN 或 DRAW
    -> PredictMarket.status = CLOSED
    -> 不写 PredictMarket.result
    -> 不自动退款、不自动派奖
    -> 运营人员通过后台 settle/void/refund 完成闭环
```

小组赛判断建议：

```text
stage == GROUP_STAGE
或 groupName 非空
```

淘汰赛判断建议：

```text
stage in LAST_16 / QUARTER_FINALS / SEMI_FINALS / THIRD_PLACE / FINAL
或 groupName 为空且 stage != GROUP_STAGE
```


### 5.2 封盘时间

封盘时间：

```text
closeTime = utcDate - 10 minutes
```

下注接口仍以 `PredictMarket.status == OPEN` 且 `now < closeTime` 为准。

即使 cron 延迟，下注服务也会用 `closeTime` 拦住过期下注。
