## 6. 幂等与并发

### 6.1 幂等约束

必须保证以下数据不会重复：

1. 同一 football-data match 只生成一条 `MatchSchedule`。
2. 同一 `MatchSchedule` 只生成一条 `PredictMarket`。
3. 同一 `PredictMarket` 只生成一条 `PredictContext`。

建议数据库唯一索引：

```text
MatchSchedule(source, external_id)
PredictMarket(source_model, source_model_id)
PredictContext(market_id)
```

### 6.2 重入控制

当前 scheduler 使用：

```go
cron.SkipIfStillRunning(cron.DefaultLogger)
```

同一个进程内，上一轮同步未结束时会跳过下一轮，避免任务重叠。

如果未来多实例部署，需要增加跨实例锁：

- 数据库 advisory lock。
- `t_job_lock` 表。
- Redis 分布式锁。

## 7. 错误处理与日志

### 7.1 失败处理

同步失败不应影响主服务运行：

- API Key 为空：记录 warning 后跳过。
- football-data 请求失败：记录 error，本轮退出。
- 单场落库失败：当前实现直接返回错误并终止本轮。

建议后续优化：

- 单场失败不影响后续比赛，记录失败列表。
- 增加 `sync_status` 或 `job_log`，便于后台查看最近同步结果。
- 对 429/rate limit 做退避。

### 7.2 关键日志

应至少保留：

```text
football-data api response received matches=...
football schedules synced matches=...
football schedule sync failed err=...
```

排查命令：

```bash
sudo journalctl -u bbs-go --no-pager -n 300 | grep -i "football"
```

## 9. 与预测市场下注/结算的关系

世界杯同步只负责“创建可下注市场”，不负责下注和派彩。

下注链路：

```text
PredictMarket.OPEN
  -> 用户 POST /api/coin/bet
    -> 创建 PredictBet
    -> 扣金币
    -> 更新 poolA/poolB
```

当前已实现结算链路：

```text
管理员确认比赛/市场结果
  -> POST /api/admin/predict/market/settle { marketId, result: "A"|"B" }
    -> PredictMarket.status = SETTLED
    -> PredictMarket.result = A/B
      -> 用户 POST /api/coin/settle
        -> PredictSettleService.SettleMyBet
          -> 读取 market.result
          -> 将 PredictBet.option 与 result 比较
          -> WIN 派奖，LOSE 不派
```

注意：`PredictSettleService` 不读 `MatchSchedule.status`，也不读 football-data 结果。它只读：

```text
PredictMarket.status == SETTLED
PredictMarket.result == A or B
```

后续如果要让比赛结果驱动结算，需要新增链路：

```text
football-data FINISHED
  -> 保存 MatchSchedule 比分
    -> 小组赛：按 A/B/DRAW 映射结果
      -> 写 PredictMarket.result = A/B/DRAW
      -> 写 PredictMarket.status = SETTLED 或进入运营确认
    -> 淘汰赛非平局：按 A/B 映射胜方
      -> 写 PredictMarket.result = A/B
      -> 写 PredictMarket.status = SETTLED 或进入运营确认
    -> 淘汰赛平局：记录错误日志
      -> PredictMarket.status = CLOSED
      -> 运营人员手动结算/作废/退款
```

当前需要明确的问题：

- A/B 如何映射主客队。
- 比赛取消/延期时是否退款。
