## 11. 代码链路核对

### 11.1 轮询同步写了什么

入口：

```go
// internal/scheduler/cron.go
services.FootballSyncService.SyncWorldCupSchedules(context.Background())
```

服务：

```go
// internal/services/football_sync_service.go
func (s *footballSyncService) SyncWorldCupSchedules(ctx context.Context) error
```

该服务当前只使用 football-data 返回的这些字段：

```go
m.ID
m.Competition.Code
m.Season.Year
m.Matchday
m.Stage
m.Group
m.Status
m.UtcDate
m.HomeTeam.Name
m.AwayTeam.Name
m.HomeTeam.ID
m.AwayTeam.ID
```

它会写入：

```go
schedule.Status = m.Status
schedule.UtcDate = m.UtcDate.Unix()
schedule.HomeTeam = m.HomeTeam.Name
schedule.AwayTeam = m.AwayTeam.Name
```

但当前 `footballdata.Match` 结构体没有 `Score` 字段，`MatchSchedule` 模型也没有比分字段。因此即使 football-data 返回 `FINISHED`，当前代码也只会保存：

```text
MatchSchedule.status = FINISHED
```

不会保存比分，也不会计算谁赢。

### 11.2 轮询如何影响 PredictMarket

轮询创建或更新市场时，核心规则是：

```go
title := buildMarketTitle(schedule.HomeTeam, schedule.AwayTeam)
desiredStatus := "CLOSE"
if isTeamsReady(schedule.HomeTeam, schedule.AwayTeam) {
    desiredStatus = "OPEN"
}
market.Title = title
market.Status = desiredStatus
market.CloseTime = schedule.UtcDate - 10*time.Minute
```

也就是说当前轮询只影响：

```text
PredictMarket.title
PredictMarket.status
PredictMarket.closeTime
PredictMarket.sourceModel/sourceModelId
```

不会影响：

```text
PredictMarket.result
PredictMarket.resolved
PredictMarket.resolvedAt
```

因此“比赛结果”和“预测市场结算结果”目前没有自动代码关联。

目标实现后，轮询会额外影响：

```text
MatchSchedule.homeScore/awayScore/winner
PredictMarket.result
PredictMarket.status 或待确认状态
```

但必须遵守字段保护规则：

- 主客队确定后不覆盖主客队身份。
- 不覆盖 `PredictContext.detail/imageUrl/heat/participantCount`。

### 11.3 管理员如何写入预测市场结果

管理员结算入口：

```go
// internal/controllers/admin/predict_controller.go
PostMarket_settle()
```

它要求：

```go
result := strings.ToUpper(strings.TrimSpace(form.Result))
if result != "A" && result != "B" {
    return web.JsonErrorMsg("result must be A or B")
}
```

并且默认只允许：

```go
if m.Status != "CLOSED" {
    return fmt.Errorf("market status must be CLOSED ...")
}
```

成功后写入：

```go
m.Status = "SETTLED"
m.Result = result
m.Resolved = true
m.ResolvedAt = now
```

注意：当前轮询服务关闭市场时写的是 `CLOSE`，管理员结算接口要求的是 `CLOSED`。这会造成状态值不一致，建议优先修正为统一 `CLOSED`。

### 11.4 用户结算如何读取结果

用户结算入口：

```go
// internal/services/predict_settle_service.go
PredictSettleService.SettleMyBet(userId, marketId)
```

它只读取 `PredictMarket`：

```go
if market.Status != "SETTLED" {
    return errors.New("market is not settled")
}
winner := strings.ToUpper(strings.TrimSpace(market.Result))
if !IsValidPredictOption(market.MarketType, winner) {
    return errors.New("market result must match market options")
}
```

然后比较下注单：

```go
isWin := bet.Option == winner
```

所以用户最终 WIN/LOSE 的唯一依据是：

```text
PredictBet.option == PredictMarket.result
```

不是：

```text
MatchSchedule.status
football-data FINISHED
football-data score
```

### 11.5 当前真实闭环

```text
football-data 轮询
  -> 写 MatchSchedule.status/队名/开赛时间
  -> 写 PredictMarket.title/status/closeTime
  -> 写 PredictContext.eventName/proText/conText/tags

管理员人工确认结果
  -> POST /api/admin/predict/market/settle
  -> 写 PredictMarket.status=SETTLED
  -> 写 PredictMarket.result=A/B

用户领取结算
  -> POST /api/coin/settle
  -> PredictBet.option 与 PredictMarket.result 比较
  -> 写 PredictBet.settleResult/payout/settleTime
  -> 写金币入账流水
```

### 11.6 要实现自动赛果联动需要补什么

需要新增或修改：

1. `footballdata.Match` 增加 `score` 结构。
2. `MatchSchedule` 增加比分字段，例如 `homeScore/awayScore/winner`。
3. `FootballSyncService.SyncWorldCupSchedules` 在 `m.Status == FINISHED` 时保存比分。
4. 定义选项映射：小组赛 `A=主胜/B=客胜/DRAW=平局`；淘汰赛 `A=主胜/B=客胜`。
5. 处理平局：小组赛平局作为 `DRAW` 结果正常结算；淘汰赛平局记录错误日志并交运营处理。
6. 将 `PredictMarket.status` 统一为 `CLOSED`，避免 `CLOSE` 与 admin settle 冲突。
7. 新增“半自动结算”：轮询识别结果后先写待确认字段，管理员确认后 `SETTLED`。
8. 增加中文队名翻译表，并在写入 `MatchSchedule/PredictMarket/PredictContext` 前完成翻译。
9. 增加主客队冻结判断，已确定主客队的场次不再覆盖身份字段。
10. 将 `PredictContext.detail/imageUrl/heat/participantCount` 从同步更新白名单中移除，仅允许运营接口修改。

## 12. 推荐演进

### P0：稳定同步与展示

- 保持当前轮询生成 `MatchSchedule/PredictMarket/PredictContext`。
- 统一关闭状态为 `CLOSED`，修正当前 `CLOSE` 与 admin settle 要求不一致的问题。
- 增加同步结果日志和最近同步时间。
- 后台展示“最近同步时间/同步比赛数/失败原因”。
- 同步生成中文队名和中文市场标题。
- 同步赛程时区分小组赛/淘汰赛，并分别创建三元/二元市场。
- 已确定主客队的场次不再覆盖主客队身份。
- 同步流程不覆盖运营字段：说明、封面图、热度、参与人数。

### P1：赛果驱动结算

- 扩展 football-data client 与 `MatchSchedule`，保存全场比分。
- 将小组赛主胜/客胜/平局映射为站内 `result=A/B/DRAW`。
- 将淘汰赛主胜/客胜映射为站内 `result=A/B`。
- 小组赛平局作为正常结果结算。
- 淘汰赛平局记录错误日志，交运营人员结算。
- 对 `CLOSED` 市场写入待确认结果。
- 后台人工确认后进入 `SETTLED`。

### P2：全自动闭环

- 到达 `FINISHED` 后自动结算非平局、低风险比赛。
- 小组赛平局按 `DRAW` 自动结算。
- 异常比赛进入人工审核队列。
- 作废/延期自动冻结或退款。
- 推送用户下注结果。

## 13. 验收清单

1. 配置 `footballData.apiKey` 后，服务启动日志出现 scheduler 注册成功。
2. 手动触发或等待 cron 后，`MatchSchedule` 有世界杯赛程。
3. 每条赛程最多对应一条 `PredictMarket`。
4. 每条市场最多对应一条 `PredictContext`。
5. 球队未确定时市场不可下注。
6. 球队确定且未到 `closeTime` 时市场可下注。
7. 运营手工编辑的 `imageUrl/detail/heat/participantCount` 不会被下一轮同步覆盖。
8. 重复执行同步不会产生重复市场。
9. 前端 `GET /api/football/markets` 能看到同步生成的市场。
10. 标签刷新后，`football` 与 `wc` 标签可被查询。
11. 已确定主客队的场次，后续同步不覆盖主客队名称和 ID。
12. 中文队名翻译后，市场标题和 A/B 文案展示中文。
13. 比赛 `FINISHED` 且非平局时，比分能映射出 `PredictMarket.result=A/B`。
14. 小组赛平局时，比分能映射出 `PredictMarket.result=DRAW`，下注 `DRAW` 的用户赢。
15. 淘汰赛平局时，系统记录错误日志，不自动退款、不自动派奖，运营人员接管闭环。
