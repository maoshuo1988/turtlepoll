## 1. 已实现

### 1.1 football-data 赛程同步

- 已实现从 football-data 拉取指定赛事比赛列表。
- 已实现配置项：`apiKey/competitionCode/season/cronSpec`。
- 已实现 API Key 为空时跳过同步并记录 warning。
- 已实现同步成功日志：`football-data api response received`、`football schedules synced`。

代码位置：

- `internal/services/football_sync_service.go`
- `internal/pkg/footballdata/client.go`
- `internal/pkg/config/config.go`

### 1.2 MatchSchedule 落库

- 已实现根据 `source=football-data` 和 `externalId` 幂等写入赛程。
- 已保存字段：
  - `competition`
  - `season`
  - `externalId`
  - `matchday`
  - `stage`
  - `groupName`
  - `matchPhase`
  - `status`
  - `utcDate`
  - `homeTeam/awayTeam`
  - `homeTeamId/awayTeamId`
  - `homeScore/awayScore`
  - `winner`
  - `lastSyncedAt`

代码位置：

- `internal/models/models/predict_models.go`
- `internal/services/football_sync_service.go`

### 1.3 小组赛和淘汰赛识别

- 已实现根据 `stage/groupName` 识别 `matchPhase=GROUP/KNOCKOUT/UNKNOWN`。
- 已实现小组赛市场写入 `marketType=1x2`。
- 已实现淘汰赛市场写入 `marketType=binary`。
- 已实现 `GET /api/football/markets` 和按名称查询返回 `schedule` 与 `matchPhase`。
- 已实现 `GET /api/football/schedules` 返回 `MatchSchedule.matchPhase`。

代码位置：

- `internal/services/football_sync_service.go`
- `internal/controllers/api/football_controller.go`

### 1.4 PredictMarket 创建与更新

- 已实现每个 `MatchSchedule` 对应一条 `PredictMarket`。
- 已实现幂等键：`sourceModel=MatchSchedule` + `sourceModelId=MatchSchedule.Id`。
- 已实现市场标题生成：`{homeTeam} vs {awayTeam}`，缺队名时使用 `TBD`。
- 已实现开盘判断：主客队都有值且比赛未开始时 `OPEN`，否则 `CLOSED`。
- 已实现 `closeTime = utcDate - 10 分钟`。
- 已实现根据赛制写入 `marketType=1x2/binary`。
- 已实现 `FINISHED` 且结果明确时写入 `result` 并置为 `SETTLED`。
- 已实现同步刷新：
  - `title`
  - `marketType`
  - `status`
  - `closeTime`

代码位置：

- `internal/services/football_sync_service.go`
- `internal/models/models/predict_models.go`

### 1.5 PredictContext 创建与更新

- 已实现每个 `PredictMarket` 对应一条 `PredictContext`。
- 已实现创建时写入：
  - `eventName`
  - `imageUrl=""`
  - `participantCount=0`
  - `proText`
  - `conText`
  - `detail=""`
  - `tags=football,{competition}`
- 已实现同步更新时仅刷新：
  - `eventName`
  - `proText`
  - `conText`
  - `tags`
- 已避免同步更新覆盖 `imageUrl/detail/heat/participantCount`。

代码位置：

- `internal/services/football_sync_service.go`
- `internal/models/models/predict_models.go`

### 1.6 定时任务与手动触发

- `internal/scheduler/cron.go`

### 1.8 A/B 与 A/B/DRAW 下注

- 已实现用户下注接口：`POST /api/coin/bet`。
- 已实现二元市场 `binary` 只允许 `A/B`。
- 已实现小组赛三元市场 `1x2` 允许 `A/B/DRAW`。
- 已实现市场状态校验：只允许 `OPEN`。
- 已实现 `closeTime` 校验。
- 已实现下注时锁定赔率。
- 已实现二元市场使用 `poolA/poolB` 计算赔率。
- 已实现三元市场使用 `poolA/poolB/poolDraw` 计算赔率。
- 已实现事务内创建下注单、扣金币、更新下注池。
- 已实现对 `PredictMarket` 加行锁，避免并发下注池更新丢失。

代码位置：

- `internal/controllers/api/coin_controller.go`
- `internal/services/predict_bet_service.go`
- `internal/services/predict_odds.go`

### 1.9 A/B/DRAW 结算

- 已实现管理员写入市场结果：`POST /api/admin/predict/market/settle`。
- 已实现管理员结果按市场类型校验：
  - `binary` 允许 `A/B`
  - `1x2` 允许 `A/B/DRAW`
- 已实现管理员将市场从 `CLOSED/CLOSE` 置为 `SETTLED`。
- 已实现用户结算接口：`POST /api/coin/settle`。
- 已实现用户结算读取 `PredictMarket.result`。
- 已实现中奖判断：`PredictBet.option == PredictMarket.result`。
- 已实现赢单按锁定赔率派奖，输单不派。
- 已实现只结算 `OPEN` 下注单，避免重复派奖。

代码位置：

- `internal/controllers/admin/predict_controller.go`
- `internal/services/predict_settle_service.go`
- `internal/controllers/api/coin_controller.go`

## 2. 部分实现

### 2.1 运营字段保护

已实现：

- 同步更新已有 `PredictContext` 时没有覆盖 `imageUrl/detail/heat/participantCount`。

仍需补齐：

- 当前 `POST /api/football/predict_context/update` 位于用户侧 football controller，后续建议迁移或补充 admin 接口。
- 尚未为运营修改建立更完整的审计日志。

### 2.2 上下文展示字段

已实现：

- `proText={homeTeam} 胜`
- `conText={awayTeam} 胜`

未完全实现：

- 小组赛平局展示字段 `drawText` 尚未建模。
- 三元市场前端展示结构尚未统一。

### 2.3 自动赛果联动结算

已实现：

- football-data `FINISHED` 且比分明确时可以写入 `PredictMarket.result`。
- 小组赛平局可以写入 `DRAW`。
- 淘汰赛平局记录错误日志，不自动派奖。

仍需补齐：

- 当前是同步侧直接置 `SETTLED`，尚未实现“待运营确认”的半自动审核状态。
- 尚未实现后台异常队列。

## 3. 未实现

### 3.1 比赛取消、延期、作废处理

- 尚未实现 `POSTPONED/CANCELLED/SUSPENDED` 的资金处理。
- 尚未实现预测市场 void/refund 流程。
- 尚未实现延期后重新开盘或保持封盘的规则。

### 3.2 多实例同步锁

- 当前只通过 `cron.SkipIfStillRunning` 避免单进程重入。
- 多实例部署下尚未实现跨实例锁。

可选方案：

- 数据库 advisory lock。
- `t_job_lock` 表。
- Redis 分布式锁。

### 3.3 运营纠错闭环

- 尚未实现主客队冻结后的运营纠错接口。
- 尚未实现淘汰赛平局异常的后台处理队列。
- 尚未实现对自动写入赛果的人工复核入口。

## 4. 优先级建议

### P0

1. 为线上数据库执行字段迁移或确认 GORM 自动迁移已覆盖新增字段。
2. 前端接入 `marketType/matchPhase/schedule` 展示二元和三元玩法。
3. 后台确认 `DRAW` 结算、统计和用户结算交互。

### P1

1. 增加半自动赛果确认。
2. 增加淘汰赛平局异常处理队列。

### P2

1. 取消/延期/作废退款闭环。
2. 多实例同步锁。
3. 运营纠错接口和操作审计。
