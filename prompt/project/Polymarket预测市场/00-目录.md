## 核心口径

- 当前 Polymarket 只做 Gamma API 只读同步，不接 CLOB，不拉实时盘口。
- 同步范围由数据库表 `t_polymarket_discovery_tag` 控制。
- 定时启动配置在 `bbs-go.yaml` 的 `polymarket.discoveryCron` 和 `polymarket.trackingCron` 中维护，当前使用 5 字段 cron 表达式。
- 通用下注、运营结算、用户结算业务流见：[预测市场公共部分](../预测市场公共部分/00-目录.md)。
- 同步会写入站内 `PredictMarket` 和 `PredictContext`，供前端列表、标签和下注复用。
- 用户下注成功后与一级评论热度入口统一复用 [撕裂带热度计算](../撕裂带热度计算/00-目录-0.md)。
- 新设计采用 Discovery 发现轮巡 + Tracking 状态轮巡，Tracking 必须按已记录的 market ID 精确拉取。
- 当前没有自动把 Polymarket resolved outcome 映射成站内 `PredictMarket.result=A/B`。
- 当前用户派奖依赖站内 `PredictMarket.status=SETTLED` 且 `result` 已明确。
- 运营可以通过 `POST /api/admin/predict/market/settle` 人工写入最终结果。
- 自动结算只负责把市场置为 `SETTLED` 并写入 `result`，不直接给用户打钱。
- 真正开工前以 `09-落地实现清单.md` 的外部接口、migration、配置和管理端接口为准。
