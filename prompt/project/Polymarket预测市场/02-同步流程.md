# Polymarket同步流程

## 1. 目标

Polymarket 同步的当前目标是：

1. 从 Gamma API 读取市场目录。
2. 按配置限制同步范围。
3. 幂等写入站内 `PredictMarket`。
4. 幂等写入站内 `PredictContext`。
5. 让已有预测市场列表、标签、下注、运营结算能力可以复用。

新目标架构：

```text
Discovery Poller
  -> 发现一批 market
  -> 记录 externalMarketId

Tracking Poller
  -> 按 externalMarketId 精确拉取
  -> 推进 CLOSED/SETTLED/OPS_PENDING/CANCELLED
```

当前不做：

- 不同步 CLOB 盘口。
- 不同步实时成交价。
- 不自动把外部 resolved outcome 转成站内派奖结果。

## 2. 入口

### 2.1 定时入口

代码：

```text
internal/scheduler/cron.go
```

当前代码流程：

```text
Start()
  -> if config.Instance.Polymarket.Enabled
  -> addCronFunc(pm.CronSpec, SyncMarkets)
```

目标拆分：

```text
Start()
  -> addCronFunc(discoverySpec, DiscoveryPoller)
  -> addCronFunc(trackingSpec, TrackingPoller)
```

默认 cron：

```text
*/30 * * * *
```

### 2.2 手动入口

接口：

```text
POST /api/football/sync_polymarket
```

代码：

```text
internal/controllers/api/football_controller.go
PostSync_polymarket()
  -> PolymarketSyncService.SyncMarkets(ctx)
```

说明：

- 该接口目前在用户侧 `/api/football`。
- 需要登录。
- 尚未迁移到 `/api/admin/predict`。

## 3. 配置

配置文件：`bbs-go.yaml`。

启动时读取顺序：

- 服务默认读取当前工作目录下的 `bbs-go.yaml`。
- 如果当前工作目录没有该文件，会继续尝试读取可执行文件同目录下的 `bbs-go.yaml`。
- 首次部署可从 `bbs-go.example.yaml` 复制生成，生产环境已有 `bbs-go.yaml` 时不要用示例文件覆盖。
- 当前代码默认文件名是 `bbs-go.yaml`；如果手上文件名是 `bbs-go.yml`，需要改名为 `bbs-go.yaml`。

启动命令示例：

```bash
BBSGO_ENV=prod ./bbs-go-server
```

本地开发从仓库根目录启动即可读取根目录下的 `bbs-go.yaml`：

```bash
BBSGO_ENV=prod go run ./main.go
```

### 3.1 完整启动配置示例

```yaml
polymarket:
  enabled: true
  baseURL: "https://gamma-api.polymarket.com"
  cronSpec: ""                       # 兼容旧配置；discoveryCron 为空时作为 Discovery cron
  discoveryCron: "*/30 * * * *"      # Discovery 发现新市场；5字段 cron
  trackingCron: "*/5 * * * *"        # Tracking 精确跟踪已发现市场；5字段 cron
  matchTags: true                    # 兼容旧配置；当前 tags 非空时总是按 Gamma 标签库解析并过滤
  tags:
    - politics                       # Gamma tag slug/name/id 均可；以 /tags 返回为准
    - sports
  marketSlugs: []
  marketIds: []
  discoveryPageSize: 50
  trackingBatchSize: 50
  maxRetry: 5
  retryBaseSeconds: 60
  autoSettleEnabled: true
  dryRun: false
```

配置语义：

| 字段 | 作用 |
|------|------|
| `enabled` | 是否启用 Polymarket 定时同步；`false` 时 Discovery 和 Tracking 都不会注册 |
| `baseURL` | Gamma API 地址，留空走默认 `https://gamma-api.polymarket.com` |
| `cronSpec` | 兼容旧配置；当 `discoveryCron` 为空时作为 Discovery cron |
| `discoveryCron` | Discovery 发现轮巡表达式，默认 `*/30 * * * *` |
| `trackingCron` | Tracking 精确跟踪表达式，默认 `*/5 * * * *` |
| `matchTags` | 兼容旧配置；当前 `tags` 非空时总是按 Gamma 标签库解析并过滤 |
| `tags` | Gamma tag slug/name/id；每个真实标签各拉取 `discoveryPageSize` 条 |
| `marketSlugs` | 额外指定 market slug 白名单 |
| `marketIds` | 指定 Polymarket market ID，启动后 Discovery 会先按 ID 精确登记 |
| `pageSize` | 兼容旧配置；`discoveryPageSize` 为空时作为 Discovery 分页大小 |
| `discoveryPageSize` | 每个 Gamma 标签每次拉取数量，默认 50，最大 100；`tags` 为空时全量拉一页 |
| `trackingBatchSize` | 每次 Tracking 从本地 tracking 表取出的批量数量，默认 50 |
| `maxRetry` | Tracking 连续失败阈值，默认 5 |
| `retryBaseSeconds` | Tracking 失败退避基数，默认 60；第 N 次失败延后 `60*N` 秒 |
| `autoSettleEnabled` | 是否允许 Tracking 自动写入站内 `SETTLED/result`，未配置时默认 `true` |
| `dryRun` | `true` 时只同步状态和记录 issue，不真正自动结算 |

### 3.2 配置方法

1. 复制示例配置：`cp bbs-go.example.yaml bbs-go.yaml`。
2. 设置 `polymarket.enabled: true`。
3. 建议配置 `tags`，Discovery 会先读取 Gamma `/tags`，把配置值按 slug/name/id 匹配成真实 tag_id。
4. 每个匹配到的 Gamma 标签会分别拉取一页 `/markets/keyset?tag_id=...&limit=discoveryPageSize`；`tags` 为空时才全量拉一页。
5. 生产环境建议保留 `discoveryCron: "*/30 * * * *"`、`trackingCron: "*/5 * * * *"`；临近结算窗口可临时提高频率。
6. 自动结算上线前可先设置 `dryRun: true` 验证 winner 映射和 issue 记录；确认无误后再改回 `false`。
7. 修改 `bbs-go.yaml` 后重启服务，定时任务会在进程启动时读取配置并注册。

非法配置：

```text
enabled=true
matchTags=true
tags=[]
marketSlugs=[]
marketIds=[]
```

会返回错误：

```text
polymarket enabled with matchTags=true but no tags/marketSlugs/marketIds configured
```

注意：

- 当前调度器按 5 字段 cron 表达式注册，不要写成带秒字段的 6 字段表达式。
- `enabled=false` 时手动调用同步入口也会跳过。
- `marketSlugs` 仍依赖列表扫描发现；一旦发现到 market，后续必须交给 Tracking 按 ID 精确拉取。
- `marketIds` 最适合做运营指定市场的强制登记和兜底跟踪。

## 4. 流程

### 4.1 当前总流程

```text
SyncMarkets(ctx)
  -> 读取 config.Instance.Polymarket
  -> 校验 enabled/tags/marketSlugs
  -> NewGammaClient(baseURL)
  -> ListTags()
  -> 构建 tagSlugToID
  -> 按 tags 分页同步 markets
  -> 按 marketSlugs 扫描同步 markets
  -> 输出 seen/upsert 日志
```

### 4.1.1 目标总流程

```text
DiscoveryPoller
  -> 按 tag/slug 拉一批 market
  -> upsert market/context/outcome
  -> upsert tracking row

TrackingPoller
  -> 读取 tracking rows
  -> GET /markets/{externalMarketId}
  -> upsert latest market/context/outcome
  -> unresolved: 继续 TRACKING
  -> resolved + 映射成功: SETTLED
  -> resolved + 映射失败: OPS_PENDING
```

### 4.2 Discovery 按 tag 发现

```text
for tagSlug in config.polymarket.tags:
  tagID = tagSlugToID[tagSlug]
  params = {"tag_id": tagID}
  syncMarketsPaged(params, baseTags=["polymarket", tagSlug])
```

分页限制：

- `maxPages=200`
- `pageSize` 默认 50，最大 100

写入：

```text
upsertMarketAndContext(market, baseTags)
```

Discovery 发现后必须记录：

```text
externalMarketId
trackingStatus=TRACKING
nextTrackAt
```

### 4.3 Discovery 按 market slug 发现

```text
target = set(config.polymarket.marketSlugs)
for page in 0..49:
  list = ListMarkets(limit, offset)
  for market in list:
    if market.slug in target:
       upsertMarketAndContext(market, ["polymarket"])
```

限制：

- 最大扫描 50 页。
- 依赖 Gamma 列表顺序。
- 不是服务端 slug 精确查询。

因此 slug 发现不能保证长期跟踪；一旦发现到 market，后续必须交给 Tracking 按 ID 精确拉取。

### 4.4 Tracking 按 market ID 精确跟踪

目标接口：

```text
GET /markets/{id}
```

流程：

```text
for tracking row:
  market = GetMarketByID(externalMarketId)
  upsert latest fields
  try auto settlement
  update tracking status
```

保证：

- ID 已记录后，后续不依赖 tag 分页。
- ID=99 被记录后，Tracking 必须请求 `/markets/99`。

### 4.5 状态计算

当前规则：

```text
status = OPEN

if resolved:
  status = CLOSE
else if closeTs > 0 && closeTs <= now:
  status = CLOSE
```

注意：

- 当前使用 `CLOSE`，不是 `CLOSED`。
- 当前 resolved 不会自动置为 `SETTLED`。
- 用户结算要求 `status=SETTLED`。

### 4.6 resolved 信息提取

代码：

```text
extractResolution(m)
```

支持：

- `m.Resolved`
- `m.ResolvedAt`
- `m.Resolution`
- `CANCELLED`
- `INVALID`

输出：

```text
resolved
outcomeID
outcomeName
resolvedAt
```

限制：

- 如果 Gamma 只在 outcomes 内标记 winner，当前没有解析。
- 如果 `resolution` 文本不是站内 A/B，当前没有安全映射。

## 5. 幂等规则

### 5.1 PredictMarket 幂等

使用：

```text
source_model = Polymarket
source_model_id = externalMarketIDNum
```

查找：

```go
db.Where("source_model = ? AND source_model_id = ?", "Polymarket", externalMarketIDNum)
```

表约束：

```text
uniqueIndex:idx_predict_market_source
```

风险：

- `sourceModelId` 是 int64。
- 非数字外部 ID 会被转成 0。
- 当前兜底用 `now`，不具备强幂等。

### 5.2 PredictContext 幂等

使用：

```text
market_id
```

规则：

- 不存在：创建。
- 存在：更新 `eventName/tags/updateTime`。

### 5.3 标签去重

同步中构建 tags 时使用本地 map 去重：

```text
baseTags + market.Tags.slug
```

大小写：

- 全部 `lowercase`
- trim 空格

## 6. 错误与日志

同步会记录：

- 同步开始配置。
- tags 拉取数量。
- tag 映射数量。
- 每个 tag 同步开始/结束。
- markets 分页数量。
- upsert 成功/失败数量。

错误会中断：

- Gamma API 请求失败。
- JSON 解析失败。
- 数据库 upsert 失败。

不会中断：

- 单个 tag slug 在 Gamma tags 中找不到，只记录 warn 后跳过。
- tag id 无法解析成 int64，会跳过该 tag 映射。
