# Polymarket自动结算设计

> 本文只描述设计，不修改代码。目标是把 `3.2 自动结算闭环` 拆成可逐项实现、可逐项验收的原子特性。

流程图说明见：[07-自动结算流程图](./07-自动结算流程图.md)。

双轮巡跟踪说明见：[08-双轮巡跟踪设计](./08-双轮巡跟踪设计.md)。

## 1. 目标

自动结算要解决的问题：

```text
Polymarket Gamma resolved outcome
  -> 识别外部赢家
  -> 映射为站内 A/B
  -> 写 PredictMarket.result
  -> 写 PredictMarket.status=SETTLED
  -> 用户可通过 /api/coin/settle 领取派奖
```

自动结算由 Tracking 状态轮巡触发，而不是由 Discovery 发现轮巡承担。

不做的事：

- 不接 CLOB 下单。
- 不用 Polymarket 外部价格计算站内赔率。
- 不在无法确定赢家时猜测 A/B。
- 不自动处理取消/无效市场退款，退款单独设计。

## 2. 外部接口字段

当前使用 Gamma API：

```text
GET /markets
GET /tags
```

自动结算至少需要从 market 中读取：

| 字段 | 用途 |
|------|------|
| `id` | 外部 market 幂等键 |
| `slug` | 白名单同步、排查 |
| `question/title` | 站内标题 |
| `active` | 是否仍活跃 |
| `closed` | 是否关闭 |
| `resolved` | 是否已有最终结果 |
| `resolvedAt` | 外部结算时间 |
| `resolution` | 可能的赢家文本或取消标记 |
| `outcomes` | 外部候选项 |
| `clobTokenIds` | outcome 对应 token，建议保存 |
| `outcomePrices` | 可辅助判断，不能单独作为结算依据 |

当前代码已支持 `resolved/resolvedAt/resolution/outcomes`，尚未支持 `clobTokenIds/outcomePrices` 及 outcome winner 标记兼容字段。

## 3. 原子特性拆分

### 3.1 Gamma Market 字段补全

状态：未实现

目标：

- 扩展 `polymarket.Market`，读取 `clobTokenIds` 和 `outcomePrices`。
- 兼容字段是数组或 JSON 字符串两种形式。

实现说明：

- 新增通用字符串数组解析类型。
- `clobTokenIds` 保存为 `[]string`。
- `outcomePrices` 可以保存为 `[]string` 或 `[]decimal string`，自动结算不依赖它。

验收：

- `["Yes","No"]` 字符串 JSON 能解析。
- `["123","456"]` token 字符串 JSON 能解析。
- 原生数组能解析。
- 解析失败不阻断整个 market 同步。

### 3.2 Outcome 映射表

状态：未实现

目标：

- 保存 Polymarket outcome 与站内下注选项的关系。

建议表：

```text
t_predict_market_outcome
```

字段：

| 字段 | 说明 |
|------|------|
| `market_id` | 站内 PredictMarket.Id |
| `external_outcome_id` | Gamma outcome id 或 name |
| `external_outcome_name` | Gamma outcome name |
| `external_token_id` | CLOB token id |
| `option` | A/B |
| `display_name` | 前端展示名 |
| `sort` | outcome 顺序 |
| `created_at/updated_at` | 时间 |

唯一键：

```text
unique(market_id, external_outcome_id)
unique(market_id, option)
```

验收：

- 同一个 market 的 A/B 各只有一条。
- 重复同步不会插入重复 outcome。
- outcome name 改变时更新展示名，不改变已确认 option。

### 3.3 Outcome 默认映射

状态：未实现

目标：

- 对二元 Polymarket 市场生成默认映射。

默认规则：

```text
outcomes[0] -> A
outcomes[1] -> B
```

约束：

- 仅当 outcome 数量等于 2 时自动生成。
- outcome 数量不是 2 时不自动映射。
- 已存在映射时不覆盖运营校正。

验收：

- Yes/No 市场生成 A/B。
- 已有人工改过的 A/B 不被同步覆盖。
- 三个以上 outcomes 不生成默认映射。

### 3.4 PredictContext 阵营文案同步

状态：未实现

目标：

- 用 outcome 映射填充站内 A/B 展示文案。

规则：

```text
option=A -> PredictContext.proText
option=B -> PredictContext.conText
```

保护：

- 只在 context 新建时写。
- 已存在 context 时不覆盖运营手改文案，除非后续单独设计强制刷新。

验收：

- 新 market 的 proText/conText 来自 outcome。
- 已存在 proText/conText 不被同步覆盖。

### 3.5 外部赢家识别

状态：未实现

目标：

- 从 Gamma market 中识别最终赢家。

识别优先级：

1. outcome 明确带 winner 标记。
2. `resolution` 精确匹配某个 outcome name。
3. `resolution` 精确匹配某个 external outcome id。
4. `resolution` 精确匹配某个 token id。

不允许：

- 不允许根据 `outcomePrices` 单独判断赢家。
- 不允许模糊匹配标题。
- 不允许把 `Yes/No` 固定写死成 A/B，必须查映射表。

验收：

- resolution=`Yes` 能匹配 Yes outcome。
- resolution=`No` 能匹配 No outcome。
- resolution 为空但 resolved=true 时不自动结算。
- 多个 outcome 同名时不自动结算。

### 3.6 赢家到站内选项映射

状态：未实现

目标：

- 将外部赢家映射为站内 `A/B`。

流程：

```text
winner external id/name/token
  -> 查 t_predict_market_outcome
  -> 得到 option=A/B
```

失败处理：

- 找不到映射：不自动结算。
- 映射结果不是 A/B：不自动结算。
- 同一赢家匹配多条：不自动结算。

验收：

- 有唯一映射时返回 A/B。
- 无映射时返回待运营处理。
- 冲突映射时记录错误日志。

### 3.7 自动写入站内结算结果

状态：未实现

目标：

- 在同步中把已确认 winner 的市场置为可用户结算。

写入：

```text
PredictMarket.result = A/B
PredictMarket.status = SETTLED
PredictMarket.resolved = true
PredictMarket.resolvedOutcomeId = external winner id
PredictMarket.resolvedOutcomeName = external winner name
PredictMarket.resolvedAt = Gamma resolvedAt or now
```

前置条件：

- market 来自 `Polymarket`。
- 外部明确 resolved。
- 已识别唯一 winner。
- winner 已映射为唯一 A/B。

保护：

- 已 `SETTLED` 且 result 非空时不重复覆盖。
- 如果需要纠错，交由 admin settle 的 `allowReset` 流程。

验收：

- resolved 且映射明确时自动 `SETTLED`。
- unresolved 不会 `SETTLED`。
- 映射失败时保持 `CLOSED`。

### 3.8 封盘状态统一

状态：未实现

目标：

- Polymarket 新同步数据不再写 `CLOSE`。

状态规则：

```text
active=true 且未到 closeTime -> OPEN
closed=true 或 closeTime 已到 -> CLOSED
resolved=true 且映射成功 -> SETTLED
resolved=true 但映射失败 -> CLOSED
```

验收：

- 新数据无 `CLOSE`。
- admin settle 仍兼容历史 `CLOSE`。
- 用户结算仍只接受 `SETTLED`。

### 3.9 自动结算失败日志

状态：未实现

目标：

- 对无法自动结算的 resolved market 留下可排查日志。

日志字段：

- marketId
- externalMarketId
- slug
- resolution
- resolvedAt
- reason

reason 枚举建议：

```text
NO_WINNER
NO_OUTCOME_MAPPING
AMBIGUOUS_OUTCOME
INVALID_MARKET_TYPE
CANCELLED_OR_INVALID
```

验收：

- resolved=true 但无法结算时必有日志。
- 日志不阻断其他 market 同步。

### 3.10 运营待处理队列

状态：未实现

目标：

- 把自动结算失败的市场暴露给运营处理。

最小实现：

- 先不建表。
- 用查询条件筛：

```text
sourceModel=Polymarket
resolved=true
status=CLOSED
result=''
```

后续增强：

- 增加 sync issue 表。
- 支持运营补 outcome 映射后重跑同步。

验收：

- 运营能查到所有 resolved 但未自动结算的市场。
- 补映射后再次同步可自动结算。

## 4. 自动结算主流程

```text
upsertMarketAndContext(market)
  -> upsert PredictMarket
  -> upsert MarketOutcome mappings
  -> upsert PredictContext
  -> if not resolved:
       set OPEN/CLOSED
       return
  -> winner = detectExternalWinner(market)
  -> if winner missing:
       mark CLOSED
       log NO_WINNER
       return
  -> option = mapWinnerToOption(marketId, winner)
  -> if option missing/conflict:
       mark CLOSED
       log NO_OUTCOME_MAPPING or AMBIGUOUS_OUTCOME
       return
  -> mark PredictMarket SETTLED with result=option
```

## 5. 推荐落地顺序

1. 先落地 Discovery、Tracking、Market ID 精确拉取。
2. 再补 Gamma 字段解析、outcome 映射表、Tracking upsert outcomes。
3. 然后生成默认 A/B 映射，并用映射填充新 context 阵营文案。
4. 最后统一 `OPEN/CLOSED/SETTLED` 状态，实现 winner 识别、winner -> option 映射、自动写 `result/status=SETTLED`、失败日志与运营待处理查询。

## 6. 不变约束

- 用户仍通过 `/api/coin/settle` 领取派奖。
- 自动结算只改变市场最终结果，不直接给用户打钱。
- 用户派奖继续保持幂等。
- 运营 `POST /api/admin/predict/market/settle` 保留最终纠错能力。
