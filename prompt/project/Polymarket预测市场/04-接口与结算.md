# Polymarket接口与结算

通用下注、运营结算、用户结算业务流已抽取到：[预测市场公共部分](../预测市场公共部分/00-目录.md)。本文只保留 Polymarket 同步入口、Polymarket 市场如何复用公共接口，以及外部 resolved 如何接入站内结果的说明。

## 1. 同步接口

### 1.1 当前手动同步

```text
POST /api/football/sync_polymarket
```

认证：

- 需要登录。

代码：

```text
FootballController.PostSync_polymarket()
  -> PolymarketSyncService.SyncMarkets(ctx)
```

说明：

- 同步范围来自 `bbs-go.yaml`。
- 接口不接收 tag 或 slug 参数。
- 当前不是管理员接口。

### 1.2 建议新增管理员同步

建议：

```text
POST /api/admin/predict/sync_polymarket
```

原因：

- Polymarket 同步属于运营能力。
- 应使用 `AdminMiddleware`。
- 方便记录 operate-log。
- 避免普通登录用户触发外部 API 同步。

## 2. 市场查询

Polymarket 市场写入后复用统一查询：

```text
GET /api/football/markets
GET /api/football/markets/by_tag
GET /api/football/markets/by_name
GET /api/football/predict_context/hot
```

返回聚合：

```text
market: PredictMarket
context: PredictContext
betSettleResult
hasBet
```

筛选建议：

- 可通过 `sourceModel=Polymarket` 筛出 Polymarket 来源市场。
- 可通过 tag `polymarket` 查询。

## 3. 下注

公共下注接口、参数、事务和资金动作见：[预测市场公共部分](../预测市场公共部分/06-接口.md#1-下注接口)。

Polymarket 差异：

- Polymarket 市场当前按二元市场处理。
- odds 使用站内池算法，不使用 Polymarket 外部赔率。
- option 仍使用站内 `A/B`，真实外部 outcome 需要通过映射表或默认规则转换。

## 4. 运营结算

公共运营人工结算接口、权限、请求参数和状态写入见：[预测市场公共部分](../预测市场公共部分/06-接口.md#3-运营人工结算接口)。

### 4.1 Polymarket 当前结算方式

当前 Polymarket resolved 同步不会自动写 `result`。

因此 Polymarket 市场的真实闭环是：

```text
Gamma 同步
  -> 写 PredictMarket.resolved/resolvedOutcomeName
  -> status=CLOSE
运营查看 resolvedOutcomeName
  -> 手动调用 admin settle
  -> 写 result=A/B
用户调用 /api/coin/settle
  -> 派奖
```

## 5. 用户结算

公共用户结算接口、派奖算法、幂等和资金动作见：[预测市场公共部分](../预测市场公共部分/06-接口.md#2-用户结算接口)。

Polymarket 差异：

- 用户结算不直接读取 Gamma `resolvedOutcomeName`。
- 自动结算或运营结算必须先把外部赢家映射成站内 `PredictMarket.result=A/B`。
- 自动结算只写市场结果，不直接派奖。

## 6. 当前完整闭环

当前已实现闭环：

```text
Polymarket Gamma
  -> SyncMarkets
  -> PredictMarket + PredictContext
  -> 用户列表查看
  -> 用户下注
  -> 运营人工结算
  -> 用户结算领取
```

当前未实现闭环：

```text
Polymarket Gamma resolved
  -> 自动识别 winner
  -> 自动映射 A/B
  -> 自动 SETTLED
  -> 用户直接领取
```
