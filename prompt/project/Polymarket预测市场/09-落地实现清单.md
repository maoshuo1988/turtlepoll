# Polymarket落地实现清单

> 本文件补齐真正实现前必须明确的信息。范围仍是只读同步与站内自动结算，不接 Polymarket 下单。

## 1. 实现前必须定住的口径

| 事项 | 决策 |
|------|------|
| 自动结算触发点 | 只由 Tracking 状态轮巡触发 |
| Discovery 职责 | 发现、创建站内市场、登记 externalMarketId |
| Tracking 职责 | 按已登记 ID 精确拉取、推进 CLOSED/SETTLED/OPS_PENDING |
| 外部结果主来源 | P0 使用 Gamma market 的 `resolved/resolution/outcomes` |
| CLOB winner 字段 | P1 可作为辅助验证，不作为 P0 强依赖 |
| 站内派奖 | 仍由用户调用 `/api/coin/settle` 触发 |
| 运营纠错 | 仍保留 `POST /api/admin/predict/market/settle` |
| 取消/无效 | 不自动派奖，进入运营处理或退款流程 |

## 2. 外部接口契约

### 2.1 Discovery 拉取

目标：

- 按配置 tag/slug/marketIds 发现市场。
- 每次发现到市场后必须持久化 externalMarketId。

接口：

```text
GET /tags
GET /markets
GET /markets?tag_id=...
GET /markets/{id}
GET /markets/slug/{slug}
```

分页口径：

- 优先兼容官方 keyset 分页：`next_cursor -> after_cursor`。
- 当前 offset 分页可先保留，但不能作为长期唯一方案。
- 如果外部接口拒绝 offset，Discovery 必须自动切到 keyset。

### 2.2 Tracking 精确拉取

目标：

- 已登记的 market ID 必须继续被拉取。
- 不依赖 tag 列表分页顺序。

接口：

```text
GET /markets/{id}
```

错误处理：

| 场景 | 处理 |
|------|------|
| 200 | 更新 market/outcomes/tracking |
| 404 | failCount+1，超过阈值进入 OPS_PENDING |
| 429 | 记录限流，延后 retryAfter |
| 5xx | failCount+1，指数退避 |
| timeout | failCount+1，保留 TRACKING |

## 3. Migration 清单

### 3.1 Tracking 表

```text
t_predict_market_tracking
```

| 字段 | 说明 |
|------|------|
| `id` | 主键 |
| `market_id` | 站内 PredictMarket.Id |
| `external_market_id` | Polymarket market id 原值 |
| `external_slug` | Polymarket slug |
| `source` | tag/slug/manual |
| `tracking_status` | DISCOVERED/TRACKING/SETTLED/OPS_PENDING/CANCELLED |
| `last_sync_at` | 最近拉取时间 |
| `next_retry_at` | 下次允许重试时间 |
| `fail_count` | 连续失败次数 |
| `last_error` | 最近错误摘要 |
| `created_at/updated_at` | 时间 |

索引：

```text
unique(external_market_id)
index(market_id)
index(tracking_status, next_retry_at)
```

### 3.2 Outcome 映射表

```text
t_predict_market_outcome
```

| 字段 | 说明 |
|------|------|
| `market_id` | 站内 PredictMarket.Id |
| `external_outcome_id` | Gamma outcome id/name |
| `external_outcome_name` | Gamma outcome name |
| `external_token_id` | CLOB token id，可空 |
| `option` | A/B |
| `display_name` | 展示文案 |
| `sort` | outcome 顺序 |
| `locked` | 运营是否锁定 |
| `created_at/updated_at` | 时间 |

索引：

```text
unique(market_id, external_outcome_id)
unique(market_id, option)
```

### 3.3 自动结算失败日志

```text
t_predict_market_settle_issue
```

| 字段 | 说明 |
|------|------|
| `market_id` | 站内 PredictMarket.Id |
| `external_market_id` | 外部 market id |
| `reason` | NO_WINNER/NO_OUTCOME_MAPPING/AMBIGUOUS_OUTCOME/CANCELLED_OR_INVALID |
| `raw_resolution` | 外部 resolution 原文 |
| `raw_payload` | 必要的排障 JSON 摘要 |
| `status` | OPEN/RESOLVED/IGNORED |
| `created_at/updated_at` | 时间 |

唯一口径：

- 同一 market 同一 reason 保留一条未解决记录。
- 运营处理后改为 `RESOLVED` 或 `IGNORED`。

## 4. 配置项清单

```yaml
polymarket:
  enabled: true
  baseURL: "https://gamma-api.polymarket.com"
  tags: []
  marketSlugs: []
  marketIds: []
  discoveryCron: "0 */30 * * * *"
  trackingCron: "0 */5 * * * *"
  discoveryPageSize: 50
  trackingBatchSize: 50
  maxRetry: 5
  retryBaseSeconds: 60
  autoSettleEnabled: true
  dryRun: false
```

配置规则：

- `marketIds` 用于强制登记指定 ID。
- `dryRun=true` 时只写日志和 issue，不写 `SETTLED/result`。
- `autoSettleEnabled=false` 时 Tracking 只同步状态，不自动结算。

## 5. 管理端接口清单

| 接口 | 用途 |
|------|------|
| `POST /api/admin/polymarket/discovery/sync` | 手动触发 Discovery |
| `POST /api/admin/polymarket/tracking/sync` | 手动触发 Tracking |
| `GET /api/admin/polymarket/issues` | 查询待运营处理 |
| `POST /api/admin/polymarket/outcome/update` | 修改 A/B outcome 映射 |
| `POST /api/admin/polymarket/tracking/retry` | 将 OPS_PENDING 重置为 TRACKING |
| `POST /api/admin/polymarket/issue/ignore` | 忽略不需要处理的问题 |
| `POST /api/admin/predict/market/settle` | 已有人工结算接口，继续复用 |

权限：

- 以上新增接口全部放在 admin 路由。
- 操作 outcome、ignore、retry 必须记录 operate log。

## 6. 状态兼容与迁移

当前代码存在：

```text
CLOSE
```

目标口径：

```text
OPEN
CLOSED
SETTLED
```

迁移策略：

1. 查询和结算入口短期兼容 `CLOSE/CLOSED`。
2. 新同步统一写 `CLOSED`，不再写 `CLOSE`。
3. migration 执行一次历史修正：`status='CLOSE' -> 'CLOSED'`。
4. 自动结算只允许从 `CLOSED` 进入 `SETTLED`。

## 7. 赢家识别口径

优先级：

1. `resolution` 精确匹配 outcome id。
2. `resolution` 精确匹配 outcome name。
3. outcome winner 标记明确且唯一。
4. 以上都失败则进入 `NO_WINNER`。

禁止：

- 禁止标题模糊匹配。
- 禁止用价格单独判断赢家。
- 禁止在多个 outcome 同名时自动结算。

## 8. 取消和无效市场

识别：

```text
resolution = CANCELLED
resolution = INVALID
外部状态表示取消或无效
```

处理：

- 不写 `result=A/B`。
- 不自动派奖。
- 写 settle issue：`CANCELLED_OR_INVALID`。
- Tracking 进入 `OPS_PENDING` 或 `CANCELLED`。

待确认：

- 是否新增 `PredictMarket.status=CANCELLED`。
- 是否新增退款结果 `REFUND`。
- 退款是否仍通过 `/api/coin/settle`，还是新增运营退款接口。

## 9. 最小 P0 实现顺序

1. 新增 migration：tracking/outcome/issue。
2. GammaClient 增加 `GetMarketByID`。
3. 配置增加 `marketIds/discoveryCron/trackingCron/trackingBatchSize`。
4. Discovery 写 tracking 表。
5. Tracking 按 ID 精确拉取。
6. Outcome 默认映射与运营锁定。
7. Winner 识别与 A/B 映射。
8. 自动写 `PredictMarket.status=SETTLED,result=A/B`。
9. 管理端 issue 查询、outcome 修改、retry。

## 10. 验收清单

- 已登记 ID 后续不依赖 tag 分页也会被 Tracking 拉取。
- offset 被外部拒绝时 Discovery 能使用 keyset 分页。
- resolved 且映射唯一的市场自动进入 `SETTLED`。
- resolved 但无法映射的市场进入 issue。
- 运营补映射后可重试并自动结算。
- 自动结算不直接改用户余额。
- `CLOSE` 历史状态被兼容或迁移为 `CLOSED`。
- 取消/无效市场不会按 A/B 派奖。
