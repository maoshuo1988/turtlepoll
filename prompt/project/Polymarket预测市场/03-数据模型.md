# Polymarket预测市场数据模型

## 1. 核心表

通用模型详见：[预测市场公共部分](../预测市场公共部分/05-配置与数据模型.md)。本文只说明 Polymarket 来源如何写入这些公共模型，以及 Polymarket 特有的 Tracking、Outcome 映射和外部 resolved 字段。

当前 Polymarket 没有独立表，复用预测市场通用模型：

| 表 | 模型 | 作用 |
|----|------|------|
| `t_predict_market` | `PredictMarket` | 市场主记录、状态、结果、下注池 |
| `t_predict_context` | `PredictContext` | 展示文案、图片、标签、热度 |
| `t_predict_bet` | `PredictBet` | 用户下注单 |
| `t_user_coin` | `UserCoin` | 用户金币账户 |
| `t_user_coin_log` | `UserCoinLog` | 金币流水 |
| `t_predict_tag` | `PredictTag` | 标签物化 |
| `t_predict_tag_stat` | `PredictTagStat` | 标签统计 |

## 2. PredictMarket

代码：

```text
internal/models/models/predict_models.go
```

Polymarket 写入字段：

| 字段 | 当前写法 |
|------|----------|
| `sourceModel` | `Polymarket` |
| `sourceModelId` | Gamma market id 转 int64 |
| `marketType` | 当前写 `AB` |
| `title` | `question`，为空则 `title` |
| `status` | `OPEN` 或 `CLOSE` |
| `closeTime` | `closeDate`，为空则 `endDate` |
| `resolved` | Gamma `resolved` 或 resolution 推断 |
| `resolvedOutcomeId` | resolution 或取消标记 |
| `resolvedOutcomeName` | resolution 或取消标记 |
| `resolvedAt` | Gamma `resolvedAt` 或首次检测时间 |

### 2.1 当前状态问题

当前 `marketType` 写的是：

```text
AB
```

但下注与结算服务使用：

```text
binary
1x2
```

`NormalizePredictMarketType` 会把非 `1x2` 当成 `binary`，所以当前下注逻辑可运行，但文档与数据口径建议统一为 `binary`。

当前封盘状态写的是：

```text
CLOSE
```

而 admin settle 接口兼容：

```text
CLOSED
CLOSE
```

用户结算只接受：

```text
SETTLED
```

### 2.2 外部 ID 风险

当前表结构：

```text
source_model_id int64
```

Gamma ID 如果是非数字字符串，会走弱兜底：

```text
sourceModelId = now
```

建议后续使用：

```text
externalKey = Gamma market id string
unique(source_model, external_key)
```

## 3. PredictContext

Polymarket 写入字段：

| 字段 | 当前写法 |
|------|----------|
| `marketId` | `PredictMarket.Id` |
| `eventName` | Event title，空则 market title |
| `tags` | `polymarket` + 配置 tag + Gamma market tags |
| `createTime/updateTime` | 当前时间 |

当前不会写入：

- `imageUrl`
- `listImage`
- `sideABgImage`
- `sideBBgImage`
- `sideABgColor`
- `sideBBgColor`
- `participantCount`
- `proText`
- `conText`
- `heat`
- `detail`

影响：

- 运营图片、背景色、详情、热度不会被 Polymarket 同步覆盖。
- 但 `eventName/tags` 会被同步刷新。

### 3.1 建议上下文映射

当 outcomes 可稳定识别后，建议写入：

| 字段 | 建议 |
|------|------|
| `proText` | outcome A 展示文案 |
| `conText` | outcome B 展示文案 |
| `detail` | 保持运营编辑，不由同步覆盖 |
| `imageUrl/listImage` | 保持运营编辑，不由同步覆盖 |
| `tags` | 同步可刷新，但建议保留运营追加标签能力 |

## 4. PredictBet

Polymarket 市场下注复用站内 `PredictBet`。

下注字段：

| 字段 | 说明 |
|------|------|
| `userId` | 用户 ID |
| `marketId` | 站内 PredictMarket ID |
| `option` | A/B，三元市场可 DRAW |
| `amount` | 金币数量 |
| `odds` | 下单时锁定赔率 |
| `effA/effB/effDraw` | 下单时有效池快照 |
| `status` | OPEN/SETTLED/CANCELED |
| `settleResult` | WIN/LOSE |
| `payout` | 派奖金额 |

注意：

- 当前不使用 Polymarket 外部价格。
- 当前 odds 来自站内池算法。
- 用户结算不读取 `resolvedOutcomeName`，只读取 `PredictMarket.result`。

## 5. 标签物化

Polymarket 同步写：

```text
PredictContext.tags
```

标签物化由：

```text
PredictTagService.RefreshTagsFromContexts()
```

写入：

- `PredictTag`
- `PredictTagStat`

刷新入口：

- 定时任务每 30 分钟。
- `POST /api/predict-tag/refresh`

一致性：

- Polymarket 同步和标签刷新不是同一事务。
- 标签列表允许最终一致。
