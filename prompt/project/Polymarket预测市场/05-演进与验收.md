# Polymarket演进与验收

## 1. 当前风险

### 1.1 状态值不统一

Polymarket 同步当前写：

```text
CLOSE
```

站内更清晰的状态应是：

```text
OPEN
CLOSED
SETTLED
```

风险：

- 列表、运营接口、用户结算对状态的理解不一致。
- 管理端结算虽然兼容 `CLOSE`，但后续功能容易漏判断。

### 1.2 outcome 映射缺失

当前没有保存：

```text
外部 outcome -> 站内 option A/B
```

风险：

- 自动结算无法安全判断谁赢。
- Yes/No 市场、候选人市场、体育市场的文案与 A/B 映射可能反转。
- 只靠 `resolution` 文本不能保证可靠。

### 1.3 非数字外部 ID 幂等弱

当前 `sourceModelId` 是 int64。

如果 Gamma market ID 是非数字字符串，当前会用 `now` 兜底。

风险：

- 重复同步可能生成重复市场。
- 无法稳定追踪外部市场。

### 1.4 同步入口权限偏弱

当前手动同步入口：

```text
POST /api/football/sync_polymarket
```

风险：

- 属于运营动作，但挂在用户侧。
- 不写 operate-log。
- 不方便审计谁触发了同步。

### 1.5 取消市场未闭环

当前能初步识别：

```text
CANCELLED
INVALID
```

但没有：

- 自动退款。
- 标记订单取消。
- 运营处理队列。

## 2. 推荐演进

### 2.1 P0：管理员同步接口

新增：

```text
POST /api/admin/predict/sync_polymarket
```

要求：

- 使用 `AdminMiddleware`。
- 复用 `PolymarketSyncService.SyncMarkets`。
- 写 operate-log。
- 文档写入 `docs/api/admin_predict.md`。

### 2.2 P0：状态统一

建议：

```text
open and before closeTime -> OPEN
closed but unresolved -> CLOSED
resolved but未映射result -> CLOSED + resolved=true
resolved and已映射result -> SETTLED
```

兼容：

- 短期保留 admin settle 对 `CLOSE` 的兼容。
- 新数据写 `CLOSED`。

### 2.3 P0：outcome 映射表

建议新增表：

```text
t_predict_market_outcome
```

字段：

| 字段 | 说明 |
|------|------|
| `marketId` | 站内市场 ID |
| `externalOutcomeId` | Polymarket outcome ID |
| `externalOutcomeName` | Polymarket outcome 名称 |
| `option` | A/B/DRAW |
| `displayName` | 站内展示名 |
| `sort` | 排序 |
| `createTime/updateTime` | 时间 |

唯一键：

```text
unique(market_id, external_outcome_id)
unique(market_id, option)
```

### 2.4 P1：自动结算

流程：

```text
TrackingPoller
  -> GET /markets/{externalMarketId}
  -> extractResolution
  -> 根据 outcome 映射表找 option
  -> 写 PredictMarket.result
  -> status=SETTLED
  -> resolved=true
```

保护：

- 如果无法映射 outcome，记录错误日志并保持 `CLOSED`。
- 不自动猜测 A/B。
- 支持运营手动补映射后重跑同步。

详细拆分见：[06-自动结算设计](./06-自动结算设计.md)。

双轮巡跟踪见：[08-双轮巡跟踪设计](./08-双轮巡跟踪设计.md)。

### 2.5 P1：取消与退款

建议：

```text
CANCELLED/INVALID
  -> market.status=CANCELED 或 CLOSED + result=REFUND
  -> bet.status=CANCELED
  -> refund amount
  -> UserCoinLog: REFUND
```

当前模型没有 `REFUND` result，需要先明确口径。

### 2.6 P1：同步批次日志

建议新增：

```text
t_predict_sync_log
```

记录：

- source
- triggerType: cron/manual
- operatorId
- config snapshot
- seen/upsert/success/failed
- error message
- startedAt/finishedAt

## 3. 验收清单

### 3.1 当前已实现验收

- [x] `polymarket.enabled=false` 时定时任务不跑。
- [x] 能从 Gamma 拉取 tags。
- [x] 能按 tag_id 分页拉取 markets。
- [x] 能写入 `PredictMarket.sourceModel=Polymarket`。
- [x] 能按 `(sourceModel, sourceModelId)` 幂等更新。
- [x] 能写入 `PredictContext.eventName/tags`。
- [x] 能通过统一市场列表查询到同步结果。
- [x] 能使用站内下注接口下注。
- [x] 能通过管理员接口人工结算。
- [x] 能通过用户结算接口领取派奖。

### 3.2 待补验收

- [ ] 新增 `/api/admin/predict/sync_polymarket`。
- [ ] 新增 Discovery 发现轮巡。
- [ ] 新增 Tracking 状态轮巡。
- [ ] Tracking 按本地 externalMarketId 精确拉取。
- [ ] Polymarket 新同步数据使用 `CLOSED`，不再写 `CLOSE`。
- [ ] 建立 outcome 映射表。
- [ ] 同步时保存外部 outcomes。
- [ ] 管理端可编辑 outcome 与 A/B 对应。
- [ ] resolved outcome 可自动映射成 `PredictMarket.result`。
- [ ] 自动结算只在映射明确时执行。
- [ ] 映射失败时记录错误日志，并进入运营处理队列。
- [ ] 自动结算不直接派奖，用户仍通过 `/api/coin/settle` 幂等领取。
- [ ] 已 `SETTLED` 且 result 非空的市场不会被同步覆盖。
- [ ] cancelled/invalid 有退款或人工处理闭环。
- [ ] 非数字 external id 也能强幂等。
- [ ] 同步批次有审计日志。

### 3.3 回归测试建议

单元测试：

- `Outcomes.UnmarshalJSON` 支持数组。
- `Outcomes.UnmarshalJSON` 支持字符串 JSON。
- `extractResolution` 支持 cancelled/invalid。
- `parseGammaTimeToUnix` 支持 RFC3339/RFC3339Nano。

集成测试：

- mock Gamma tags + markets，同步后只生成一条 market。
- 重复同步不重复生成 market。
- 同步更新 eventName/tags。
- 手动 settle 后用户可 settle。
- 无法映射 outcome 时不自动 SETTLED。
