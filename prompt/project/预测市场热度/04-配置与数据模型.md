# 预测市场热度配置与数据模型

## 1. 配置

P0 不新增配置。

热度公式固定：

```text
heatDelta = amount
commentHeatDelta = 1
```

不提供以下配置：

- 金额换算比例
- 单笔上限
- 每日上限
- 用户维度上限
- 评论热度倍率

## 2. 数据模型

P0 复用现有字段：

```text
t_predict_context.heat
```

对应模型：

```go
type PredictContext struct {
    MarketId int64
    Heat     int64
}
```

不新增字段。

## 3. 数据来源

热度来源包括但不限于：

- 用户下注
- 预测市场一级评论
- 运营手动调整

P0 不区分来源，统一累加到 `PredictContext.heat`。

## 4. 下注热度计算

输入：

- `amount int64`

输出：

- `heatDelta int64`

规则：

```text
if amount <= 0:
    heatDelta = 0
else:
    heatDelta = amount
```

下注服务已经校验 `amount > 0`，因此正常成功下注场景下：

```text
heatDelta = amount
```

## 5. 评论热度计算

输入：

- `entityType`
- `entityId`
- `commentLevel`

输出：

- `commentHeatDelta int64`

规则：

```text
entityType == topic
commentLevel == 一级评论
存在 market_id = entityId 的 PredictContext
    -> commentHeatDelta = 1
否则
    -> commentHeatDelta = 0
```

当前代码落点：

- `CommentService.Create`
- `constants.EntityTopic`
- `PredictContextService.IncrHeatByMarketId(tx, form.EntityId, 1)`

说明：

- 当前没有独立 `commentLevel` 字段参与判断，一级评论来自 `entityType=topic`。
- 二级评论来自 `entityType=comment`，不增加预测市场热度。
- `PredictContext` 不存在时，`IncrHeatByMarketId` 原子更新影响 0 行，不报错。

## 6. 下注事务位置

推荐放在 `PredictBetService.PlaceBet` 事务内，顺序：

1. 锁定 `PredictMarket`。
2. 校验市场状态和截止时间。
3. 计算并锁定赔率。
4. 创建 `PredictBet`。
5. 扣减用户金币。
6. 更新市场下注池。
7. 增加 `PredictContext.heat`。
8. 提交事务。

## 7. 评论事务位置

已有评论流程：

1. 创建 `Comment`。
2. 如果是 `entityType=topic`，更新 Topic 评论计数。
3. 尝试增加对应 `PredictContext.heat`。
4. 提交事务。

失败策略：

- 评论创建失败时，热度不增加。
- Topic 评论计数更新失败时，事务回滚，热度不增加。
- 预测市场热度增加失败时，当前设计建议回滚评论事务；如果只是没有对应 `PredictContext`，则跳过不报错。

## 8. 并发控制

`PredictMarket` 已经使用行锁保护下注池。

下注和评论都应通过同一个 `PredictContextService.IncrHeatByMarketId` 增加热度。该方法使用原子增量 SQL：

```sql
UPDATE t_predict_context
SET heat = heat + ?, update_time = ?
WHERE market_id = ?
```

这样即使多个事务排队执行，也不会丢失热度增量。

## 9. 世界杯与 Polymarket

世界杯：

- `sourceModel=MatchSchedule`
- 同步创建 `PredictMarket/PredictContext`
- 下注成功后增加同一个 `PredictContext.heat`
- 一级评论成功后增加同一个 `PredictContext.heat`

Polymarket：

- `sourceModel=Polymarket`
- Gamma 同步创建 `PredictMarket/PredictContext`
- 下注成功后增加同一个 `PredictContext.heat`
- 一级评论成功后增加同一个 `PredictContext.heat`

同步任务约束：

- 不覆盖 `PredictContext.heat`
- 不重算下注热度
- 不因外部 resolved 状态清空热度
