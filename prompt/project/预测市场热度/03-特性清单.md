## 2. F1 下注成功增加市场热度

触发点：

- `PredictBetService.PlaceBet`

规则：

- 下注成功后增加 `PredictContext.heat`。
- 增量等于本次下注金额：`heatDelta = amount`。
- 只要下注单真实创建并扣款成功，就增加热度。
- 世界杯、Polymarket 使用同一逻辑。

验收：

- 世界杯市场下注 100，热度 +100。
- Polymarket 市场下注 500，热度 +500。
- 市场关闭导致下注失败时，热度不变。
- 余额不足导致下注失败时，热度不变。

## 3. F2 热度增量纯函数

建议新增：

```go
func PredictBetHeatDelta(amount int64) int64
```

行为：

```text
amount <= 0 -> 0
amount > 0  -> amount
```

验收：

- `amount=0` 返回 0。
- `amount=1` 返回 1。
- `amount=100` 返回 100。
- `amount=10000` 返回 10000。

## 4. F3 事务一致性

要求：

- 创建 `PredictBet`
- 扣减 `UserCoin`
- 更新 `PredictMarket.poolA/poolB/poolDraw`
- 增加 `PredictContext.heat`

以上必须在同一个数据库事务里提交。

失败策略：

- 热度更新失败时，整笔下注失败并回滚。
- 扣款失败时，不创建有效下注热度。
- 市场池更新失败时，热度不提交。

## 5. F4 并发原子更新

热度更新必须使用原子增量：

```sql
UPDATE t_predict_context
SET heat = heat + ?, update_time = ?
WHERE market_id = ?
```

不要使用“查出 heat -> 加值 -> Save”的方式，避免并发下注丢失更新。

验收：

- 并发 10 笔下注，每笔 100，最终热度增加 1000。

## 6. F5 预测市场一级评论增加热度

触发点：

- `CommentService.Create`

已有代码口径：

- 当 `form.EntityType == constants.EntityTopic` 时创建一级评论。
- 如果 `form.EntityId` 对应某个 `PredictContext.marketId`，则调用 `PredictContextService.IncrHeatByMarketId(tx, form.EntityId, 1)`。
- 当前业务约定是 `topicId` 与 `PredictMarket.id` 相同时，评论 topic 同时提升预测市场热度。

规则：

- 成功创建一级评论后，`PredictContext.heat +1`。
- 评论创建失败时，热度不增加。
- 二级评论当前不增加预测市场热度。
- 如果找不到对应 `PredictContext`，跳过不报错，避免影响评论主流程。

验收：

- 对预测市场对应 topic 发一级评论，热度 +1。
- 对普通 topic 发评论，如果没有对应 `PredictContext`，评论成功但预测市场热度不变。
- 回复评论时，预测市场热度不变。

## 8. F7 运营手动热度兼容

P0 规则：

- 运营手动修改的是最终 `heat`。
- 后续下注和评论在运营修改后的值上继续累加。
- 不区分下注热度、评论热度和人工热度来源。

P2 如需审计，再拆来源字段。

## 9. F8 热度重算

P1 预留能力。

重算下注热度：

```text
betHeat = sum(amount)
where market_id = ?
  and status in ('OPEN', 'SETTLED')
```

限制：

- 当前若评论热度、运营热度、下注热度都混在 `heat`，重算只能得到可计算来源的贡献，不能无损恢复总热度。
- 评论重算需要从 `t_comment` 按 `entity_type=topic` 和 `entity_id=marketId` 统计一级评论数量。
