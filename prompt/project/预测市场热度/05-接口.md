# 预测市场热度接口

## 1. 用户下注接口

接口：

```text
POST /api/coin/bet
```

请求参数保持不变：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `marketId` | int64 | 是 | 预测市场 ID |
| `option` | string | 是 | `A/B/DRAW` |
| `amount` | int64 | 是 | 下注金额 |

新增业务效果：

```text
PredictContext.heat += amount
```

返回结构 P0 不变：

- `bet`
- `market`
- `userCoin`
- `lockedOdds`

P0 不新增 `heatDelta` 返回字段，避免接口兼容风险。

## 2. 评论接口

接口：

```text
POST /api/comment
```

新增业务效果：

```text
当 entityType = topic 且 entityId 对应 PredictContext.marketId:
PredictContext.heat += 1
```

说明：

- 该能力当前已有基础实现。
- 一级评论增加预测市场热度。
- 二级评论不增加预测市场热度。
- 如果没有对应 `PredictContext`，评论主流程不受影响。

## 3. 市场列表接口

接口：

```text
GET /api/football/markets
```

要求：

- 返回的 `context.heat` 是下注后的最新热度。
- 返回的 `context.heat` 也包含预测市场一级评论贡献。
- 世界杯和 Polymarket 市场都使用相同字段。

## 4. 按标签查询接口

接口：

```text
GET /api/football/markets/by_tag
```

要求：

- 返回的 `context.heat` 是下注后的最新热度。
- 标签页排序如使用热度，应自然受到下注金额和评论活跃影响。

## 5. 热榜接口

接口：

```text
GET /api/football/predict_context/hot
```

要求：

- 按 `PredictContext.heat` 排序。
- 用户下注金额越高，对热榜影响越大。
- 预测市场一级评论越多，对热榜也有正向影响。

## 6. 管理端重算接口预留

P1 可新增：

```text
POST /api/admin/predict/market/heat/recalc
```

请求：

```json
{
  "marketId": 123,
  "mode": "bet_only"
}
```

说明：

- `bet_only` 表示只按有效下注金额重算下注贡献。
- 后续可增加 `calculable_sources`，同时重算下注贡献和一级评论贡献。
- P0 不实现。
