# 预测市场热度总览与边界

## 1. 背景

预测市场当前已经有 `PredictContext.heat` 字段，并且市场列表、热榜、标签市场等展示链路可读取该字段。

新需求是：用户下注时，下注金额要直接增加预测市场热度。已有能力是：用户对预测市场对应 topic 发一级评论时，预测市场热度会增加 1。两类热度都应该覆盖全部预测市场，包括：

- 世界杯市场：`sourceModel=MatchSchedule`
- Polymarket 市场：`sourceModel=Polymarket`
- 后续站内创建的预测市场

## 2. 目标

- 下注成功后，按下注额度增加市场热度。
- 评论预测市场成功后，按评论次数增加市场热度。
- 让热榜能反映真实资金参与强度。
- 让热榜保留真实讨论活跃度。
- 保持世界杯与 Polymarket 统一口径。
- 保持实现落点集中在通用下注服务和通用评论服务，不在各市场来源同步逻辑里分叉。

## 3. 热度公式

### 3.1 下注热度

```text
heatDelta = amount
```

说明：

- `amount` 是用户本次下注金币数量。
- 下注 1 金币，热度 +1。
- 下注 100 金币，热度 +100。
- 下注 10000 金币，热度 +10000。
- 不做取整换算，因为 `amount` 本身就是整数。
- 不设置上限。

### 3.2 评论热度

```text
commentHeatDelta = 1
```

说明：

- 用户成功创建一条预测市场一级评论，热度 +1。
- 当前代码约定：当 `entityType=topic` 且 `topicId` 与 `PredictMarket.id` 相同，评论 topic 时同步提升预测市场热度。
- 二级评论当前不增加预测市场热度。
- 评论失败或事务回滚时，热度不增加。

## 4. 范围

### 覆盖

- `POST /api/coin/bet` 成功下注。
- `POST /api/comment` 成功创建预测市场一级评论。
- 二元市场 `A/B`。
- 三元市场 `A/B/DRAW`。
- 世界杯同步创建的市场。
- Polymarket 同步创建的市场。
- 查询接口读取并展示最新 `PredictContext.heat`。

### 不覆盖

- 下注失败后的热度变化。
- 评论失败后的热度变化。
- 二级评论对预测市场热度的影响。
- 退款或作废后是否回退热度。
- 多来源热度拆分字段，例如 `heatBet/heatComment/heatManual`。

这些能力可以后续作为 P1/P2 单独设计。

## 5. 不变约束

- 下注单创建、扣款、市场池更新、下注热度增加必须在同一事务中完成。
- 评论创建、帖子评论计数更新、评论热度增加必须在同一事务中完成。
- 任一环节失败，对应事务回滚，热度也回滚。
- 同步任务不得覆盖运营字段和热度字段。
- 查询侧仍统一读取 `PredictContext.heat`。
