# 对立PK：外部特性依赖详情

## F01 用户金币账户与流水

### 接口定义

- 接口名：SpendToPool / PayFromPoolToUser / BurnFromPool
- 调用方向：PKService -> UserCoinService
- 调用方式：进程内服务调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | int64 | 是 | 用户ID |
| amount | int64 | 是 | 金额，单位龟币 |
| bizType | string | 是 | 业务类型（PK_BET_STAKE_IN/PK_PAYOUT/PK_DRAW_REFUND） |
| bizId | int64 | 是 | 业务主键（betId或roundId） |
| subBizId | int64 | 否 | 用户级幂等子键；派奖时固定为 userId |

兼容规则：

- 未传 subBizId 时，保持原有幂等语义，仍按 bizType + bizId 去重。
- 对立PK新增派奖链路必须传 subBizId=userId，确保同一 roundId 可对多个用户分别入账。

### 输出参数

| 字段 | 类型 | 说明 |
|------|------|------|
| ok | bool | 是否成功 |
| balanceAfter | int64 | 账户变更后余额 |
| coinLogId | int64 | 流水ID |

### 错误码

| 错误码 | 触发条件 |
|--------|----------|
| COIN_507_INSUFFICIENT | 余额不足 |
| COIN_409_DUP_BIZ | 相同bizType+bizId+subBizId重复入账 |
| COIN_500_INTERNAL | 账户写入异常 |

### 固定策略

- 超时：300ms。
- 重试：最多 2 次，间隔 50ms，仅对网络抖动或连接中断重试。
- 熔断：30 秒窗口内错误率 >= 40% 且请求数 >= 50 时打开，打开后 60 秒半开探测。
- 并发：单实例最大 200 并发调用。
- 限速：每实例每秒 500 次。

### 验收标准

- 下注幂等重试不出现重复扣款。
- 结算重试不出现重复派奖。

## F02 通用评论发布与回复

### 接口定义

- 接口名：PublishComment / PublishReply
- 调用方向：PKCommentService -> CommentService
- 调用方式：进程内服务调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | int64 | 是 | 用户ID |
| entityType | string | 是 | pk_topic 或 comment |
| entityId | int64 | 是 | 话题ID或父评论ID |
| content | string | 是 | 评论内容 |
| imageList | []string | 否 | 图片URL列表 |
| quoteId | int64 | 否 | 引用评论ID |

### 输出参数

| 字段 | 类型 | 说明 |
|------|------|------|
| commentId | int64 | 评论ID |
| createTime | int64 | 创建时间戳 |

### 错误码

| 错误码 | 触发条件 |
|--------|----------|
| COMMENT_422_INVALID_CONTENT | 内容为空或超长 |
| COMMENT_403_FORBIDDEN | 用户无评论权限 |
| COMMENT_500_INTERNAL | 评论写入失败 |

### 固定策略

- 超时：400ms。
- 重试：0 次，评论发布不自动重试，防止重复内容。
- 熔断：60 秒窗口内错误率 >= 30% 且请求数 >= 30 时打开，保持 30 秒。
- 并发：单实例最大 150 并发调用。
- 限速：用户维度 30 次/分钟，IP 维度 120 次/分钟。

### 验收标准

- cooldown 阶段评论请求被拒绝。
- 回复必须继承父评论阵营。

- 调用方向：PKHeatService -> UserLikeService
- 调用方式：进程内服务调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |

|------|------|------|

### 错误码

| 错误码 | 触发条件 |
|--------|----------|

- 并发：单实例最大 300 并发调用。
- 限速：用户维度 120 次/分钟。

### 验收标准

- 点赞事件可在 1 秒内反映到热度计算。

- 接口名：CheckComment
- 调用方向：PKCommentService -> SpamService
- 调用方式：进程内服务调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | int64 | 是 | 用户ID |
| content | string | 是 | 文本内容 |
| ip | string | 是 | 用户IP |
| userAgent | string | 是 | 设备标识 |

### 输出参数

| 字段 | 类型 | 说明 |
|------|------|------|
| pass | bool | 是否通过 |
| reason | string | 拒绝原因 |
| riskScore | float64 | 风险分 |

### 错误码

| 错误码 | 触发条件 |
|--------|----------|
| SPAM_403_BLOCKED | 命中黑词或频率规则 |
| SPAM_429_RATE_LIMIT | 触发频率限制 |
| SPAM_500_INTERNAL | 校验服务异常 |

### 固定策略

- 超时：150ms。
- 重试：0 次，避免重复放行。
- 熔断：60 秒窗口内错误率 >= 50% 且请求数 >= 20 时打开，保持 30 秒。
- 并发：单实例最大 400 并发调用。
- 限速：用户维度 20 次/分钟，IP 维度 60 次/分钟。

### 验收标准

- 命中黑词内容必须 100% 拒绝。
- 频率超限请求必须返回 429。

## F05 定时任务调度

### 接口定义

- 接口名：RegisterCron / ExecuteTick
- 调用方向：PKService -> Scheduler
- 调用方式：进程内框架调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| jobName | string | 是 | 任务名：pk_round_tick |
| cronExpr | string | 是 | 表达式：*/1 * * * * |
| lockKey | string | 是 | 分布式锁键 |

### 输出参数

| 字段 | 类型 | 说明 |
|------|------|------|
| runId | string | 本次执行ID |
| success | bool | 是否成功 |
| durationMs | int64 | 执行耗时 |

### 错误码

| 错误码 | 触发条件 |
|--------|----------|
| SCHED_409_LOCKED | 分布式锁被占用 |
| SCHED_504_TIMEOUT | 单次执行超时 |
| SCHED_500_INTERNAL | 调度执行异常 |

### 固定策略

- 超时：单次执行 5s。
- 重试：失败后 1 次重试，间隔 200ms。
- 熔断：连续 5 次失败后暂停 2 分钟。
- 并发：同一 jobName 全局并发=1。
- 限速：每分钟固定 1 次。

### 验收标准

- 任一回合状态推进最多延迟 60 秒。
- 同一回合不会出现重复状态推进记录。

## F06 热度计算服务

### 接口定义

- 接口名：ComputeHeatSnapshot / GetHeatSnapshot
- 调用方向：PKSettleService/PKHeatService -> HeatComputeService
- 调用方式：进程内服务调用

### 输入参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| bizType | string | 是 | 固定为 PK |
| bizId | int64 | 是 | 对立PK事件ID |
| roundId | int64 | 是 | 回合ID |
| userId | int64 | 否 | 由上游互动写入时使用，快照查询可不传 |
| option | string | 否 | A/B（用于上游互动归属，不是快照查询必填） |
| actionType | string | 否 | 上游互动动作类型 |
| amount | decimal | 否 | BET 时的下注额 |
| requestId | string | 否 | 幂等键 |

兼容规则：

- 上游互动日志由对立PK服务写入 `t_tear_interact_log` 与 `t_tear_user_event_stat`，热度服务在快照计算时聚合这些输入。
- 未显式传 snapshotType 时，ComputeHeatSnapshot 默认生成 CHECKPOINT 快照。
- GetHeatSnapshot 传 snapshotType=SETTLE 时读取冻结快照。

### 输出参数

| 字段 | 类型 | 说明 |
|------|------|------|
| options[] | array | 热度快照列表 |
| option | string | 阵营标识，固定为 A/B |
| hLike | float64 | 阵营点赞热度 |
| hComment | float64 | 阵营评论热度 |
| hCoin | float64 | 阵营投币热度 |
| hTotal | float64 | 阵营总热度 |
| snapshotTime | int64 | 快照时间戳 |

### 错误码

| 错误码 | 触发条件 |
|--------|----------|
| HEAT_404_ROUND_NOT_FOUND | 回合不存在 |
| HEAT_409_WINDOW_CLOSED | 热度窗口已关闭，不再接收输入 |
| HEAT_409_SNAPSHOT_NOT_READY | 结算所需冻结快照尚未就绪 |
| HEAT_500_INTERNAL | 热度计算异常 |

### 固定策略

- 超时：300ms。
- 重试：最多 1 次，仅对读超时重试。
- 熔断：30 秒窗口内错误率 >= 35% 且请求数 >= 40 时打开，保持 20 秒。
- 并发：单实例最大 300 并发调用。
- 限速：回合维度每分钟 180 次。
- 当 now >= endTime 且尚无 FROZEN 快照时，SettlePKRound 或定时任务均可调用 ComputeHeatSnapshot 触发惰性冻结；同一 roundId 重复触发必须幂等。
- ComputeHeatSnapshot 未显式传 snapshotType 时，保持旧行为，默认生成最新 CHECKPOINT 快照，不推进到 FROZEN。
- GetHeatSnapshot 未显式传 snapshotType 时，保持旧行为，返回该 roundId 最新可用快照；传 snapshotType=SETTLE 时才强制读取冻结快照。

### 验收标准

- 同一输入快照结果必须幂等。
- 对立PK结算读取的 options[] 与撕裂带冻结快照完全一致。
- 同一 roundId 的重复冻结请求不会生成多份不同的 SETTLE 快照。
