### 1.0 话题列表接口定义

- 接口名：ListPKTopics
- URL：GET /api/pk/topics
- 输入参数：page(int,选填), pageSize(int,选填)
- 认证：游客可访问；登录用户返回个人态字段
- 输出参数（新增）：
  - topicId
  - title
  - currentRoundId
  - phase
  - options[]
  - countdownSeconds
  - hasBet(bool)：我在当前回合是否已投注
  - canSettle(bool)：我当前是否可触发结算
  - settleDisabledReason(string,选填)：不可结算原因

字段判定规则：

1. hasBet
   - 登录用户：存在 `PKBet(roundId=currentRoundId, userId=当前用户)` 则为 true，否则 false。
   - 游客：固定 false。

2. canSettle
   - 需满足以下条件才为 true：
     - 当前用户已登录；
     - `now >= endTime`；
     - 当前回合 `settledAt=0`（尚未完成结算）。
   - 任一条件不满足则 false。

3. settleDisabledReason
   - 当 canSettle=false 时返回，取值范围：
     - `NOT_LOGIN`
     - `ROUND_NOT_READY`
     - `ROUND_NOT_ENDED`
     - `ROUND_ALREADY_SETTLED`
   - 当 canSettle=true 时可不返回。

兼容规则：

- 旧调用方未使用新增字段时，不影响原有行为。
- 新增字段仅扩展响应，不改变原有字段语义。

### 1.1 下注意向接口定义

- 接口名：PlacePKBet
- URL：POST /api/pk/bet
- 输入参数：topicId(int64,必填), side(string,必填,A/B), requestId(string,必填), amount(int64,选填,正整数，默认100)
- 输出参数：betId, roundId, side, amount, oddsA, oddsB, heatA, heatB, balanceAfter
- 错误码：
  - PK_401_UNAUTHORIZED：未登录
  - PK_404_TOPIC_NOT_FOUND：话题不存在
  - PK_409_ROUND_NOT_BETTING：非下注期
  - PK_409_ALREADY_BET：本局已下注
  - PK_422_INVALID_SIDE：side 非法
  - PK_422_INVALID_AMOUNT：amount 非法
  - PK_507_INSUFFICIENT_COIN：余额不足

### 1.2 用户触发结算接口定义

- 接口名：SettlePKRound
- URL：POST /api/pk/settle
- 输入参数：topicId(int64,选填), roundId(int64,选填), requestId(string,选填), snapshotType(string,选填), freezeSource(string,选填)
- 输出参数：topicId, roundId, snapshotType, freezeSource, winner, settledAt, options[], settlement
- options[]子项：option, hLike, hComment, hCoin, hTotal, snapshotTime
- 当前实现约束：仅校验 `now >= endTime` 与 `settledAt`，不依赖额外可结算标记字段。

### 1.3 热度榜接口定义

- 接口名：GetPKHeatRank
- URL：GET /api/pk/heat/rank
- 输入参数：topicId(int64,选填), roundId(int64,选填), scope(string,选填, ALL/MY_SIDE), page(int,选填), pageSize(int,选填)
- 输出参数：topicId, roundId, phase, options[], leaderSide, list[], count, page, pageSize

### 1.4 我的热度数据接口定义

- 接口名：GetPKHeatMe
- URL：GET /api/pk/heat/me
- 输入参数：topicId(int64,选填), roundId(int64,选填)
- 输出参数：myOption, myHeat, myActionCount, myRank, myBetAmount, myCommentCount, receivedLikeCount, estimatedPayout, myBet

### 1.5 当前赔率接口定义

- 接口名：GetPKOddsCurrent
- URL：GET /api/pk/odds/current
- 输入参数：topicId(int64,选填), roundId(int64,选填)
- 输出参数：topicId, roundId, phase, options[], oddsA, oddsB

### 1.6 记录阵营行为接口定义

- 接口名：RecordPKOption
- URL：POST /api/pk/recordOption
- 输入参数：topicId(int64,选填), roundId(int64,选填), option(string,必填), actionType(string,必填), requestId(string,必填), entityType(string,选填), entityId(int64,选填)
- 输出参数：recorded, optionAtAction, actionType, requestId, action

### 1.7 回复评论接口定义

- 接口名：ReplyPKComment
- URL：POST /api/pk/comment/reply
- 输入参数：commentId(int64,必填), content(string,必填)
- 输出参数：comment, heat, optionAtAction
- 约束：`optionAtAction` 必须为“回复写入时用户所属阵营”，不得回填为父评论阵营。

### 1.8 评论查询阵营透出规则

- 接口名：ListPKComments / GetCommentReplies
- URL：GET /api/pk/comments 与 GET /api/comment/replies
- 输出字段：
  - `option`/`side`：评论或回复归属阵营（写入时快照）
  - `comment.optionAtAction`：通用评论结构中透出的写入时阵营
- 约束：查询返回的阵营字段必须与写入时一致，不随用户后续换边或操作变化。

### 1.9 评论回复查询接口定义

- 接口名：ListPKCommentReplies
- URL：GET /api/pk/comment/replies
- 输入参数：commentId(int64,必填), cursor(int64,选填), pageSize(int,选填)
- 输出参数：list[], cursor, hasMore
- list[]子项：comment, option, side, heatScore, downvoteCount, liked
- 约束：
  - 仅返回指定 commentId 的直接回复。
  - `option/side` 返回回复写入时阵营快照。
  - 分页排序为 id 升序，续页条件 `id > cursor`。

## 3. 路由绑定规范（Iris MVC）

当 URL 含短横线或多级路径时，必须在 BeforeActivation 显式绑定。

示例：

```go
import "github.com/kataras/iris/v12/mvc"

func (c *PkController) BeforeActivation(b mvc.BeforeActivation) {
    b.Handle("POST", "/bet", "PostBet")
  b.Handle("POST", "/settle", "PostSettle")
    b.Handle("GET", "/my/bets", "GetMyBets")
}
```

## 4. 验证要求

1. 新增接口必须按文档 URL 使用 curl 实测。
2. 对 /api/admin/** 同时验证 cookie 与 bearer token 两种认证方式。
3. 返回 HTML 首页视为路由未命中，不算通过。
