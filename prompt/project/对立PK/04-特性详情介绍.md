# 对立PK：特性详情介绍

## 1. 话题与回合领域模型

- 话题是长期实体，保存 A/B 阵营、当前回合、当前赛季引用。
- 回合是短周期实体，保存阶段时间窗、奖池、热度、胜负结果。
- 赛季是统计实体，保存 30 天窗口内的胜场与冠军结果。

实现要点：

1. 新建 PKService 作为领域门面，统一暴露读写能力。
2. 话题状态只区分 enabled/disabled，避免多状态歧义。
3. 当前回合和当前赛季在话题表冗余引用，减少列表查询成本。

## 2. 阶段推进与定时任务

阶段规则：

- betting: roundStartTime <= now < lockTime。
- locked: lockTime <= now < endTime。
- cooldown: 结算完成后 <= now < nextRoundTime。

推进规则：

1. 每分钟扫描 betting 且 now >= lockTime 的回合，更新为 locked。
2. 每分钟扫描 locked 且 now >= endTime 的回合，更新为 cooldown（进入可结算窗口）。
3. 每分钟扫描 cooldown 且 settledAt=0 的回合，执行结算并在需要时惰性冻结热度快照。
4. 每分钟扫描 cooldown 且 now >= nextRoundTime 的回合，创建下一局。
5. 每分钟检查活动赛季到期，归档并开新赛季。

## 3. 下注与结算

下注规则：

- 支持可变下注金额（正整数），未传金额时默认 100 龟币。
- 每用户每回合最多下注一次。
- 仅 betting 阶段允许下注。
- 下注请求必须携带 requestId，实现接口幂等。

结算规则：

- 结算触发方式：由任意登录用户调用结算接口触发，不再由后端轮询任务主动触发。
- 结算前置条件：now >= endTime 且 settledAt=0。
- 懒冻结规则：结算时先检查是否已有 FROZEN 快照；若没有，则先调用 ComputeHeatSnapshot 生成并冻结快照。若冻结已完成或命中幂等，则直接读取现有冻结快照。
- 快照读取规则：GetHeatSnapshot 统一返回 options[]；对立PK从中读取 option=A/B 的 hTotal，分别映射为 heatA、heatB。
- 胜方收益 = 本金 + 败方奖池 * 本人下注额 / 胜方总下注额。
- 败方收益 = 0。
- 平局触发条件：结算时 heatA = heatB，则 winner=draw。
- 平局收益 = 用户投入本金原路退回，不产生额外收益或损失。
- 平局是完全中立结果：不计入胜方或败方，不增加或中断用户连胜，不改变排名分或排名统计，不触发胜负类推送。
- 平局仅可选触发中性通知，例如"本场打平，本金已退还"。
- 回合结算唯一键：roundId。
- 用户派奖唯一键：roundId + userId。

落库规则：

1. 先校验回合已到可结算时间窗，且尚未结算。
2. 若无冻结快照，则先惰性调用 ComputeHeatSnapshot；若冻结失败，则本次结算直接失败并返回错误。
3. 读取撕裂带 options[] 热度快照，映射出 heatA、heatB 并写回合；winner=draw 时仅记录平局结果，不更新胜负、连胜、排名或推送相关统计。
4. 按 roundId + userId 写结算明细表。
5. 按 roundId + userId 执行派奖流水。

## 4. 热度计算与胜负判定

本节只定义对立PK如何消费外部热度计算服务并据此判定胜负，不定义热度公式本体。

热度来源约束：

- 对立PK不自行计算热度，不保留本地热度公式。
- 对立PK完全依赖撕裂带热度计算服务输出的 options[] 冻结快照。
- 对立PK仅消费快照并执行胜负判定与收益分配。

胜负判定：

1. heatA > heatB，则 winner=A。
2. heatB > heatA，则 winner=B。
3. heatA = heatB，则 winner=draw，并按完全中立平局处理。

## 5. 评论战场与阵营归属

评论归属策略：

- 一级评论必须绑定 topicId、roundId、side。
- 回复按“写入时用户阵营”记录归属，不继承父评论 side。
- P0 互动动作仅包含评论、回复、点赞，不包含拉踩。
- cooldown 阶段禁止新增评论和回复。

### 5.3 强弱锁边与覆盖规则

锁边定义：

- `INTERACT`：弱锁边，由评论、回复、点赞建立。
- `BET`：强锁边，由下注建立。

建立规则：

1. 首次评论、回复或点赞时，若该用户在该回合尚无锁边，则建立 `INTERACT` 弱锁边。
2. 首次下注时，若该用户在该回合尚无锁边，则建立 `BET` 强锁边。
3. 若用户已有 `INTERACT` 弱锁边且后续下注选项一致，则升级为 `BET`。
4. 若用户已有 `INTERACT` 弱锁边且后续下注选项不一致，则由 `BET` 覆盖原弱锁边并拒绝冲突请求。
5. 若用户已有 `BET` 强锁边，则后续不一致的评论、回复、点赞或下注直接拒绝。

覆盖规则：

- `BET` 优先级高于 `INTERACT`。
- 查询与写入都以强锁边为准。
- 同一用户同一回合只保留一个有效阵营归属，冲突请求不得产生新的归属记录。

数据策略：

- 通用评论写入 Comment。
- 阵营元信息写入 PKCommentMeta。
- 热度动作写入 PKAction，支持审计和结算对账。

### 5.1 回复写入时阵营快照与查询透出

规则定义：

- 回复创建时，先读取当前用户在该回合的阵营锁定（camp option）。
- 若用户尚未锁定阵营，则使用父评论阵营作为本次回复的 `optionAtAction` 并写入锁定。
- `optionAtAction` 作为回复写入时快照，落库后不随用户后续行为变化。

落库口径：

- 回复对应的 `PKCommentMeta.side` 写入 `optionAtAction`，即“写入时阵营”。
- 回复写入时生成的 `PKAction.side` 与互动日志 `optionAtAction` 保持一致。

查询口径：

- PK 查询与通用评论/回复查询均返回 `optionAtAction`（或等价 `side`）字段。
- 查询返回的是写入时阵营快照，而不是查询时的实时阵营。

### 5.2 评论回复查询（游标分页）

接口能力：

- 提供 PK 维度的评论回复查询接口，支持 `commentId + cursor + pageSize` 游标分页。
- 返回结构与 PK 评论列表保持一致：`comment + option/side + heatScore + downvoteCount + liked`。

查询规则：

- 仅返回 `entity_type=comment` 且 `entity_id=commentId` 的回复。
- 回复需具备 PK 元信息（`PKCommentMeta`），并与父评论保持同 topic/round。
- 排序使用 `id asc`，续页条件为 `id > cursor`。

阵营口径：

- `option/side` 字段返回回复写入时的阵营快照（`PKCommentMeta.side`）。
- 不使用查询时用户实时阵营覆盖历史记录。

### 5.4 我参与（下注）对局列表（按状态查询）

接口能力：

- 在 `GET /api/pk/my/bets` 基础上新增 `status` 查询参数，支持按状态筛选“我参与下注”的对局。
- 列表元素返回结构与 `GET /api/battle/by?battleId=...` 顶层字段对齐：`battle + myAction + myRole + settlement`。
- 保留旧字段 `bet/topic/round`，保证历史调用方无感升级。

状态口径：

- `in_progress`（进行中）：回合处于 `betting` 或 `locked`，且未结算。
- `pending`（待结算）：回合已到 `endTime`，但尚未产出结算结果（`settledAt=0` 且 `winner=''`）。
- `settled`（已结算）：回合已产出结算结果（`settledAt>0` 或 `winner!=''`）。

兼容值：

- 高层状态：`in_progress/pending/settled`。
- 阶段值：`betting/locked/cooldown/settled`（其中 `cooldown` 归属待结算语义）。

返回结构约定：

- `battle`：PK 对局视图（包含 `status/phase/result/resultTime`，以及 `bet/topic/round`）。
- `myAction`：固定 `bet`。
- `myRole`：固定 `challenger`（表示参与下注方）。
- `settlement.settlement`：仅在已结算时返回结算摘要。
- `settlement.myItem`：我的结算明细（存在则返回）。

## 6. 运营与前端能力

P0 前端能力：

- 列表页展示阶段、倒计时、热度、赔率、上局胜方。
- 列表页返回并展示个人态：`hasBet`（我是否已投注）、`canSettle`（我能否结算）；当 `canSettle=false` 时可根据 `settleDisabledReason` 展示禁用态提示。
- 详情页展示对抗条、下注区、双列评论战场、历史战绩。
- 登录用户展示 mySide、myBet、预计收益。

P1 运营能力：

- 话题启停、排序、封面配置。
- 参数配置：下注期、锁局期、冷却期、赛季天数、热度上限。
- 异常回合手动重试结算。

## 7. 风控策略分层

P0：

- 单用户单回合下注唯一约束。
- 复用现有 spam 校验。

P1：

- 账号年龄系数、行为频率衰减。
- 重复内容惩罚。
- 热度异常波动预警。

P2：

- IP/设备聚类。
- 自动熔断高风险动作。
