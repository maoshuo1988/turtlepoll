# 对立PK：特性详情介绍

## 1. 话题与回合领域模型

- 话题是长期实体，保存 A/B 阵营、当前回合、当前赛季引用。
- 回合是短周期实体，保存阶段时间窗、奖池、热度、胜负结果。
- 赛季是统计实体，保存 30 天窗口内的胜场与冠军结果。

实现要点：

1. 新建 PKService 作为领域门面，统一暴露读写能力。
2. 话题状态只区分 enabled/disabled，避免多状态歧义。
3. 当前回合和当前赛季在话题表冗余引用，减少列表查询成本。

## 2. 阶段推进与定时任务

阶段规则：

- betting: roundStartTime <= now < lockTime。
- locked: lockTime <= now < endTime。
- cooldown: endTime <= now < nextRoundTime。

推进规则：

1. 每分钟扫描 betting 且 now >= lockTime 的回合，更新为 locked。
2. 每分钟扫描 locked 且 now >= endTime 的回合，触发结算并更新为 cooldown。
3. 每分钟扫描 cooldown 且 now >= nextRoundTime 的回合，创建下一局。
4. 每分钟检查活动赛季到期，归档并开新赛季。

## 3. 下注与结算

下注规则：

- 固定下注金额 100 龟币。
- 每用户每回合最多下注一次。
- 仅 betting 阶段允许下注。
- 下注请求必须携带 requestId，实现接口幂等。

结算规则：

- 胜方收益 = 本金 + 败方奖池 * 本人下注额 / 胜方总下注额。
- 败方收益 = 0。
- 平局收益 = 本金原路退回。

落库规则：

1. 先写回合 winner、heatA、heatB。
2. 再写结算明细表。
3. 最后执行派奖流水。

## 4. 热度计算与胜负判定

P0 热度采用可解释简化模型：

$$
Heat_{side}=\sum\limits_{comment\in side}\min\left(3+\ln(1+likeCount+1.5\times replyCount),20\right)+validLikeCount+validBetHeat
$$

其中：

- validLikeCount 为有效点赞数。
- validBetHeat 为下注热度贡献，P0 可采用固定值。

胜负判定：

1. heatA > heatB，则 winner=A。
2. heatB > heatA，则 winner=B。
3. heatA = heatB，则 winner=draw。

## 5. 评论战场与阵营归属

评论归属策略：

- 一级评论必须绑定 topicId、roundId、side。
- 回复继承父评论 side，不允许跨阵营继承。
- cooldown 阶段禁止新增评论和回复。

数据策略：

- 通用评论写入 Comment。
- 阵营元信息写入 PKCommentMeta。
- 热度动作写入 PKAction，支持审计和重算。

## 6. 运营与前端能力

P0 前端能力：

- 列表页展示阶段、倒计时、热度、赔率、上局胜方。
- 详情页展示对抗条、下注区、双列评论战场、历史战绩。
- 登录用户展示 mySide、myBet、预计收益。

P1 运营能力：

- 话题启停、排序、封面配置。
- 参数配置：下注期、锁局期、冷却期、赛季天数、热度上限。
- 异常回合手动重算热度。

## 7. 风控策略分层

P0：

- 单用户单回合下注唯一约束。
- 拉踩唯一约束（用户-评论维度）。
- 复用现有 spam 校验。

P1：

- 账号年龄系数、行为频率衰减。
- 重复内容惩罚。
- 热度异常波动预警。

P2：

- IP/设备聚类。
- 自动熔断高风险动作。
