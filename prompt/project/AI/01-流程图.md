# AI 系统核心流程图

> 本文汇总 AI 系统的所有重要流程，包括主动对话、推送投递、体力系统等。详细设计见相应的 04-特性详情介绍-*.md 文件。

## 1. 主动对话链路流程

```mermaid
flowchart TD
  A[用户发起对话] --> B[POST /api/ai/chat]
  B --> C{登录态检查}
  C -- 未登录 --> Z1[返回 401]
  C -- 已登录 --> D{开关检查 AI 功能是否关闭}
  D -- 已关闭 --> Z2[返回提示]
  D -- 已开启 --> E{速率限制检查}
  E -- 超频 --> Z3[返回 429 Too Many Requests]
  E -- 正常 --> F[输入长度/格式校验]
  F -- 不合法 --> Z4[返回 400]
  F -- 合法 --> G[查询 user_ai_stamina]
  G --> H{当前体力是否 > 0}
  H -- 否 --> Z5[返回 425 体力不足]
  H -- 是 --> I[扣除 1 体力]
  I --> J[调用 DeepSeek API]
  J --> K{请求成功?}
  K -- 否 重试 < 3 次 --> J
  K -- 否 重试 >= 3 次 --> L[使用兜底文本 或 记录错误]
  K -- 是 --> M[检查返回内容合规性]
  M --> N{内容是否合规}
  N -- 否 --> O[使用安全兜底文本]
  N -- 是 --> P[保存 ai_message 到库]
  O --> P
  P --> Q[返回消息给前端]
  Q --> R[前端展示对话]
```

## 2. 体力系统流程

```mermaid
flowchart TD
  A[体力管理系统] --> B{体力操作类型}
  
  B --> C[自然恢复]
  C --> C1[每 60 分钟恢复 1 点体力]
  C1 --> C2[监听 last_stamina_recover_at]
  C2 --> C3{上次恢复至今 >= 60 分钟?}
  C3 -- 是 --> C4[stamina_value += 1]
  C3 -- 否 --> C5[等待下一个检查周期]
  C4 --> C6[更新 last_stamina_recover_at]
  
  B --> D[苹果购买]
  D --> D1[用户点击 购买体力]
  D1 --> D2{余额是否 >= 5 龟币/点}
  D2 -- 否 --> D3[返回 余额不足]
  D2 -- 是 --> D4[扣除 5 龟币]
  D4 --> D5[stamina_value += 1]
  D5 --> D6[记录交易日志]
  
  B --> E[管理员授予]
  E --> E1[后台赠送体力]
  E1 --> E2[stamina_value += N]
  E2 --> E3[记录日志 source=admin]
  
  C6 --> F[保存 ai_stamina 到库]
  D6 --> F
  E3 --> F
  F --> G[记录 stamina_operation_log]
  G --> H{操作是否成功}
  H -- 是 --> I[返回最新体力值]
  H -- 否 --> J[记录错误 回滚]
```

## 3. 结算推送流程

```mermaid
flowchart TD
  A[结算服务完成资金入账] --> B[组装 SettlementEvent]
  B --> C[AIPushService.OnSettlement]
  C --> D{request_id 是否已存在}
  D -- 是 --> E[跳过推送]
  D -- 否 --> F[AIMemoryService 更新结算记忆]
  F --> G[更新 win/lose streak]
  F --> H[更新最大盈利/最长连胜]
  G --> I[DecideSettlementScene]
  H --> I
  I --> J{是否命中 scene}
  J -- 否 --> K[不生成消息]
  J -- 是 --> L[AITemplateService 选择模板]
  L --> M{模板是否可渲染}
  M -- 否 --> N[换下一条模板或使用兜底]
  N --> M
  M -- 是 --> O[保存 ai_message 未读消息]
  O --> P[写 template_user_view 曝光]
  P --> Q[AIPushDelivery 投递]
  Q --> R{SSE 在线?}
  R -- 是 --> S[发送 ai_push 事件]
  R -- 否 --> T[等待未读接口补拉]
```

## 4. 闲置推送流程

```mermaid
flowchart TD
  A[cron 每分钟触发] --> B[AIPresenceService.FindIdleCandidates]
  B --> C{是否有候选用户}
  C -- 否 --> D[结束本轮扫描]
  C -- 是 --> E[逐个处理用户]
  E --> F{active=true 且 last_seen_at 在 60 秒内?}
  F -- 否 --> Z1[跳过用户]
  F -- 是 --> G{距上次 AI 互动是否超过 idleTriggerMinutes?}
  G -- 否 --> Z1
  G -- 是 --> H{是否超过冷却且未达每日上限?}
  H -- 否 --> Z1
  H -- 是 --> I[读取 user_ai_memory]
  I --> J[选择可用 idle scene]
  J --> K{是否有可用记忆}
  K -- 否 --> Z1
  K -- 是 --> L[AITemplateService 渲染模板]
  L --> M{模板是否完整}
  M -- 否 --> Z1
  M -- 是 --> N[保存 ai_message 未读消息]
  N --> O[更新 last_idle_push_at 和 idle_push_count]
  O --> P[更新 flag_meta.lastPushedAt]
  P --> Q[AIPushDelivery 投递]
  Q --> R{SSE 在线?}
  R -- 是 --> S[发送 ai_push 事件]
  R -- 否 --> T[等待未读接口补拉]
  Z1 --> U{还有下一个用户?}
  S --> U
  T --> U
  U -- 是 --> E
  U -- 否 --> V[结束本轮扫描]
```

## 5. 投递与已读闭环

```mermaid
sequenceDiagram
  participant Backend as AIPushService
  participant DB as ai_message
  participant Hub as AIPushHub/SSE
  participant FE as Frontend

  Backend->>DB: 保存未读推送 status=0
  Backend->>Hub: Publish(userId, message)
  alt SSE 在线
    Hub-->>FE: event: ai_push
    FE->>FE: 展示浮窗或插入消息列表
  else SSE 不在线
    FE->>DB: GET /api/ai/pushes/unread
    DB-->>FE: 返回未读消息列表
  end
  FE->>Backend: POST /api/ai/pushes/read ids=[...]
  Backend->>DB: update status=1 where user_id=? and id in (...)
  DB-->>Backend: 更新成功
  Backend-->>FE: ok
```

## 6. Presence 心跳与在线判定流程

```mermaid
flowchart TD
  A[前端启动 或 用户交互] --> B[POST /api/ai/presence]
  B --> C{检查参数}
  C -- 参数非法 --> Z1[返回 400]
  C -- 参数有效 --> D[保存或更新 user_presence]
  D --> E{active 状态}
  E -- active=true --> F[更新 last_seen_at=now]
  E -- active=false --> G[保留 last_seen_at 不变]
  F --> H[计算心跳间隔]
  G --> H
  H --> I{是否需要启动心跳定时器}
  I -- 是 --> J[设置 setInterval 60 秒]
  I -- 否 --> K[检查现有定时器]
  J --> L[自动调用 Presence 保活]
  K --> L
  L --> M[发送心跳 active=true]
  M --> N{收到响应}
  N -- 失败 --> O[记录日志 继续重试]
  O --> L
  N -- 成功 --> P[心跳有效]
  P --> Q{是否继续活跃?}
  Q -- 用户离开 --> R[主动调用 active=false]
  Q -- 用户在线 --> L
  R --> S[清理心跳定时器]
```

## 7. DeepSeek 超时重试策略

```mermaid
flowchart TD
  A[发起 DeepSeek 请求] --> B[request_id=uuid]
  B --> C[设置超时时间 30秒]
  C --> D[调用 DeepSeek API]
  D --> E{请求在 30 秒内返回?}
  E -- 是 --> F{HTTP 状态码}
  E -- 否 超时 --> G{重试次数 < 3?}
  G -- 是 --> H[等待 backoff 秒 重试]
  H --> D
  G -- 否 --> I[记录错误 使用兜底]
  F -- 200 --> J[解析响应体]
  F -- 429 --> K[标记限流 使用兜底]
  F -- 5xx --> L{重试次数 < 3?}
  L -- 是 --> M[等待 backoff 秒 重试]
  M --> D
  L -- 否 --> I
  J --> N{返回内容是否为空}
  N -- 是 --> I
  N -- 否 --> O[返回有效回复]
```

## 8. 消息模板去重与选择

```mermaid
flowchart TD
  A[命中推送场景] --> B[scene=lose_streak 或 win_streak 等]
  B --> C[查询 template_user_view]
  C --> D[按 曝光次数 升序 排序模板]
  D --> E{是否存在 未曝光 的模板}
  E -- 是 --> F[选择 最少曝光 的模板]
  E -- 否 --> G{是否 超过 24h 的模板}
  G -- 是 --> H[选择 最少曝光 的历史模板]
  G -- 否 --> I[降级为 通用兜底模板]
  F --> J[渲染模板]
  H --> J
  I --> J
  J --> K{是否存在占位符}
  K -- 是 --> L[替换占位符 如 {user_name}}]
  K -- 否 --> M[模板已完成]
  L --> N{占位符替换成功?}
  N -- 是 --> M
  N -- 否 --> O[使用兜底模板重试]
  O --> J
  M --> P[返回最终消息]
```
