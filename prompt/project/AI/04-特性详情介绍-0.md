## 2. 核心业务链路

### 2.1 主动对话链路

用户主动向小龟提问，系统进行登录验证、频率控制、体力校验、输入检查，然后调用 DeepSeek 生成回复，保存消息并扣减体力。见 [04-特性详情介绍-主动对话链路.md](./04-特性详情介绍-主动对话链路.md)。

**关键特性**：
- 体力校验：体力不足不调用 LLM
- 体力管理：自然恢复、苹果购买、体力流水
- 频率控制：每日对话上限、用户频控
- 身份兜底：不暴露底层模型
- DeepSeek 调用：超时重试、错误处理

### 2.2 结算推送链路

投票/预测结算完成后，触发 AI 推送服务生成相应文案。系统先检查幂等性、更新用户记忆（streak、最大盈利等）、决策推送场景、选择并渲染模板、落库消息、记录曝光。见 [04-特性详情介绍-结算推送链路.md](./04-特性详情介绍-结算推送链路.md)。

**关键特性**：
- 幂等性保护：防止重复推送
- 记忆维护：streak、最大盈利、连胜纪录
- 场景决策：优先级决策（streak > 普通输赢）
- 模板选择：去重机制，优先未看过的
- 消息落库：不消耗体力，不调用 LLM

### 2.3 闲置推送链路

定时扫描在线但长时间未互动的用户，根据用户记忆（首次龟种、最大盈利、连胜纪录）选择合适的推送场景，生成闲置推送。通过 SSE 在线投递和未读轮询兜底。见 [04-特性详情介绍-闲置推送链路.md](./04-特性详情介绍-闲置推送链路.md)。

**关键特性**：
- Presence 上报：心跳保活
- 闲置候选扫描：定时任务
- 频率控制：冷却期、每日上限
- 记忆选择：有事实才推送
- SSE 投递：在线实时、离线补拉
- 未读接口：拉取与标记已读

## 4. 验收重点

**主动对话链路**：
- 体力不足时不调用 DeepSeek。
- DeepSeek 调用失败时不扣体力。
- 用户消息和助手回复都会保存。
- 体力流水记录准确。

**结算推送链路**：
- 结算推送不调用 DeepSeek。
- 同一结算事件重复投递只生成一条消息（幂等性）。
- `win_streak/lose_streak` 优先于普通 `win/lose`。
- 模板曝光记录准确更新。

**闲置推送链路**：
- 闲置推送遵守冷却期和每日上限。
- 无可用记忆时跳过推送（不发空推送）。
- 在线用户通过 SSE 实时接收推送。
- 离线用户下次打开时能补拉所有未读消息。

**通用要求**：
- 主动推送都不消耗体力，不调用 LLM。
- 推送失败不影响主业务事务。
- 模板缺失或占位符错误时不发送半成品文案。
