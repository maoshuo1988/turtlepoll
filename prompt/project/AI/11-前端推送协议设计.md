# 前端推送协议设计

> 本文说明 AI 主动推送如何送达前端。结论：本期推荐 SSE 做在线即时推送，HTTP 未读轮询做兜底，暂不优先使用 WebSocket。

## 1. 协议选择

| 通道 | 用途 | 是否 MVP 必需 |
| --- | --- | --- |
| SSE | 在线即时推送，服务端向前端单向发送 AI 推送事件 | 建议做 |
| HTTP 轮询 | 拉取未读推送，作为离线、断线、SSE 不可用时的兜底 | 必做 |
| WebSocket | 暂不使用；只有后续需要双向实时互动时再引入 | 否 |

选择 SSE 的原因：

- AI 主动推送是服务端到前端的单向消息，不需要 WebSocket 的双向通道。
- 浏览器原生 `EventSource` 支持断线重连和 `Last-Event-ID`。
- 服务端实现比 WebSocket 简单，和未读消息表配合更稳。
- 失败兜底仍以 `ai_message` 未读查询为准。

## 2. SSE 接口

```text
GET /api/ai/pushes/stream
```

要求：

- 需要登录态。
- 响应头：

```text
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

- 服务端每 30 秒发送心跳，避免代理或浏览器断开：

```text
: ping
```

## 3. SSE 事件格式

新推送事件：

```text
id: 20001
event: ai_push
data: {"id":20001,"scene":"win","content":"这把赢了 120。小龟先替你把尾巴翘一下。","contextType":"predict_market","contextId":123,"createTime":1760000000}
```

未读数变更事件，可选：

```text
event: ai_push_unread_count
data: {"count":3}
```

约定：

- `id` 使用 `ai_message.id`。
- 前端收到 `ai_push` 后展示浮窗或插入小龟消息列表。
- 展示后是否立刻标记已读由产品决定；建议用户实际看到浮窗或打开消息后再调用标记已读。

## 4. 断线补偿

SSE 断线重连时浏览器会带 `Last-Event-ID`。服务端处理建议：

1. 若请求带 `Last-Event-ID`，先查询 `id > lastEventId` 且 `status=0` 的未读推送。
2. 逐条补发 `ai_push` 事件。
3. 再进入实时等待。

前端仍应在以下时机调用 `GET /api/ai/pushes/unread`：

- 页面首次加载。
- SSE 连接失败或重连超过 3 次。
- 用户从后台切回前台。
- 用户打开 AI 聊天浮窗。

## 5. 后端连接管理

建议新增连接管理器：

```text
AIPushHub
  Register(userId, connection)
  Unregister(connection)
  Publish(userId, message)
```

实现要点：

- 一个用户允许多端或多标签页连接。
- 每个连接有缓冲队列，队列满时断开该连接，避免慢客户端拖垮服务。
- `Publish` 失败不影响消息落库。
- MVP 单实例可用本机内存 Hub。
- 多实例上线前必须接跨进程通道，推荐先用 Redis Pub/Sub：业务实例提交 `ai_message` 后发布 `{userId,messageId}`，各实例收到后只向本机 SSE 连接投递；投递失败仍由未读接口兜底。

## 6. 前端接入建议

前端启动顺序：

1. 页面加载后先调用 `GET /api/ai/pushes/unread`。
2. 建立 `EventSource('/api/ai/pushes/stream')`。
3. 收到 `ai_push` 后插入本地消息列表或展示浮窗。
4. 用户打开浮窗或确认已看到后，调用 `POST /api/ai/pushes/read`。
5. `EventSource.onerror` 时显示为离线状态，并保留轮询兜底。

标记已读响应：

```json
{
  "updated": 2
}
```

`updated` 是真实从未读改为已读的数量；重复提交已读 ID 不视为错误。

兜底轮询：

- SSE 正常时可以不轮询，或每 2-5 分钟低频校准一次。
- SSE 异常时每 15-30 秒调用一次未读接口。
- 页面重新可见时立即拉一次未读。

## 7. MVP 降级策略

如果第一期不做 SSE：

1. `AIPushDelivery.Deliver` 先做 no-op。
2. 前端每 15-30 秒调用 `GET /api/ai/pushes/unread`。
3. 用户打开聊天浮窗时立即拉一次未读。
4. 后端所有推送仍先保存到 `ai_message`，后续补 SSE 不改业务生成逻辑。

## 8. 验收点

- SSE 在线时能收到 `ai_push` 事件。
- SSE 心跳不会在 1 分钟内断开。
- SSE 断线重连后能通过 `Last-Event-ID` 补齐遗漏消息。
- SSE 不可用时，前端能通过未读轮询补拉消息。
- 多标签页登录同一账号时，每个标签页都能收到消息或通过未读接口补齐。
- 服务端重启后，未读消息仍能从 `ai_message` 拉取。
- 多实例部署时，跨进程 Pub/Sub 中断不影响未读接口补拉。
