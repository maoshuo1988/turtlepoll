# AI 基础能力特性实现详述

> 本文承接 [02-特性清单.md](./02-特性清单.md)，只展开主动聊天、体力、身份兜底、DeepSeek、记忆问答与风控相关特性。推送相关详述见 [14-特性实现详述-推送与迭代.md](./14-特性实现详述-推送与迭代.md)。

## 1. 用户主动 AI 对话

目标：用户在聊天入口、预测市场页、比赛页向小龟提问，并获得短回复。

实现方案：

1. 前端调用 `POST /api/ai/chat`，传 `content/scene/contextType/contextId`。
2. `AIChatController` 校验登录态，转交 `AIChatService.Chat`。
3. `AIChatService` 执行功能开关、输入长度、每日频控、体力校验。
4. `AIContextService` 根据 `contextType/contextId` 读取站内上下文；MVP 先支持 `predict_market`。
5. `AIPromptBuilder` 组合基础人格 Prompt、站内上下文、近期历史消息、用户输入。
6. `DeepSeekClient` 非流式调用模型，返回助手文案和 token usage。
7. 成功后事务内保存用户消息、助手消息、扣 AI 体力并写体力流水。
8. 失败时返回降级文案，不扣体力，不保存成功对话。

验收点：

- 普通闲聊可返回小龟口吻。
- `contextType=predict_market` 时回复能引用站内事件事实。
- 回复不暴露 DeepSeek / ChatGPT 身份。
- DeepSeek 异常时不扣体力。

## 2. 体力校验

目标：控制主动 LLM 调用频率和成本。

实现方案：

1. 新增 `user_ai_stamina` 和 `user_ai_stamina_log`。
2. 用户首次使用时初始化 `stamina=max_stamina=5`。
3. 每次读取体力时根据 `last_recover_at` 懒结算自然恢复。
4. 主动聊天前校验 `stamina >= aiChat.defaultStaminaCost`。
5. DeepSeek 成功后在同一事务里扣体力、写流水、更新每日使用计数。
6. 体力不足时直接返回兜底文案，不调用 DeepSeek。

并发要求：

- 扣体力时对 `user_ai_stamina` 行加锁。
- 体力不能扣成负数。
- DeepSeek 失败或事务失败时不能产生体力流水。

## 3. 体力状态查询

目标：让前端能稳定展示用户当前 AI 体力、上限、下次恢复时间和每日使用次数。

实现方案：

1. 新增 `GET /api/ai/stamina`。
2. 查询前调用自然恢复懒结算，保证返回的是最新体力。
3. 返回 `stamina/maxStamina/nextRecoverAt/dailyUsedCount/dailyLimit`。
4. 若用户没有体力状态，先创建 `user_ai_stamina`，默认 `stamina=max_stamina=5`。
5. 前端打开聊天入口、聊天成功、苹果恢复成功后都可以刷新该接口。

验收点：

- 新用户首次查询能拿到默认满体力。
- 返回的 `nextRecoverAt` 能支持前端倒计时。
- 查询接口不调用 DeepSeek，不消耗体力。

## 4. 自然体力恢复

目标：用户不操作时，体力按时间自然恢复到上限。

实现方案：

1. 根据 `last_recover_at` 和当前时间计算完整恢复周期数。
2. 每经过 `aiChat.staminaRecoverMinutes` 恢复 1 点体力。
3. 恢复后更新 `stamina` 和 `last_recover_at`。
4. 到达 `max_stamina` 后不继续累计溢出体力。
5. 在查询体力、聊天前校验、苹果恢复前统一触发懒结算。

并发要求：

- 懒结算时对 `user_ai_stamina` 行加锁。
- 多个请求同时触发恢复时，恢复量不能重复计算。

## 5. 苹果恢复体力

目标：用户体力不足时，可以消耗龟币主动恢复体力。

实现方案：

1. 新增 `POST /api/ai/stamina/apple`，接收 `count`。
2. 处理前先做自然恢复懒结算。
3. 每颗苹果消耗 5 龟币并恢复 1 点体力。
4. 苹果恢复时同时写龟币流水和 `user_ai_stamina_log`。
5. 龟币扣减、体力增加、两类流水必须在同一事务内成功。
6. 体力已满、龟币不足、`count <= 0` 时直接拒绝，不写任何流水。
7. 恢复成功后返回最新 `stamina/maxStamina/nextRecoverAt/coinCost`。

验收点：

- 苹果恢复扣龟币和加体力同时成功或同时失败。
- 体力已满时不会扣龟币。
- 一次购买多颗苹果时，实际恢复量不能超过剩余体力缺口。

## 6. 运营赠送体力

目标：支持运营或客服在活动、补偿、异常处理时给用户补发体力。

实现方案：

1. 后台或脚本入口接收 `userId/amount/remark`。
2. 操作前先读取并锁定 `user_ai_stamina`。
3. 按 `amount` 增加体力，但不能超过 `max_stamina`，除非后续明确支持临时溢出。
4. 写 `user_ai_stamina_log`，`biz_type=ADMIN`，保留操作人、原因、关联活动等信息。
5. 后台操作需记录操作日志，便于追溯。

## 7. AI 身份兜底

目标：用户问“你是谁”“你是不是 ChatGPT/DeepSeek”时，只回答小龟身份。

实现方案：

1. `AIRiskService` 或 `AIIntentService` 先做规则识别。
2. 命中身份问答时优先返回固定模板，不调用 LLM。
3. 未命中规则时仍通过 system prompt 约束模型不得暴露底层模型。
4. 身份兜底可保存到 `ai_message`，`scene=identity_fallback`，`stamina_cost=0`。

规则示例：

- 包含 `ChatGPT`、`DeepSeek`、`模型`、`AI`、`你是谁`。
- 问法相似但不确定时，可以仍调用 LLM，但 Prompt 必须强约束。

## 8. 对话消息保存

目标：聊天、推送、降级都能追踪来源和展示历史。

实现方案：

1. 用户主动聊天成功保存两条 `ai_message`：用户消息和助手回复。
2. 主动推送保存一条助手消息，`status=unread`。
3. 降级文案是否保存需区分场景：DeepSeek 失败的临时降级可不保存；规则兜底可保存。
4. `context_type/context_id` 弱关联业务上下文。
5. `template_id` 记录主动推送模板来源。
6. `prompt_tokens/completion_tokens/total_tokens` 只记录 LLM 回复。

## 9. DeepSeek 调用封装

目标：服务端统一调用 DeepSeek，屏蔽外部 API 细节。

实现方案：

1. `DeepSeekClient` 接收 `baseURL/apiKey/model/timeout/maxRetries`。
2. 默认使用 `deepseek-v4-flash`、`thinking.disabled`、非流式。
3. HTTP 非 2xx 时读取有限长度错误体，便于排查。
4. 支持上下文取消和超时。
5. 返回统一结构：文本、request id、模型名、token usage。
6. 日志不得打印 API Key 和 Authorization。

验收点：

- API Key 缺失时返回明确错误。
- 超时和 429 可降级。
- 不保存 `reasoning_content`。

## 10. 用户主动问记忆

目标：用户问“我第一次开蛋是什么”“我最多赚过多少”时，小龟按事实回答。

实现方案：

1. `AIIntentService` 识别记忆问答意图。
2. `AIMemoryService` 根据意图读取所需 `user_ai_memory` Flag。
3. 将事实拼入记忆 Prompt。
4. 调用 DeepSeek 生成自然回答。
5. 缺少事实时返回固定兜底，不编造。
6. 消耗体力，成功后保存对话。

## 11. 记忆 Flag 维护

目标：业务事件持续更新关键用户记忆。

实现方案：

1. 结算服务更新最大盈利、输赢 streak。
2. 开蛋服务更新首次开蛋、首次 SSS、拥有龟种数。
3. 登录/签到服务更新连续登录。
4. 主动聊天成功后更新累计对话次数。
5. `AIMemoryService.UpsertFlag` 统一写入 `flag_key/flag_value/flag_meta`。
6. 对“最大值”类 Flag 只在新值更大时更新。

## 12. 风控与成本

敏感话题兜底：

1. 复用现有敏感词系统或新增 `AIRiskService` 分类。
2. 命中强敏感时不调用 LLM，返回固定兜底。
3. 命中弱敏感时调用 LLM，但增加风险 Prompt。
4. LLM 输出后做二次风险词扫描，命中则替换为兜底。

用户辱骂兜底：

1. `AIRiskService` 根据辱骂词表和语义规则识别。
2. 重度辱骂直接返回克制文案，不调用 LLM，不消耗体力。
3. 可记录 `scene=abuse_fallback` 便于运营审计。

成本记录与频控：

1. `DeepSeekClient` 解析 `usage.prompt_tokens/completion_tokens/total_tokens`。
2. `AIChatService` 保存 token usage 到助手消息。
3. 按北京时间自然日统计用户主动聊天次数。
4. 达到 `aiChat.dailyUserMessageLimit` 时不调用 LLM。
