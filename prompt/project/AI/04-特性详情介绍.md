## 2. 核心技术特性

### 2.1 主动对话链路

- 用户调用 `POST /api/ai/chat`
- 先做登录、开关、频控、输入长度、体力校验
- 再组装 Prompt 调用 DeepSeek
- 成功后保存消息并扣减体力

### 2.2 记忆问答链路

- 用户问题命中记忆类型时读取 `user_ai_memory`
- 仅将后端事实注入 Prompt
- 无事实时走统一兜底，不编造

### 2.3 结算推送链路

- 监听结算事件
- 幂等键：`settle:{bizType}:{bizId}:{scene}`
- 场景优先级：`lose_streak/win_streak > lose/win`
- 先落库再 SSE 投递

### 2.4 闲置推送链路

- 定时扫描在线且闲置用户
- 满足冷却和每日上限后才触发
- 无记忆事实则跳过

### 2.5 体力系统

- 主动消息消耗体力
- 主动推送不消耗体力
- 自然恢复 + 苹果恢复 + 运营赠送

## 4. 验收要点

1. 体力不足时不调用 DeepSeek。
2. 主动推送不消耗体力。
3. 主动推送失败不影响主业务事务。
4. 结算事件重复投递不产生重复消息。
5. 未读补拉和 SSE 在线投递一致。
