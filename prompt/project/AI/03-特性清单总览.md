# AI 聊天特性清单

> 本文按优先级整理 AI 聊天需要实现的特性。

## 1. MVP 特性

| 特性 | 描述 | 触发方式 | 调用 LLM | 优先级 | 实现状态 | 当前说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 用户主动 AI 对话 | 用户向小龟提问，支持闲聊、比赛分析、身份问答 | 用户发送消息 | 是 | P0 | 部分实现 | 已实现 `POST /api/ai/chat`、普通聊天、历史上下文拼装、独立 AI 体力扣减；比赛/预测上下文只保留 `contextType/contextId` 字段，尚未读取站内预测数据。 |
| 体力校验 | 主动对话前检查体力，不足直接兜底 | 用户发送消息 | 否 | P0 | 已实现 | 已在聊天前按 `aiChat.defaultStaminaCost` 校验 `user_ai_stamina`；体力不足返回兜底，不调用 DeepSeek；DeepSeek 成功后才扣体力并写流水。 |
| 体力状态查询 | 查询当前体力、上限、下次恢复时间和每日使用次数 | 打开聊天入口 / 体力变化后刷新 | 否 | P0 | 已实现 | 已实现 `GET /api/ai/stamina`；读取前做自然恢复懒结算，返回 `stamina/maxStamina/nextRecoverAt/dailyUsedCount/dailyLimit` 等字段。 |
| 自然体力恢复 | 按时间周期自动恢复体力，不超过体力上限 | 查询体力 / 聊天前校验 | 否 | P0 | 已实现 | 已根据 `last_recover_at` 懒结算恢复量，默认每 `aiChat.staminaRecoverMinutes=60` 分钟恢复 1 点；不需要单独定时任务。 |
| 苹果恢复体力 | 用户消耗龟币购买苹果恢复体力 | 用户点击喂苹果 | 否 | P0 | 已实现 | 已实现 `POST /api/ai/stamina/apple`，默认 5 龟币恢复 1 点体力；龟币扣减、体力增加、两类流水在同一事务内完成。 |
| AI 身份兜底 | 问模型身份时回答“小龟”身份 | 用户发送消息 | 可不调 | P0 | 部分实现 | 已在 system prompt 中要求不暴露底层模型、以小龟身份回答；尚未做规则级免 LLM 兜底。 |
| 结算资金入账完成 | 预测/投票结算先完成用户资金入账，再允许触发 AI 推送 | 结算服务 | 否 | P0 | 已实现 | `PredictSettleService.SettleMyBet` 在资金入账事务提交后触发 AI 推送事件；入账失败不会推送。 |
| 结算推送事件发布 | 入账成功后组装 `SettlementEvent` 并交给 AI 推送服务 | 结算服务事务完成 | 否 | P0 | 已实现 | 已组装 `AISettlementEvent`，包含 `userId/bizType/bizId/settleResult/profitAmount/context`。 |
| 结算推送幂等检查 | 防止结算重试或重复事件生成多条 AI 消息 | `AIPushService.OnSettlement` | 否 | P0 | 已实现 | 使用 `ai_message.request_id=settle:{bizType}:{bizId}:{scene}`；迁移增加非空 request_id 部分唯一索引。 |
| 结算记忆更新 | 结算后更新最大盈利、最长连胜、最长连败等记忆 | 结算推送事件 | 否 | P0 | 已实现 | `AIPushService` 已写 `UserAIMemory`，更新最大盈利、最长连胜和最长连败。 |
| 连胜 streak 维护 | 盈利结算累加连胜并清空连败 | 结算推送事件 | 否 | P0 | 已实现 | 已维护 `vote_win_streak`，同时将 `vote_lose_streak` 归零。 |
| 连败 streak 维护 | 亏损结算累加连败并清空连胜 | 结算推送事件 | 否 | P0 | 已实现 | 已维护 `vote_lose_streak`，同时将 `vote_win_streak` 归零。 |
| 结算推送场景决策 | 根据盈亏和 streak 选择唯一推送 scene | 记忆更新后 | 否 | P0 | 已实现 | 已按 `lose_streak > win_streak > lose > win` 决策，单次结算最多一条推送。 |
| 投票结算赢推送 | 盈利结算命中 `win` 场景时生成鼓励文案 | 场景决策 | 否 | P0 | 已实现 | 已由 `AIPushService.OnSettlement` 生成 `win` 场景未读消息。 |
| 投票结算输推送 | 亏损结算命中 `lose` 场景时生成克制提醒 | 场景决策 | 否 | P0 | 已实现 | 已由 `AIPushService.OnSettlement` 生成 `lose` 场景未读消息。 |
| 连胜推送 | 连胜达到 3 场及以上时生成 `win_streak` 文案 | 场景决策 | 否 | P0 | 已实现 | 已支持 `vote_win_streak >= 3` 时优先生成 `win_streak`。 |
| 连败推送 | 连败达到 5 场及以上时生成 `lose_streak` 文案 | 场景决策 | 否 | P0 | 已实现 | 已支持 `vote_lose_streak >= 5` 时优先生成 `lose_streak`。 |
| 推送模板选择 | 按 scene 从启用模板中选择一条候选模板 | 后端推送服务 | 否 | P0 | 已实现 | 已实现启用过滤、曝光次数优先和权重排序；无模板时使用固定兜底模板。 |
| 推送模板渲染校验 | 替换 `{amount}`、`{n}` 等占位符并校验完整性 | 模板选择后 | 否 | P0 | 已实现 | 渲染后检查残留 `{xxx}`，不可渲染则换模板或使用兜底。 |
| 主动推送消息落库 | 将主动推送保存为未读 `ai_message` | 模板渲染成功 | 否 | P0 | 已实现 | 已保存 `role=assistant/status=0/stamina_cost=0/request_id/template_id`。 |
| 模板曝光记录 | 推送落库后记录用户看过的模板 | 消息落库后 | 否 | P0 | 已实现 | 已对 `template_user_view` 做 upsert 并累计 `view_count`。 |
| 推送投递编排 | 落库后统一调度 SSE 在线投递和离线兜底 | 消息落库后 | 否 | P0 | 已实现 | 已实现内存 `AIPushHub`，事务提交后发布，离线用户由未读接口补拉。 |
| SSE 在线推送 | 在线用户通过 SSE 接收 `ai_push` 事件 | 消息落库后 | 否 | P0 | 已实现 | 已实现 `GET /api/ai/pushes/stream`，支持心跳和 `Last-Event-ID` 未读补发。 |
| 未读推送拉取 | 前端拉取离线或断线期间的未读推送 | 页面加载/断线重连/打开浮窗 | 否 | P0 | 已实现 | 已实现 `GET /api/ai/pushes/unread`。 |
| 推送标记已读 | 用户展示或打开推送后标记消息已读 | 前端确认展示/打开消息 | 否 | P0 | 已实现 | 已实现 `POST /api/ai/pushes/read`，仅更新当前用户自己的未读消息并返回 `updated`。 |
| 对话消息保存 | 保存用户消息和小龟回复 | 聊天/推送 | 否 | P0 | 部分实现 | 用户主动聊天成功时会保存用户消息和助手回复；主动推送落库、未读拉取、已读更新尚未实现。 |
| DeepSeek 调用封装 | 服务端统一封装非流式调用 | 主动聊天 | 是 | P0 | 已实现 | 已新增 `internal/pkg/deepseek` 非流式 Chat Completions 客户端，支持超时、重试、错误响应读取。 |

| 记忆 Flag 维护 | 业务事件更新关键记忆 | 结算/开蛋/登录 | 否 | P1 | 未实现 | 已建 `UserAIMemory` 表结构，尚未接入结算、开蛋、登录等业务事件。 |

## 4. DeepSeek 调用策略

| 场景 | 是否调用 DeepSeek | 模型 | thinking | 说明 |
| --- | --- | --- | --- | --- |
| 普通闲聊 | 是 | `deepseek-v4-flash` | disabled | 默认低成本模型。 |
| AI 身份问答 | 可不调用 | 无 | 无 | 推荐规则兜底。 |
| 比赛/预测简单分析 | 是 | `deepseek-v4-flash` | disabled | 基于站内上下文生成简短分析。 |
| 复杂预测分析 | 是 | `deepseek-v4-pro` | enabled | 可使用 `reasoning_effort=high`。 |
| 用户主动问记忆 | 是 | `deepseek-v4-flash` | disabled | 事实由后端提供。 |
| 投票结算推送 | 否 | 无 | 无 | 只走模板。 |
| 闲置推送 | 否 | 无 | 无 | 只走模板。 |
| 体力不足 | 否 | 无 | 无 | 系统兜底。 |
| DeepSeek 不可用 | 否 | 无 | 无 | 系统降级文案。 |

## 7. 验收重点

1. 体力不足时不调用 DeepSeek。
2. 主动推送不消耗体力。
3. 主动推送不实时调用 DeepSeek。
4. 普通分析不会主动提起历史记忆。
5. 问模型身份不会暴露底层模型。
6. DeepSeek 调用失败不扣体力。
7. 模板去重能避免同一用户短期反复看到同一句。
