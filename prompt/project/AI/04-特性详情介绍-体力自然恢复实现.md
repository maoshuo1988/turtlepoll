# AI 体力自然恢复实现

> 本文补充 [04-特性详情介绍-主动对话链路.md](./04-特性详情介绍-主动对话链路.md) 中 2.2b 自然恢复实现的细节，明确采用的模块和触发方式。

## 1. 结论

- 采用“请求时计算 + 需要时回写”的懒结算机制，不使用独立轮询任务。
- 自然恢复由 `AIStaminaService` 统一负责。
- 触发点只有三处：
  - `GET /api/ai/stamina` 查询体力
  - 聊天扣减前的体力预处理
  - 苹果购买前的体力预处理

## 2. 负责模块

### 2.1 查询模块

- `AIStaminaService.GetStamina()`：读取体力、做懒恢复、返回 `nextRecoverAt`。

### 2.2 聊天模块

- `AIChatService` 在进入 DeepSeek 调用前，先调用 `AIStaminaService.RefreshIfNeeded()`。
- 若恢复后仍不足，则直接返回体力不足兜底，不进入模型调用。

### 2.3 苹果模块

- `AIStaminaService.BuyApple()` 在扣龟币和加体力前，先调用 `RefreshIfNeeded()`。
- 恢复回写与苹果购买必须放入同一事务。

## 3. 恢复计算

```text
elapsedMinutes = now - last_recover_at
recoverPoints  = floor(elapsedMinutes / staminaRecoverMinutes)
newStamina     = min(stamina + recoverPoints, defaultMaxStamina)
newRecoverAt   = last_recover_at + recoverPoints * staminaRecoverMinutes * 60
```

- `staminaRecoverMinutes` 从 `aiChat.staminaRecoverMinutes` 读取，默认 60。
- `defaultMaxStamina` 从 `aiChat.defaultMaxStamina` 读取，当前生产值为 5。
- `newRecoverAt` 必须按整周期推进，不得直接写为 `now`。

## 4. 回写规则

| 场景 | 是否回写 |
| --- | --- |
| 查询体力 | 有恢复量时回写 |
| 聊天扣减前 | 有恢复量时回写 |
| 苹果购买前 | 有恢复量时回写，并与购买事务合并 |

## 5. 边界规则

1. `recoverPoints == 0` 时不更新数据库。
2. 体力已满时，不推进 `last_recover_at`。
3. 不得使用定时轮询作为主恢复手段；若存在定时任务，只能做补偿对账。
4. 回写与后续扣减/增加必须在同一事务内完成。

## 6. SQL 口径

```sql
UPDATE user_ai_stamina
SET stamina = :newStamina,
    last_recover_at = :newRecoverAt,
    updated_at = NOW()
WHERE user_id = :userId
```

## 7. nextRecoverAt 返回

```text
if newStamina >= defaultMaxStamina:
    nextRecoverAt = 0
else:
    nextRecoverAt = newRecoverAt + staminaRecoverMinutes * 60
```

## 8. 验收要点

1. 查询、聊天、苹果三条链路都能触发同一套恢复逻辑。
2. 不存在独立轮询任务参与主恢复。
3. 体力恢复回写与业务扣减/增加不会拆成两个事务。
