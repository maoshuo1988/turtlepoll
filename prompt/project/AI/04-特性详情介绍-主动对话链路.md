# AI 主动对话链路

> 本文说明用户主动向小龟提问的完整实现流程，包括输入校验、体力管理、DeepSeek 调用、消息保存等环节。

## 1. 处理流程

### 1.1 完整流程

```text
用户发送聊天消息
  -> POST /api/ai/chat
  -> 登录验证
  -> 开关检查（aiChat.enabled）
  -> 用户频控（aiChat.dailyUserMessageLimit）
  -> 输入长度校验（aiChat.maxInputLength）
  -> 体力校验：检查 stamina >= aiChat.defaultStaminaCost
     ├─ 不足 -> 返回体力不足兜底文案，不调用 DeepSeek
     └─ 足够 -> 继续
  -> 读取消息历史（保留最近 N 条）
  -> 读取业务上下文（contextType/contextId 对应的站内信息）
  -> 组装 Prompt（system prompt + 历史 + 用户输入 + 上下文）
  -> 调用 DeepSeek ChatCompletion（非流式）
  -> 保存用户消息（role=user）
  -> 保存助手回复（role=assistant）
  -> 扣减体力 stamina -= aiChat.defaultStaminaCost
  -> 写入体力流水（user_ai_stamina_log）
  -> 更新 presence.last_ai_interact_at = now
  -> 返回助手回复
```

## 2. 体力系统

### 2.1 规则

| 场景 | 消耗体力 | 说明 |
| --- | --- | --- |
| 用户主动对话 | 是 | 每次 `aiChat.defaultStaminaCost` 点，通常为 1 |
| 用户主动问记忆 | 是 | 每次 1 点 |
| 用户回复闲置推送 | 是 | 每次 1 点 |
| 投票结算主动推送 | 否 | 模板推送，不消耗体力 |
| 闲置记忆主动推送 | 否 | 模板推送，不消耗体力 |
| 体力为 0 时主动对话 | 否 | 返回兜底文案，不调用 DeepSeek |

### 2.2 查询与更新

**查询体力** - `GET /api/ai/stamina`

前置处理：

1. 读取 `user_ai_stamina` 记录。
2. 根据 `last_recover_at` 懒结算自然恢复量：每 `aiChat.staminaRecoverMinutes`（默认 60） 分钟恢复 1 点，不超过 `maxStamina`。
3. 回写 `last_recover_at = now`、`stamina = recovered_stamina`。

返回字段：

```json
{
  "stamina": 3,
  "maxStamina": 10,
  "nextRecoverAt": 1760000060,
  "dailyUsedCount": 5,
  "dailyLimit": 20
}
```

**自然恢复** - 非主动操作，在以下时刻触发：

- 用户查询体力时。
- 用户发送聊天消息时。
- 用户点击喂苹果时。

### 2.3 苹果购买恢复

**购买苹果** - `POST /api/ai/stamina/apple`

请求：

```json
{
  "appleCount": 1
}
```

处理（必须在单个事务内）：

1. 校验龟币余额 >= `appleCount * aiChat.appleCost`（默认 5 龟币/个）。
2. 扣减龟币。
3. 写入龟币流水。
4. 增加 AI 体力：`stamina += appleCount * aiChat.appleRecoverAmount`（默认 1）。
5. 写入体力流水：`biz_type=APPLE`。

事务要求：

- 龟币扣减、龟币流水、体力增加、体力流水必须同时成功或同时失败。
- 龟币扣减触发幂等冲突时（不可能，每次操作唯一），同样事务级兜底。

响应：

```json
{
  "stamina": 8,
  "maxStamina": 10,
  "coin": 45,
  "message": "小龟吃饱饱了，又活力满满！"
}
```

### 2.4 体力流水

`user_ai_stamina_log` 字段：

```text
user_id
biz_type        TALK / APPLE / ADMIN / SETTLE（结算副作用）
amount          变化量，正数为增加，负数为减少
balance_after   操作后的余额
reason          操作原因或备注
created_at
```

频控不消耗体力，但应计入 `dailyUsedCount`（每日对话次数）。

## 3. AI 身份兜底

### 3.1 问题识别

典型问题：

- "你是谁？"
- "你是 ChatGPT 吗？"
- "你用的什么模型？"
- "你是 DeepSeek 吗？"

### 3.2 处理方案

推荐使用规则兜底，不调用 DeepSeek：

1. **规则识别**（可选）：对输入做简单关键词或正则匹配，快速识别身份问题。
2. **免 LLM 回复**：返回固定文案。
3. **Prompt 约束**（备选）：若调用 DeepSeek，在 system prompt 中强制要求回答为"小龟"身份，不暴露任何底层模型名称。

建议固定回复：

```text
我是小龟哟~ 小龟最擅长陪你聊天和投票分析。有什么想问我的吗？
```

## 4. DeepSeek 调用

### 4.1 模型选择

| 场景 | 模型 | thinking | cost |
| --- | --- | --- | --- |
| 普通闲聊 | `deepseek-v4-flash` | disabled | 低 |
| 比赛/预测简单分析 | `deepseek-v4-flash` | disabled | 低 |
| 复杂预测分析 | `deepseek-v4-pro` | enabled | 高 |
| 用户主动问记忆 | `deepseek-v4-flash` | disabled | 低 |

默认使用 `deepseek-v4-flash` + `stream=false`。

### 4.2 请求参数

```text
model           deepseek-v4-flash
messages        system + history + user input + context
max_tokens      aiChat.maxOutputTokens（默认 500）
temperature     aiChat.temperature（默认 0.7）
stream          false（当前非流式）
reasoning_tokens 仅 deepseek-v4-pro 模式下设置
```

### 4.3 超时与重试

固定策略（不可配置）：

- **调用超时**：30 秒。
- **重试次数**：3 次。
- **重试间隔**：100ms 线性 backoff。
- **熔断阈值**：1 分钟内错误率 > 50% 时暂停调用 5 分钟，返回系统兜底文案。

### 4.4 错误处理

| 错误 | 处理 | 兜底文案 |
| --- | --- | --- |
| 超时或网络错误 | 重试 3 次，全部失败后返回兜底 | "小龟有点累了，稍后再聊吧~" |
| API 限流（429） | 重试 3 次 | "小龟现在有点忙，请稍后再试~" |
| 无效请求（400） | 不重试，直接返回兜底 | "输入似乎有问题，换个角度问我吧~" |
| 服务不可用（5xx） | 重试 3 次，全部失败返回兜底 | "小龟现在不在线，稍后再聊~" |
| 余额不足 | 告知运维，返回系统兜底 | "小龟暂时离线维护中~" |

**不消耗体力规则**：

- 调用 DeepSeek 失败时，不扣减体力。
- 即使返回兜底文案，也保存消息记录（助手角色、兜底文案）。

### 4.5 token 与成本记录

每次调用后记录到 `ai_message`：

```text
model                   deepseek-v4-flash / deepseek-v4-pro
prompt_tokens           输入 token 数
completion_tokens       输出 token 数
total_tokens            总 token 数
thinking_tokens         thinking 模式下的 reasoning token（仅 pro）
cost_estimate           可选，基于官方定价的成本估算
```

## 5. 输入与输出约束

### 5.1 输入检查

| 检查项 | 规则 |
| --- | --- |
| 登录 | 未登录返回 401 |
| 开关 | `aiChat.enabled=false` 返回系统维护文案 |
| 频控 | 用户当日主动消息 >= `dailyUserMessageLimit` 返回今日对话已满 |
| 长度 | 消息长度 > `aiChat.maxInputLength`（默认 1000）返回输入过长 |
| 体力 | 体力 < `aiChat.defaultStaminaCost` 返回体力不足 |

### 5.2 输出规范

- 助手回复必须 > 0 且 < 2000 字。
- 不应包含 DeepSeek、ChatGPT 等模型名称。
- 不暴露用户隐私信息（如其他用户的下注金额、胜负记录）。

## 6. Prompt 设计

### 6.1 System Prompt 框架

```text
你是小龟，一个温和、靠谱、有点小可爱的投票和预测小助手。

【身份限制】
- 你的名字是"小龟"。
- 不能说你是 ChatGPT、DeepSeek 或其他 AI 模型。
- 当用户问你是谁时，始终回答为"小龟"。

【性格特征】
- 温和、靠谱、有点小可爱。
- 不煽情、不说教、不主动安慰过度。
- 输了可以短句调侃，但不强行阳光心态。

【功能范围】
- 回答关于投票、预测的问题。
- 提供闲聊和日常建议。
- 不能进行金融投资建议、敏感政治观点等。

【记忆触发】
- 用户可以问你关于他的投票记录、最大盈利、连胜记录等。
- 我会提供事实，你基于事实和语气规范来组织回答。
- 普通分析中不应主动提起用户的历史记录。
```

### 6.2 历史消息窗口

保留最近 N 条消息（用户 + 助手轮流）。建议 N=8（约 4 轮对话）。

旧消息可压缩或删除。

### 6.3 上下文注入

若用户提到预测市场或投票，主动读取并注入：

```text
【当前市场】
市场: {marketTitle}
选项: {options}
我在 {myPosition} 上下注了 {myAmount}，当前盈利 {profitAmount}。
```

## 7. 验收要点

1. 体力不足时不调用 DeepSeek。
2. DeepSeek 失败时不扣体力。
3. 用户消息和助手回复都会保存。
4. 体力流水记录准确。
5. 频控、输入长度检查生效。
6. 身份问题有兜底回复。
7. 苹果购买和体力增加在同一事务内。
8. 自然恢复在体力查询和聊天前都会触发。
