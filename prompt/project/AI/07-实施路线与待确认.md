# AI 聊天实施路线与待确认

> 本文用于排期、验收和记录尚未定口径的问题。

## 1. 分阶段实施

### Phase 1：最小可用聊天

目标：用户可以主动和小龟聊天。

范围：

- DeepSeek 配置。
- DeepSeekClient 非流式调用。
- `/api/ai/chat`。
- 体力校验。
- 基础人格 Prompt。
- 对话消息保存。
- token usage 记录。
- DeepSeek 失败不扣体力。

验收：

- 体力充足时能返回小龟回复。
- 体力不足时返回兜底文案。
- 问模型身份时不暴露底层模型。
- DeepSeek 超时或报错时有降级文案。

### Phase 2：模板主动推送

目标：结算后小龟可以主动发消息。

范围：

- `dialogue_template`。
- `template_user_view`。
- 投票结算 win/lose 推送。
- 连胜/连败 streak 更新。
- 连胜/连败推送。
- 推送消息保存到 `ai_message`。

验收：

- 主动推送不消耗体力。
- 主动推送不调用 DeepSeek。
- 模板占位符能正确替换。
- 同一用户优先看到未见过模板。

### Phase 3：记忆系统

目标：小龟能回答关键历史记忆，并做闲置记忆回调。

范围：

- `user_ai_memory`。
- 开蛋、结算、登录等业务事件更新 Flag。
- 用户主动问记忆。
- 闲置状态上报。
- 闲置推送冷却和每日上限。

验收：

- 有记忆事实时，回答准确。
- 没有记忆事实时，不编造。
- 普通聊天不会主动提起记忆。
- 闲置推送每天最多 2 条。

### Phase 4：体验增强

目标：提升聊天体验和运营效率。

可选范围：

- 流式输出。
- 更完整的预测市场上下文。
- 更细的敏感分类。
- 后台模板管理。
- 异步 AI 补充模板池。
- Tool Calls。

## 2. 推荐实现顺序

1. 配置与 DeepSeekClient。
2. AI 消息表。
3. `/api/ai/chat`。
4. 体力校验与失败不扣体力。
5. 基础 Prompt。
6. 模板表和模板选择。
7. 投票结算推送接入。
8. 记忆 Flag 表。
9. 业务事件更新记忆。
10. 用户主动问记忆。
11. 闲置状态与闲置推送。

## 3. 待确认问题

| 问题 | 影响 |
| --- | --- |
| 用户主动聊天每次体力消耗是否固定为 `1` | 影响体力扣减和返回字段。 |
| “苹果 5 龟币”是否已有购买/恢复接口 | 影响体力不足兜底后的转化链路。 |
| 主动推送走 WebSocket、站内消息、轮询还是已有通知系统 | 影响前后端联调方式。 |
| 一次结算同时满足 win/lose 和 streak 时是否只推一条 | 影响推送策略。 |
| 对话历史保留周期和最大条数 | 影响存储与上下文拼装。 |
| 闲置判断由前端上报还是服务端连接状态判断 | 影响 `presence` 接口设计。 |
| 预测分析是否允许读取外部数据 | 影响上下文来源与实时性。 |
| AI 消息是否需要运营后台审计与删除 | 影响后台功能范围。 |
| 敏感话题是否复用现有敏感词系统 | 影响 AIRiskService 实现。 |
| 记忆 Flag 是否需要运营后台可查看/修正 | 影响后台数据管理。 |

## 4. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| LLM 编造历史记忆 | 记忆问答只使用后端提供事实，缺失时兜底。 |
| LLM 给出过度下注建议 | Prompt 禁止重仓、梭哈、稳赚表达。 |
| 成本失控 | 限制输入长度、历史轮数、每日次数。 |
| DeepSeek 服务不可用 | 降级文案，不扣体力。 |
| 主动推送打扰用户 | 冷却期、每日上限、模板去重。 |
| 用户反复看到同一句 | `template_user_view` 记录曝光次数。 |
| API Key 泄露 | 只在服务端保存，日志脱敏。 |
