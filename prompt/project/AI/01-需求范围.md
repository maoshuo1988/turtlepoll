# AI 聊天需求范围

> 来源：[13-原始需求.md](./13-原始需求.md)。
>
> 本文只描述目标、边界和核心规则，不展开技术实现细节。

## 1. 目标

1. 提供用户主动发起的“小龟 AI 对话”能力。
2. 支持用户询问比赛、预测市场、普通闲聊和 AI 身份。
3. 投票结算后由系统主动推送小龟文案。
4. 用户长时间停留但未互动时，触发记忆类闲置推送。
5. 用户主动询问关键历史记忆时，小龟可以基于事实回答。
6. 接入体力消耗规则：用户主动对话消耗体力，AI 主动消息不消耗体力。
7. 小龟语气保持温和、靠谱、有点小可爱。

## 2. 本期范围

| 模块 | 本期是否做 | 说明 |
| --- | --- | --- |
| 用户主动聊天 | 做 | 调用 DeepSeek，支持普通聊天和预测分析。 |
| AI 身份问答 | 做 | 不暴露底层模型，统一回答为“小龟”。 |
| 体力校验 | 做 | 体力不足不调用 LLM。 |
| 投票结算推送 | 做 | 模板池随机，不调用 LLM。 |
| 连胜/连败推送 | 做 | 结算后根据 streak 触发。 |
| 用户主动问记忆 | 做 | 读取业务 Flag 后调用 LLM 表达。 |
| 闲置记忆推送 | 做 | 模板池随机，不调用 LLM。 |
| 模板去重 | 做 | 优先选用户未见过或见过最少的模板。 |

## 3. 核心规则

### 3.1 体力规则

| 场景 | 是否消耗体力 | 是否调用 LLM |
| --- | --- | --- |
| 用户主动聊天 | 是 | 是 |
| 用户主动问记忆 | 是 | 是 |
| 用户回复闲置推送 | 是 | 是 |
| 投票结算主动推送 | 否 | 否 |
| 闲置记忆主动推送 | 否 | 否 |
| 体力为 0 | 否 | 否 |

体力不足兜底：

```text
小龟睡着啦~ 喂它一颗苹果(5 龟币)就能继续聊咯
```

### 3.2 记忆触发规则

记忆系统只在两种情况下触发：

1. 用户主动问，例如“我之前最多赢过多少？”
2. 闲置推送，例如用户停留很久但没有互动。

普通比赛分析、闲聊、身份问答里，AI 不应主动提起用户过去的事。

### 3.3 主动消息规则

AI 主动发起的消息均不消耗用户体力，包括：

- 投票结算推送。
- 连胜/连败推送。
- 闲置记忆推送。

主动消息本期使用模板池，不实时调用 DeepSeek。

### 3.4 语气规则

小龟整体语气：

- 温和。
- 靠谱。
- 有点小可爱。
- 不煽情。
- 不说教。
- 不主动安慰过度。
- 输了可以短句调侃，不强行阳光。

## 4. 本期不做

| 项目 | 不做原因 |
| --- | --- |
| 心情系统 | 需求明确本期不做。 |
| 装备龟影响语气 | 需要为不同龟种设计 personality prompt，后置。 |
| 连胜/连败影响聊天语气 | 本期只用于推送触发。 |
| AI 在分析中自然提起记忆 | 容易造成越界和编造，本期禁止。 |
| 生日祝福 | 依赖用户生日字段和填写率。 |
| 节日推送 | 属于运营活动，后续再加。 |
| 里程碑祝贺 | 需要更多成就口径。 |
| AI 主动日常闲聊 | 本期主动消息只做结算和记忆回调。 |
| 第一次抽到 SSS 的闲置回调 | 触发率低，本期不做。 |
| AI 自动补充实时模板池 | 可作为异步后台能力后续补。 |

## 5. 关键约束

1. LLM 输出不能作为下注、结算、派奖依据。
2. DeepSeek API Key 只能放服务端。
3. 用户输入进入 LLM 前必须做长度限制。
4. DeepSeek 失败时不应扣体力。
5. 不能向用户暴露 DeepSeek、ChatGPT 等模型身份。
6. 对话历史不保存 DeepSeek 的 `reasoning_content`。
