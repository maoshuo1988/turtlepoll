# AI 闲置推送链路

> 本文说明如何在用户闲置时（停留但未互动）触发记忆类推送，包括 Presence 上报、闲置候选扫描、频率控制、推送生成、SSE 投递和未读补拉的完整流程。

## 1. 完整处理流程

```text
【Presence 上报】
用户进入 AI 聊天页面
  -> 前端定期调用 POST /api/ai/presence（心跳）
  -> 后端记录 user_ai_presence.first_seen_at / last_seen_at / page / active
  -> 用户主动聊天成功时，同时更新 last_ai_interact_at = now()

【闲置候选扫描】
cron 每分钟触发
  -> AIPresenceService.FindIdleCandidates()
  -> 查询满足条件的在线用户：
     active=true AND now-last_seen_at<=60s AND now-last_ai_interact_at>=idleTriggerMinutes
     AND now-last_idle_push_at>=idlePushCooldownMinutes
     AND (idle_push_count_date!=today OR idle_push_count<idlePushDailyLimit)
  -> 对每个用户：
     -> 读取 user_ai_memory
     -> DecideIdleScene(memory, recentPushMeta)
     -> 开启事务
     -> AITemplateService.SelectAndRender(scene, userId, placeholders)
     -> 保存 ai_message(role=assistant, status=0, stamina_cost=0, scene=idle_xxx)
     -> 更新 user_ai_presence.last_idle_push_at / idle_push_count
     -> 更新 memory flag_meta.lastPushedAt
     -> 写 template_user_view
     -> 提交事务
     -> AIPushDelivery.Deliver(userId, message)

【Presence 上报】
用户页面关闭或长时间未活动
  -> active=false 或自动判断离线
  -> Presence 扫描将跳过此用户
```

## 2. Presence 上报

### 2.1 上报接口

**API**：`POST /api/ai/presence`

请求体：

```json
{
  "page": "predict_market",
  "active": true
}
```

**页面值**：

- `predict_market`：预测市场
- `vote`：投票页面
- `pet`：宠物页面
- `ai_chat`：AI 聊天气泡（可选）
- 其他：待扩展

**active 含义**：

- `true`：页面在前台，用户看得见。
- `false`：页面在后台或用户已离开。

### 2.2 后端处理

```text
POST /api/ai/presence
-> 登录验证
-> 读取或创建 user_ai_presence 记录
-> 更新：
   first_seen_at       若为首次记录，设为 now()；否则不变
   last_seen_at        = now()
   page                = request.page
   active              = request.active
-> 若主动对话成功时，同时更新：
   last_ai_interact_at = now()
```

### 2.3 心跳频率

建议前端每 10-30 秒上报一次心跳，保持 `last_seen_at` 新鲜。

## 3. 闲置候选扫描

### 3.1 扫描条件

定时任务（cron）每分钟执行一次，查询满足以下条件的用户：

```sql
SELECT * FROM user_ai_presence
WHERE
  active = true                                    -- 在线用户
  AND now() - last_seen_at <= 60                 -- 最近 60 秒有心跳
  AND now() - last_ai_interact_at >= ?           -- 闲置时间 >= idleTriggerMinutes
  AND now() - last_idle_push_at >= ?             -- 距离上次推送 >= idlePushCooldownMinutes
  AND (date(last_idle_push_at) != today()         -- 今天还未推过，或者
       OR idle_push_count < ?)                    -- 今天推送数 < idlePushDailyLimit
```

### 3.2 默认配置

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `idleTriggerMinutes` | 10 | 闲置 10 分钟以上触发扫描 |
| `idlePushCooldownMinutes` | 120 | 两次推送间隔至少 2 小时 |
| `idlePushDailyLimit` | 2 | 每天最多推 2 次闲置推送 |

配置存储在 `aiChat` 配置节点，运营可热修改。

### 3.3 扫描结果处理

对每个候选用户：

1. 读取 `user_ai_memory`。
2. 判断是否有可推的记忆事实（见第 4 节）。
3. 若无可用场景，跳过此用户。
4. 若有，进行推送生成（见第 5 节）。

## 4. 记忆选择

### 4.1 可用场景

闲置推送只从以下候选场景中选择（用户已有相应记忆时）：

| memory flag | idle scene | 占位符 | 说明 |
| --- | --- | --- | --- |
| `biggest_win_amount` + `biggest_win_event` | `idle_biggest_win` | `{amount}` / `{event}` | 最大盈利金额和事件 |
| `first_egg_turtle` | `idle_first_egg` | `{turtle_name}` | 第一个获得的龟种 |
| `longest_win_streak` | `idle_longest_streak` | `{n}` | 最长连胜纪录 |

### 4.2 选择算法

```text
候选场景 = [
  first_egg_turtle 若 user有此记忆,
  biggest_win_amount 若 user有此记忆,
  longest_win_streak 若 user有此记忆
]

可用场景 = 候选场景中未在同一天或冷却期推过的场景

// 可选：加权随机选择，或简单循环选择
选中场景 = 可用场景[0] 或 随机选择
```

### 4.3 冷却与消重

**同场景冷却**：同一个场景（如 `idle_first_egg`），距离上次推送不足 N 天时不重复推。建议 N >= 1（每 1 天最多推一次同场景）。

**近期记忆**：记录最近 7 天内推过的场景，优先选择未推或推得最少的场景。可存储在 `user_ai_memory.flag_meta`：

```json
{
  "lastPushedAt": 1760000000,
  "idlePushHistory": [
    {"scene": "idle_first_egg", "pushedAt": 1760000000},
    {"scene": "idle_biggest_win", "pushedAt": 1759000000}
  ]
}
```

## 5. 闲置推送生成

### 5.1 推送流程

```text
DecideIdleScene(memory, recentPushMeta) -> idle_xxx 场景
  -> AITemplateService.SelectAndRender(idle_xxx, userId, placeholders)
  -> 开启事务
  -> INSERT INTO ai_message(...)
  -> UPDATE user_ai_presence SET last_idle_push_at=now(), idle_push_count+=1, last_idle_push_date=today()
  -> UPDATE user_ai_memory SET flag_meta.lastPushedAt=now()
  -> UPSERT template_user_view
  -> 提交事务
  -> AIPushDelivery.Deliver(userId, message)
```

### 5.2 ai_message 记录

```text
user_id           用户 ID
role              assistant
scene             idle_first_egg / idle_biggest_win / idle_longest_streak
content           渲染后的文案
template_id       使用的模板 ID
status            0（未读）
stamina_cost      0（推送不消耗体力）
context_type      none（闲置推送无业务对象）
context_id        0 或 NULL
request_id        幂等键（闲置推送无特殊幂等需求，可为 NULL 或 idle_{userId}_{timestamp}）
model             无
create_time       now()
```

### 5.3 占位符示例

| scene | 模板样例 | 占位符 | 渲染结果 |
| --- | --- | --- | --- |
| `idle_first_egg` | "还记得你第一只龟是 {turtle_name} 吗？" | `{turtle_name}`: "小红" | "还记得你第一只龟是小红吗？" |
| `idle_biggest_win` | "你最大赢过 {amount} 龟币，就在 {event}。" | `{amount}`: 1000, `{event}`: "世界杯决赛" | "你最大赢过 1000 龟币，就在世界杯决赛。" |
| `idle_longest_streak` | "连胜 {n} 场是你的纪录呢~" | `{n}`: 5 | "连胜 5 场是你的纪录呢~" |

## 6. 投递与已读

### 6.1 投递方案

闲置推送落库后立即投递：

**在线投递（SSE）**：

```text
if 用户当前在线 {
  通过 SSE 或 WebSocket 发送 ai_push 事件
  类型: idle_xxx
  content: 推送文案
}
```

**离线补拉**：

```text
前端定期轮询 GET /api/ai/pushes/unread
返回所有 status=0 的消息，包括结算和闲置推送
```

### 6.2 拉取未读

**API**：`GET /api/ai/pushes/unread`

查询条件：

```sql
SELECT * FROM ai_message
WHERE
  user_id = ?
  AND role = 'assistant'
  AND status = 0  -- 未读
ORDER BY create_time ASC, id ASC
LIMIT 20
```

返回示例：

```json
{
  "results": [
    {
      "id": 20001,
      "scene": "idle_first_egg",
      "content": "还记得你第一只龟是小红吗？",
      "contextType": "none",
      "contextId": 0,
      "createTime": 1760000000
    },
    {
      "id": 20002,
      "scene": "win_streak",
      "content": "3 连了。我都怀疑是不是出 bug 了。",
      "contextType": "predict_market",
      "contextId": 123,
      "createTime": 1760001000
    }
  ]
}
```

### 6.3 标记已读

**API**：`POST /api/ai/pushes/read`

请求体：

```json
{
  "ids": [20001, 20002]
}
```

处理：

```sql
UPDATE ai_message
SET status = 1
WHERE user_id = ? AND id IN (?) AND role = 'assistant'
```

返回：

```json
{
  "updated": 2
}
```

`updated` 表示本次从未读改为已读的消息数。重复标记已读时返回 0，不视为错误。

### 6.4 消息展示流程

```
1. 页面加载时 -> GET /api/ai/pushes/unread -> 显示未读消息
2. 用户进入聊天气泡 -> POST /api/ai/presence(active=true) -> 保持心跳
3. SSE 连接在线时 -> 实时接收 ai_push 事件 -> 展示推送
4. 用户展示推送气泡 -> POST /api/ai/pushes/read -> 标记已读
5. SSE 断线后重连 -> GET /api/ai/pushes/unread -> 补拉未读消息
```

## 7. 频率控制

### 7.1 控制维度

| 维度 | 规则 | 配置 |
| --- | --- | --- |
| **用户冷却** | 两次推送间隔 >= 120 分钟 | `idlePushCooldownMinutes` |
| **每日上限** | 每用户每天最多 2 次 | `idlePushDailyLimit` |
| **扫描频率** | cron 每分钟扫描一次 | 固定 |
| **在线判断** | `last_seen_at` 距今 <= 60 秒 | 固定 |
| **闲置阈值** | 最后交互距今 >= 10 分钟 | `idleTriggerMinutes` |

### 7.2 示例

```
用户 A 在 10:00 收到第一次闲置推送
-> 下次可推送时间 >= 10:00 + 120min = 12:00
-> 今日推送计数 = 1，仍可再推 1 次
-> 下一个候选推送时间窗口 = [12:00, 23:59]
-> 若在 12:10 再有推送触发，则该推送可投递
-> 今日推送计数 = 2，已达上限 idlePushDailyLimit=2
-> 之后的推送被跳过，直到 00:00 计数重置
```

## 8. 风险与保护

| 风险 | 保护 |
| --- | --- |
| 用户离线仍收到推送 | 闲置扫描只查 active=true 用户 |
| 推送过于频繁骚扰用户 | 冷却期 + 每日上限 |
| 无记忆事实的空推送 | 记忆选择检查，无可用场景则跳过 |
| 模板缺失或占位符错误 | 模板选择与渲染，失败使用兜底 |
| 扫描任务阻塞 | 使用异步任务队列或 goroutine + 超时 |
| 多用户并发推送 | 使用连接池，每个用户独立事务 |

## 9. 推荐落地顺序

1. 实现 `POST /api/ai/presence` 接口与 presence 表。
2. 实现 `GET /api/ai/pushes/unread` 和 `POST /api/ai/pushes/read`。
3. 实现 cron 闲置扫描逻辑（暂时 no-op）。
4. 实现 `DecideIdleScene` 和模板渲染。
5. 测试闲置推送的频率控制（冷却、每日上限）。
6. 集成 SSE 投递。
7. 性能优化（批量扫描、连接池等）。
