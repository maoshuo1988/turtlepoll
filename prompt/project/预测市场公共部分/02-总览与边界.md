# 预测市场公共部分总览与边界

## 1. 背景

世界杯预测市场和 Polymarket 预测市场来源不同，但进入站内后共享同一套预测市场领域模型和用户玩法。热度计算入口与公式统一迁移到 [撕裂带热度计算](../撕裂带热度计算/00-目录-0.md)，公共部分只保留入口映射与依赖关系：

- 用户看市场。
- 用户下注。
- 市场封盘。
- 运营或同步写入最终结果。
- 用户领取结算。
- 系统更新用户预测胜率和最新连胜。
- 热度和标签参与排序与发现。
- 账户余额榜展示高余额用户及其预测战绩。

因此需要把共通部分抽出来，避免两个专项文档重复描述下注和结算。

## 2. 公共领域目标

- 定义统一数据模型。
- 定义统一下注流程。
- 定义统一结算流程。
- 定义统一热度入口、标签、查询口径。
- 定义统一用户预测战绩口径。
- 定义统一账户余额榜查询口径。
- 明确专项文档只描述来源差异。

## 3. 公共领域覆盖

覆盖：

- `PredictMarket`
- `PredictContext`
- `PredictBet`
- `UserCoin`
- `UserCoinLog`
- 赔率计算与锁定
- 下注扣款
- 市场池更新
- 运营人工结算
- 用户领取结算
- 预测市场热度入口映射
- 预测市场查询
- 用户预测胜率
- 用户最新连胜场次
- 账户余额 Top N 查询

## 4. 不覆盖

不覆盖：

- football-data API 对接。
- 世界杯小组赛/淘汰赛阶段识别。
- 世界杯比分到 A/B/DRAW 的映射。
- Polymarket Gamma API 对接。
- Polymarket tag_id 发现。
- Polymarket outcome 到站内 A/B 的映射。
- Polymarket 自动 resolved 跟踪。
- 外部市场取消、无效、争议的专项处理。
- 用户等级、勋章、积分体系。
- 非预测市场玩法的胜率统计。

这些内容继续保留在：

- `prompt/project/世界杯预测市场`
- `prompt/project/Polymarket预测市场`

## 5. 统一状态口径

`PredictMarket.status`：

| 状态 | 含义 |
|------|------|
| `OPEN` | 可下注 |
| `CLOSED` | 已封盘，不可下注，等待结果 |
| `SETTLED` | 已写入最终结果，可用户结算 |

历史兼容：

- 旧代码或旧数据可能出现 `CLOSE`。
- 查询和运营结算可短期兼容。
- 新设计统一写 `CLOSED`。

## 6. 统一选项口径

`PredictMarket.marketType`：

| 类型 | 合法选项 | 说明 |
|------|----------|------|
| `binary` | `A/B` | 二元市场 |
| `1x2` | `A/B/DRAW` | 三元市场 |

公共结算只读取：

```text
PredictMarket.status == SETTLED
PredictMarket.result
PredictBet.option
PredictBet.odds
```

不直接读取外部比分或外部 resolved 字段。

## 7. 用户战绩口径

用户战绩按“用户 + 市场”统计：

| 指标 | 说明 |
|------|------|
| 胜率 | 命中市场数 / 已结算市场数 |
| 最新连胜场数 | 最近连续命中的已结算市场数 |

同一用户在同一市场多笔下注只统计一场，避免通过拆单刷场次。

用户战绩只在用户领取结算时更新，运营结算和自动结算不直接更新用户战绩。

## 8. 账户余额榜口径

账户余额榜按 `UserCoin.balance` 降序查询前 N 名用户。

返回字段：

- 用户名称。
- 用户头像。
- 账户余额。
- 用户胜率。
- 用户最新连胜场次。
