# 预测市场公共部分接口

## 1. 下注接口

```text
POST /api/coin/bet
```

认证：

- 需要登录。

参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `marketId` | int64 | 是 | 市场 ID |
| `option` | string | 是 | `A/B/DRAW` |
| `amount` | int64 | 是 | 下注金额 |

返回：

- `bet`
- `market`
- `userCoin`
- `lockedOdds`

## 2. 用户结算接口

```text
POST /api/coin/settle
```

认证：

- 需要登录。

参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `marketId` | int64 | 是 | 市场 ID |

规则：

- 市场必须是 `SETTLED`。
- `PredictMarket.result` 必须合法。
- 只结算当前用户未结算下注单。
- 结算成功后按“用户 + 市场”幂等更新用户胜率和最新连胜。
- 同一用户同一市场重复结算不重复更新战绩。

## 3. 运营人工结算接口

```text
POST /api/admin/predict/market/settle
```

认证：

- 管理员。

请求：

```json
{
  "marketId": 1,
  "result": "A",
  "requestId": "manual-001",
  "remark": "manual settle",
  "allowReset": false
}
```

规则：

- `binary` 允许 `A/B`。
- `1x2` 允许 `A/B/DRAW`。
- 默认只允许 `CLOSED/CLOSE -> SETTLED`。
- `allowReset=true` 可重设已结算市场。

## 4. 市场查询接口

```text
GET /api/football/markets
GET /api/football/markets/by_tag
GET /api/football/markets/by_name
GET /api/football/predict_context/hot
```

返回聚合：

- `market`
- `context`
- `hasBet`
- `betSettleResult`
- 来源专项字段，例如 `schedule`

## 5. 评论接口与热度

```text
POST /api/comment
```

公共影响：

- 一级评论预测市场时，`PredictContext.heat +1`。
- 二级评论当前不影响预测市场热度。
- 预测市场一级评论需要提交 `marketId` 和 `option`，用于结算后获胜方评论奖励。

预测市场评论参数建议：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `entityType` | string | 是 | 预测市场评论沿用评论实体类型 |
| `entityId` | int64 | 是 | `marketId` |
| `content` | string | 是 | 评论内容 |
| `option` | string | 是 | `A/B/DRAW`，必须匹配市场类型 |

写入：

- `Comment`
- `PredictCommentMeta`

详见：

- `prompt/project/预测市场热度`

## 6. 账户余额榜接口

建议新增：

```text
GET /api/coin/leaderboard
```

认证：

- 可公开访问，或按产品策略要求登录。

参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `limit` | int | 否 | 返回数量，默认 20，最大 100 |

返回：

| 字段 | 说明 |
|------|------|
| `items` | 账户余额 Top N 用户列表 |
| `myRank` | 我的排名，未登录或无账户时为空 |
| `myBalance` | 我的余额，未登录时为空 |
| `myWinRate` | 我的预测胜率，未登录时为空 |
| `myCurrentWinStreak` | 我的最新连胜场数，未登录时为空 |

`items` 字段：

| 字段 | 说明 |
|------|------|
| `rank` | 当前榜单排名 |
| `userId` | 混淆后的用户 ID，和评论返回的 `user.id` 一致 |
| `nickname` | 用户名称 |
| `avatar` | 用户头像 |
| `balance` | 当前金币余额 |
| `winRate` | 用户预测胜率 |
| `currentWinStreak` | 用户最新连胜场数 |

排序：

```text
balance desc
userId asc
```

未参与过预测市场的用户：

- `winRate = 0`
- `currentWinStreak = 0`

我的排名：

```text
rank = count(balance greater than myBalance) + count(balance equals myBalance and userId less than myUserId) + 1
```

## 7. 评论奖励任务接口

P0 建议先由定时任务自动触发，不暴露用户接口。

运营补偿接口建议：

```text
POST /api/admin/predict/comment_reward/run
POST /api/admin/predict/comment_reward/retry
GET /api/admin/predict/comment_reward/logs
```

### 7.1 手动触发发放

```text
POST /api/admin/predict/comment_reward/run
```

参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `marketId` | int64 | 是 | 市场 ID |

规则：

- 仅管理员可调用。
- 市场必须已 `SETTLED`。
- 当前时间必须在结算后 1 小时内。
- 已发放市场重复调用直接返回已有批次，不重复发放。

### 7.2 重试失败批次

```text
POST /api/admin/predict/comment_reward/retry
```

参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `rewardLogId` | int64 | 是 | 奖励批次 ID |

规则：

- 只允许重试 `FAILED` 状态。
- `EXPIRED` 默认不允许重试，除非后续新增运营强制补发能力。

### 7.3 审计查询

```text
GET /api/admin/predict/comment_reward/logs
```

返回：

- 奖励批次。
- 获奖用户明细。
- 对应金币流水 ID。
