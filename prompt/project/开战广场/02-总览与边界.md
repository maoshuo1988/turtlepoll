# 开战广场总览与边界

## 1. 模块定位

开战广场是站内用户自发创建临时对战赌局的模块。它强调议题驱动、庄家制、可争议仲裁和资金可追溯，与预测市场的外部赛事同步、盘口赔率、统一市场模型不同。

核心目标：

- 支持用户创建可判定的对战议题。
- 支持公开局和私人局。
- 支持挑战者多次追加下注。
- 支持自动封盘、庄家宣判、挑战者确认、争议仲裁。
- 支持完整金币流水、资金池托管、结算单和提取。
- 支持评论、点赞、热度，形成广场内容流。

## 2. 用户角色

| 角色 | 说明 |
|------|------|
| 庄家 | 发起赌局，定义标题、立场、押注本金、公开性、结算时间，并在到期后宣判 |
| 挑战者 | 加入赌局，持挑战者立场下注，可追加下注，可确认或异议 |
| 管理员 | 处理 disputed 赌局，执行最终裁决、处罚和作废 |
| 系统任务 | 负责封盘、到期、超时默认结果、争议超时兜底 |

## 3. 范围内

- 赌局创建、列表、详情。
- 公开局、私人局。
- 挑战者加入和追加下注。
- 庄家加注。
- 容量满自动封盘。
- 到结算时间自动进入待宣判。
- 庄家宣判，超时自动判庄家输。
- 挑战者确认或异议，超时默认确认。
- 管理员仲裁，超时默认作废。
- 资金池、入场费、销毁、结算单、提取。
- 评论和点赞带来的 battle 热度增长。
- 面向运营的 disputed 队列、详情、裁决入口。

## 4. 范围外

- 不引入预测市场盘口赔率。
- 不复用 `PredictMarket/PredictBet` 作为 battle 领域模型。
- 不支持庄家和挑战者同立场下注。
- 不支持部分提取，提取必须一次性全额。
- 不支持结算后修改结果。
- 不在一期内实现复杂好友关系校验。私人局先以邀请码为准。
- 不在一期内实现资金冻结，下注即扣款入池。

## 5. 公开局与私人局边界

公开局：

- 可进入公共广场列表。
- 任意登录用户可查看详情和加入。
- 挑战者下注时额外支付 5% 入场费。
- 入场费实时转给庄家，不进入资金池。

私人局：

- 创建时由服务端自动生成 `inviteCode`。
- 加入时必须提供正确 `inviteCode`。
- `inviteCode` 规则为 4 位字母数字，大小写不敏感。
- `inviteCode` 默认 24 小时过期，以 Redis 校验为准。
- 不收取入场费。
- 设计目标是不进入公共广场默认列表。
- 庄家、已参与用户、持链接或邀请码用户可以访问详情和加入流程。

## 6. 状态机

| 状态 | 标识 | 说明 |
|------|------|------|
| 开放中 | `open` | 接受挑战者加入和追加下注，庄家可加注 |
| 已封盘 | `sealed` | 不接受挑战者下注，等待到结算时间进入待宣判 |
| 待宣布和确认 | `pending` | 到期后等待庄家宣判；宣判后等待挑战者确认或异议 |
| 争议中 | `disputed` | 有挑战者异议，等待管理员裁决 |
| 已结算 | `settled` | 已生成结算单，用户可提取 |

## 7. 资金原则

- 下注本金：从用户账户扣除后进入 battle 资金池。
- 入场费：公开局挑战者额外支付，实时转给庄家。
- 处罚：通过 burn 进入销毁账户。
- 结算：`settled` 时生成结算单，提取时才真实出池给用户。
- 审计：所有资金动作必须写 `BattleLedger` 和 `UserCoinLog`。

## 8. 幂等原则

所有写操作都必须能安全重试：

- 加入或追加下注：同一 battle、user、requestId 返回同一下注记录。
- 庄家加注：同一 battle、user、requestId 不重复扣款。
- 宣判、确认、异议、裁决：重复请求不重复改变状态。
- 提取：已提取时直接返回结算明细，不重复出池。

## 9. 排序与发现

广场列表支持：

- 最新。
- 热度。
- 大额。
- 快结算。
- 状态筛选。
- 我做庄。
- 我挑战。
- 与我相关。

默认公共广场只展示公开局；私人局通过我的局、详情链接或邀请码入口进入。
